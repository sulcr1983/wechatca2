# 排版页 v4 · 结构纠正 + 开头结尾预设（2026-11-02）

> **本文推翻 `design-wechat-page-v3.md` 的一处结构性错误**，并加入一个新增需求。
>
> 背景：用户指出「新增的 15 套风格和之前的风格是完全不同的独立设计，现在变成了下级了」。
> 这句话是对的，v3 把**独立产品降成了子选项**。本文纠正它。

---

## 一、先说清楚我错在哪

### 1.1 实测：15 套 kit 与 15 个版式是**一一对应**的

| kit 名 | 锁定版式 |
|---|---|
| 时代周刊 / 卫报 / 经济学人 / 福布斯 / Vogue 画报 / 国家地理 / 阿迪达斯 | `time` / `guardian` / `economist` / `forbes` / `vogue` / `natgeo` / `adidas` |
| 无印良品 / 森系杂志 / 浮世绘 / 笔记纸底 / 宜家目录 / 星巴克 / 新粗野 / 深度阅读 | `muji` / `mori` / `ukiyoe` / `note` / `ikea` / `starbucks` / `brutal` / `deepread` |

**15 套 kit = 15 个版式，一个不多一个不少。**

### 1.2 实测：两者是同一层级的独立设计，不是「主题 + 参数」

| 项 | kit（`mg-*.json`） | 普通主题（`su-*.json`） |
|---|---|---|
| 顶层字段 | `name` / `description` / **`kind`** / **`locked_layout`** / `colors` / `styles` | `name` / `description` / `colors` / `styles` / `blocks` |
| `styles` 覆盖元素数 | **33 个** | **36 个** |
| 是否带完整排版样式 | ✅ 是 | ✅ 是 |
| `layout` 字段 | ❌ 没有（用 `locked_layout`） | ❌ 没有（用全局版式） |

**两者 `styles` 覆盖深度几乎相同。** kit 不是「在普通主题上叠一层版式」，
而是**一整套独立设计，只是额外声明了「我这套设计绑定哪个版式」**。

### 1.3 所以 v3 错在哪

v3 把 15 个版式放进了抽屉的「**第 2 段：文章结构怎么排**」，这等于宣判：

> 「这 15 个杂志风设计，只是普通主题的一个可选参数。」

**三重错误**：

1. **语义错**：用户选了「时代周刊」，再让他点「朱丝栏」版式 —— 两套设计的视觉语言互相打架
2. **产品错**：**独立的产品被降成了子选项**（用户原话）
3. **UX 错**：用户看到「15 种版式」，会以为它们和 164 套主题可以自由组合，
   但实际上其中 8 个（写死品牌色的）根本不该暴露成参数

## 二、正确结构：两个并列 tab

### 2.1 IA

```
┌─ 风格库 ──────────────────────────────────────────────┐
│ [搜索名字或 id…]                                    [×] │
│                                                         │
│ ╔══════════════╗ ╔══════════════╗                      │
│ ║  配色主题     ║ ║  整篇设计     ║  ← 两个并列 tab      │
│ ║  164 套      ║ ║  15 套       ║                      │
│ ╚══════════════╝ ╚══════════════╝                      │
│                                                         │
│ ── 配色主题 tab ────────────────────────────────────── │
│ 族：[全部][收藏][公文][节庆][信笺][素页][夜航][钢印][暮色]│
│ 版式：默认 图文节奏 卡片流 目录导航 杂志分栏 …          │
│ 段落：☑金句 ☐数据 ☑提示                                │
│ [主题网格 164 套]                                       │
│                                                         │
│ ── 整篇设计 tab ────────────────────────────────────── │
│ 15 套，每张是一个完整设计（配色 + 版式已配套）          │
│ 选中即锁定，不需要再选版式或配色                        │
│ [设计网格 15 套，带真缩略图]                            │
└─────────────────────────────────────────────────────────┘
```

### 2.2 两个 tab 的差别（说给用户听）

| | 配色主题 | 整篇设计 |
|---|---|---|
| 一句话 | **换皮不换骨** | **成套的稿子** |
| 用什么 | 商务/文艺/暗黑等气质，**结构自己调** | 报刊/杂志的专业排版，**结构是设计的一部分** |
| 可组合 | ✅ 版式、段落、配色全可调 | ❌ 锁定，但可「改回可组合」 |
| 数量 | 164 套 × 7 族 | 15 套 |

### 2.3 底部版式行的归属（关键）

- **配色主题模式** → 底部显示「版式 默认 ▸」（v3 的设计保留）
- **整篇设计模式** → 底部**不显示版式行**，显示一行提示：

```
┌────────────────────────────────────────────────────────┐
│ 整篇设计 · 时代周刊            版式与配色已内置  [改回] │
└────────────────────────────────────────────────────────┘
```

**理由**：整篇设计自带 `locked_layout`，再给一个版式选择条是**自相矛盾**。

## 三、新增需求：开头 / 结尾预设（分模块编辑）

### 3.1 需求原文

> 「还要考虑到有些人有默认开头和结尾的需要的，能不能增加这部分？预存？
> 譬如他可以分模块去编辑？」

拆成三条：

1. **预设片段**：用户可预存「开头」「结尾」（可能还有更多常用块）
2. **自动插入**：写文章时自动带出，或用一次点击插入
3. **分模块编辑**：文章可以按「开头 / 正文 / 结尾」分段编辑，而不是一整块 textarea

### 3.2 现有能力盘点（能不能复用）

| 现有能力 | 位置 | 能否复用 |
|---|---|---|
| `:::` 围栏容器 | `core/preprocessor.py` + `format_engine.py` | ✅ 可用来包「开头区/结尾区」 |
| 容器类型 | `summary` / `cta` / `quote` / `stat` / `steps` / `compare` / `eyebrow` / `cards` / `dialogue` / `gallery` / `longimage` / `timeline` | ✅ 够用 |
| localStorage 存储 | `LS` 常量表，`supersu.*` 前缀统一清理 | ✅ 新建 `supersu.snippets` 即可 |
| 草稿机制 | `supersu.pwa.draft`，500ms 防抖 + pagehide 落盘 | ✅ 可扩展成「分段落盘」 |
| 前端插入模块 | **已下线**（`#btn-insert` 在 2026-10-18 移除） | ⚠️ 需要重做 |

**结论**：**引擎侧零改动**，全部是前端 + localStorage。这是低成本方案。

### 3.3 三个设计方案（从轻到重）

#### 方案 A · 预设片段（最轻，1 天）

抽一个新面板「常用片段」：

```
┌─ 常用片段 ────────────────────────┐
│ [+ 新建]  [导入]  [导出]           │
│                                    │
│ ┌ 开头 ─────────────────────┐     │
│ │ 我是 SuperSu，每周分享…    │ ✎ ✕ │
│ │ 「关注我，不错过」          │     │
│ └───────────────────────────┘     │
│ ┌ 结尾 ─────────────────────┐     │
│ │ 如果这篇对你有用，点个「在看」│ ✎ ✕ │
│ └───────────────────────────┘     │
└────────────────────────────────────┘
```

- **插入方式**：编辑器顶部两个小按钮「插开头」「插结尾」，点一下插到光标处
- **存储**：`supersu.snippets = [{id, name, type:'head'|'tail'|'block', body}]`
- **不自动插入**：用户不接受「每篇都自动加」的话会烦。默认手动点

#### 方案 B · 三段式编辑（中等，3 天）

编辑器拆成三个可折叠区：

```
┌─ 内容 ─────────────────────────────┐
│ ▸ 开头（可选）               [展开] │  ← 收起时只占 28px
│ ▾ 正文                              │
│   ┌──────────────────────────────┐ │
│   │ 周末去了趟海边                │ │
│   │ 第一天：什么也没做            │ │
│   └──────────────────────────────┘ │
│ ▸ 结尾（可选）               [展开] │  ← 收起时只占 28px
└────────────────────────────────────┘
```

- **提交渲染时**：`开头 + '\n\n' + 正文 + '\n\n' + 结尾` 拼接
- **好处**：正文永远在中间，开头结尾不会被误删或改坏
- **代价**：要改 `doRender()` 的取文本逻辑；草稿格式从 `string` 变成 `{head, body, tail}`

#### 方案 C · 分模块编辑（最重，5+ 天）

整个编辑器变成**块列表**（像 Notion）：

```
┌─ 内容 ─────────────────────────────┐
│ [段落] 周末去了趟海边               │
│ [段落] 第一天：什么也没做           │
│ [段落] 两天里我没看手机…            │
│ [金句] 「后来我才发现…」            │
│ [+ 插入块 ▾]                        │
└────────────────────────────────────┘
```

- **好处**：最灵活，可以任意插入预设块
- **代价**：**推翻整个编辑器**，与项目「纯文本进、排版出」的核心理念冲突
- **我的判断**：**不建议**。这个项目最大的价值是「粘贴纯文本就能排版」，
  换成块编辑器会让老用户流失

### 3.4 我推荐：**A 先做，B 可选，C 不做**

理由：

1. **A 解决 80% 需求**：多数人要的就是「一段固定的开头/结尾，点一下插进去」
2. **B 的代价被低估了**：草稿格式变更会影响 `saveDraft` / `restoreDraft` / `pagehide` 三条路径，
   而且用户可能在「正文」里按下 Ctrl+A 全选，行为要重新定义
3. **C 违反项目定位**：`AGENTS.md` 写着「纯文本进，排版出」，块编辑器是另一个产品

### 3.5 预设的数据结构（建议）

```js
// localStorage: supersu.snippets
{
  version: 1,
  items: [
    {
      id: 'snip-1730…',
      name: '我的开头',
      type: 'head',            // head | tail | block
      body: '我是 SuperSu，每周分享…\n\n「关注我，不错过」',
      enabled: true,           // 用户可临时停用
      updatedAt: 1730000000000
    }
  ]
}
```

**渲染时拼接规则**（方案 B 才有）：

```
final = [head.body, body, tail.body].filter(Boolean).join('\n\n')
```

**导入导出**：做成 JSON 文件，方便换机器（与现有「备份/恢复本机数据」复用同一机制）。

### 3.6 与「整篇设计」的交互

**要注意一个冲突**：整篇设计（如时代周刊）的视觉语言是完整的。
如果用户硬塞一个花哨的开头（带 emoji、带分隔线），会和设计打架。

**建议**：整篇设计模式下，插入预设时**给一条提示**：

```
ⓘ 当前是「时代周刊」整篇设计，插入的开头会沿用它的样式。
   如果样式不协调，可以切到「配色主题」再插图。
```

不阻止，但提示。符合项目「不静默」的原则。

## 四、落地顺序（建议）

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P0** | ① 抽屉改成两个并列 tab | 无 |
| **P0** | ② 整篇设计模式下隐藏底部版式行 | 依赖 ① |
| **P1** | ③ 预设片段（方案 A） | 无（纯前端） |
| P2 | ④ 三段式编辑（方案 B） | 需要用户确认「草稿格式变更」可接受 |
| ❌ | ⑤ 分模块编辑（方案 C） | **不做**，违反产品定位 |
