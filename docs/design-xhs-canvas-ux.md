## 0. 修订记录（2026-11-01 上午，用户反馈后）

### 0.1 第一版为什么被否

用户原话：**「又极简过头了，啥都弹窗了。要适当精简啊，因为要常常切换的——选图之后要不断切不同版式看预览、切字体、切配色」**。

这是对第一版的核心判断错误：**我把「切换频率」当成了「功能重要性」，于是把最高频的三个动作（版式 / 配色 / 字体）关进了弹层。**

正确的判据只有一个——**切换频率决定它是否常驻**：

| 动作 | 真实频率 | 第一版的处理 | 应该的处理 |
|---|---|---|---|
| 换版式 | **极高**（选完图后连续试 5–10 次） | 弹层（每次开/关两次点击） | **常驻，一键** |
| 换配色 | **高**（和版式一起试） | 弹层 | **常驻，一键** |
| 换字体 | 中 | 弹层 | **常驻，一键** |
| 换底图 | 中（一轮试 3–5 张） | 弹层（合理，因为要大图候选） | 弹层或小图排 |
| 尺寸 / 署名 / 导出 | 低（最后一次性） | 弹层 | 弹层 |

弹层只应该装**低频、需要大空间**的东西（搜图候选、导出托盘、九宫格）。**高频的切换必须裸露在界面上。**

### 0.2 三版对比（等决策）

三版共用渲染内核 `xhs-ux-core.js`（从第一版原型抽出的同一份 `coverHtml`），
**画的封面完全一致**，差别只在控制区放哪。

| 指标（1440×900 实测） | A 三栏 | B 单侧集成栏 | C 双带环绕 |
|---|---|---|---|
| 画布尺寸 | 615×820 | **617×822** | 600×800 |
| 不滚动可见版式 | **9/9** | **9/9** | 4/9 |
| 不滚动可见配色/字体 | **8/3** | 8/0（要滚） | **8/3** |
| 画布中心→最近版式卡 | **499px** | 588px | 616px |
| 缩略图单张宽度 | ≈98px | ≈82px | **≈100px** |

**结论：A 综合最优**（画布几乎一样大，但全部控件一屏可见、离画布最近）。
C 的「版式贴着画布」直觉上更近，实测反而最远——因为竖排的起点在顶部，单列只能看 4 张。
B 画布最大，但配色/字体要滚动，把高频动作变成了两步。

**若选 A，建议两处微调**：右栏 3 列 → 2 列（缩略图 98→148px，看得清版式细节）、
左栏文案与配图合并压缩，把宽度让给右栏。

### 0.3 保留有效的部分

以下结论**不受布局方案影响**，三版都适用，落地时保留：

- 版式缩略图必须用**用户自己的文案**渲染（A/B/C 三版都已实现）
- 底图可读性四档判定（§5），含 sRGB 反解 α
- 「不要图」与纯文字版式的自动联动 + 版式可用性置灰（清单需 ≥2 条）
- 长文分页改「像素装箱 + 平均分配」（§6），末页欠填升格结尾页
- 保存 = 出片 → 托盘 → 下载（**这部分弹层是合理的，因为是低频一次性动作**）
- 长文整篇文章不常驻首屏（文章条 + 全屏编辑层）

> 下面 §1–§11 是第一版的完整论证，**布局部分（§2.1 删左右两栏）已作废**，
> 其余章节（可读性 / 分页 / 自检 / 踩坑 / 落地清单）仍然有效。

## 0. 一句话结论

**现在的封面页把「画布」和「设置」当成同等重要的两块，而用户其实只想看那张图。**
本方案把**画布提到占屏约 68%**，把所有设置收进**不遮画布的弹层**，并把「保存」拆成「出片 → 托盘 → 下载」两个明确动作。

## 1. 现状诊断（代码实证，不是感觉）

| 问题 | 实据（`pwa/src/cover/`） |
|---|---|
| **同一张图出现两次** | `title-page.js:664-685`：中栏上半「实时预览」，下半「标题图结果」画廊——预览已是成品，结果区是同一张图的第二次呈现 |
| 首屏 4 个可交互区 | 左栏 7 个 `.cv-sec`、中栏预览 + 结果 + 示例墙、右栏 9 张版式卡 × 27 个色点 |
| **两个模块各一套骨架** | `title-page.js` 与 `longform-page.js` 结构近同构，但切 tab 后所有位置都变，用户要重新找 |
| **版式卡是「别人的图」** | 右栏缩略图是预渲染的 `cover-thumbs/*.png`，看不到**自己的文案**在那个版式里的样子 → 只能靠想象，所以反复试 |
| **保存没有确认环节** | `generate()` 生成后直接 `want.click()` 落盘，用户不知道存到哪、存了几张 |
| 长文文章常驻首屏 | 300 字的 textarea 占 284px，画布被压到 473px 高——用户此刻要看的是成品，不是自己刚粘的原文 |

**根因不是「功能多」，是「画布太小 + 决策点太散 + 预览和结果是两回事」。**

## 2. 三条结构改动

### 2.1 删掉左右两栏，画布升为主角

```
改前：  [左 348px 设置] [中 预览+结果+示例墙] [右 版式卡 27 色点]
改后：          ┌─────────────────────────────┐
                │  命令栏（输入 + 胶囊 + 保存）│   ← 一条，不占两栏
                ├─────────────────────────────┤
                │                             │
                │        画  布  （68%）        │   ← 唯一的主角
                │                             │
                ├─────────────────────────────┤
                │ 1080×1440 · 改完即时预览 · 九宫格 │
                └─────────────────────────────┘
```

**实测数据**（1440×900，CDP 量取）：画布从改前约占屏 40% → 改后 648px 高，占可用区 **93%**。

### 2.2 胶囊 = 入口 + 当前值

命令栏下方四颗胶囊：`配图 · 海边雾晨` / `版式 · 全出血` / `文字 · 跟随版式` / `尺寸 · 3:4`。

**它既是打开面板的按钮，也是当前状态的显示**——省掉一整套「当前设置摘要」。原来这类摘要要么不存在（用户忘了自己选了什么），要么单独占一块（重复信息）。

选中态用 `--accent` 描边 + 文字变红，一眼看出「这颗胶囊的面板正开着」。

### 2.3 版式缩略图用**你自己的文案**实时渲染

这是整套方案最关键的一处。

| | 改前 | 改后 |
|---|---|---|
| 缩略图内容 | 预渲染的示例图（`cover-thumbs/*.png`） | **用户当前那句话**，用与画布完全同一套渲染函数画 |
| 用户要做的 | 靠想象「我的字放进去好不好看」 | 直接看到 9 种结果 |
| 试错成本 | 点一次 → 看画布 → 不满意 → 再点（9 次） | 一屏看 9 种，选一次 |

**实现要点**：缩略图不是截图，而是 `coverHtml(1080, 1440, {...})` 生成真实画布后整体 `scale()`。缩放比**必须运行时量容器宽度**——写死 `320/1080` 会因面板列宽变化而溢出裁切（本项目已踩过，见 §8 坑 3）。

### 2.4 两个模块共用一套骨架

| | 标题图 | 长图文 |
|---|---|---|
| 命令栏 | 一句话（2 行 textarea） | **文章条**：标题 + 「309 字 · 自动分 5 页」+ 编辑全文 |
| 胶囊 | 配图 / 版式 / 文字 / 尺寸 | 配图 / **模板** / **配色** |
| 画布 | 1 张 | 当前页 1 张 + 左右翻页箭头 |
| 画布下方 | — | **胶片条** P01–P05（点缩略图跳页） |
| 主按钮 | 保存大图 | 导出整套 |

切 tab 后位置全不变，只有输入形态与画布下方多一条胶片。

**长文为什么用「文章条」而不是常驻 textarea**：实测 300 字占 284px，画布只剩 473px。改成文章条后画布回到 554px（+17%）。整篇文章要看的时候点「编辑全文」升一个 88vh 的全屏层——**读改和看图是两件事，不该抢同一块空间**。

## 3. 保存流程：出片 → 托盘 → 下载

原来点保存直接 `a.click()` 偷偷落盘。现在拆成两步：

```
点「保存大图」
   ↓ 画布闪一下（0.55s 定影动画，暗示正在出片）
   ↓ 画布让位（padding-bottom 112px，托盘不盖住标题）
   ↓
┌──────────────────────────────────────────────────────┐
│ [缩略图]  ✓ 大图已生成                                │
│           1080 × 1440 · PNG · 纯前端生成              │
│                          [复制]  [下载 PNG]           │
└──────────────────────────────────────────────────────┘
```

- **托盘不自动消失**（9 秒后才收），用户确认后再关
- 长文时变成「整套 5 张已生成 · 封面 + 4 张内页」+ `[九宫格] [复制首图] [打包 ZIP]`
- **画布必须让位**：托盘是 `fixed` 不参与布局，实测会盖住底部 59px——正好是标题所在的位置

## 4. 版式清单（9 套，分两组）

| 组 | 版式 | 文字保护方式 |
|---|---|---|
| **① 有底图（4 套）** | 全出血 / 刊头 / 左文右图 / 卡片浮层 | 局部 scrim / 空间分离 / 卡片容器 |
| **② 纯文字（5 套）** | 瑞士极简 / 大字报 / 金句 / 编号大字 / 清单 | 不依赖底图，靠留白 + 字号对比 |

**分组的意义**：用户第一步要决定的是「有没有图」，第二步才是排版。混在一个网格里会让 9 个平级选项互相抢注意力。

### 「不要图」与版式自动联动

- 切「不要图」→ 若当前版式需要图，自动落到「瑞士极简」+ toast 提示
- 切回「搜图」→ 自动回到「全出血」
- 版式面板**只列当前可用的那组**，不给用户点了报错的选项

### 有前提内容的版式要置灰 + 说明

「清单」需要 ≥2 条条目（用「、」或换行分隔）。只有 1 条时：
- 卡片 `disabled` + 缩略图去饱和（`filter:grayscale(.75)`）
- 描述文字换成原因：**「需要 2 条以上小字（用「、」或换行分隔）」**
- 渲染层兜底：真被调用也退化成「金句」排法，**绝不留半页空白**

## 5. 底图可读性：四种判定（沿用 design §11 口径，不重新发明）

```js
zone = 由「文字块实际高度」反推（不是常量）
busy = 带内最大标准差 > 0.15      ← 明暗交错，任何单色字都会在某处失效

① 不 busy 且白字 ≥4.5  → 白字，α=0（不压暗）
② 不 busy 且黑字 ≥4.5  → 黑字，α=0
③ 不 busy 且 α(sRGB) ≤ 0.30 → 白字 + 该 α
④ 其余 → 判不合格，α=0，提示「建议换版式」
```

**原型实测数据**（运行时真算，不是查表）：

| 照片 | 判定 | α | 对比度 |
|---|---|---|---|
| 海边雾晨 | 免压暗 | 0 | 11.1:1 |
| 山野秋千 | 轻压暗 | **0.106** | 4.50:1 |
| 夜街路灯 | 免压暗 | 0 | 14.8:1 |

**「山野秋千」是关键验证点**：天空亮度 0.87，若用旧的线性公式会算成 α 0.20（照片被多压一倍 = 用户抱怨的「灰雾」）。sRGB 反解只要 0.106。

**压在照片上的文字另加极淡投影**：`text-shadow: 0 1px 18px rgba(8,7,6,.34)`。
- 模糊半径 18px 而不是 `2px 2px`——硬投影会让笔画发虚，大半径才是「衬底」
- scrim 管 90%，投影只补笔画边缘那 10%（design §5 铁律 3）

## 6. 长文分页：像素装箱 + 平均分配

> ⚠️ **本方案在这一处推翻了原口径**，理由如下。

### 6.1 不能用「行数包络」

design §6 原口径是 `Σceil(字数/17) + 段数 ≤ 13`。实测证明它对「段数多、每段短」系统性低估：

| 内容 | 行数包络 | 实际占高 | 后果 |
|---|---|---|---|
| 4 段 × 10 字 | 6.2（判「够满」） | 约 33% 画布 | 最后一张看起来像「图断了」 |

原因：每段都要付一次 43px 段间距，包络公式只给 0.55 的权重。

### 6.2 也不能纯贪心装满

贪心 → 前几页 100%、末页 35%。读者翻到最后一张看到大片空白，会怀疑「是不是没生成完」。

### 6.3 落地口径（原型已实现）

```js
PAGE_H = 1108          // 1440 − 176(页眉) − 156(页脚余量)
blockH(b) = 行数 × 52 × 1.74 + 43   // 真实像素高度
总高 = Σ blockH
页数 n = ceil(总高 / PAGE_H)
目标每页高 = 总高 / n
→ 按目标高度分配，每页填充率一致
```

**实测结果**（示例文章 309 字）：

| 页 | 角色 | 填充率 |
|---|---|---|
| P2 | 开篇 | 20%（airy 版式，靠锚点成立，不是靠填充） |
| P3 | 正文 | 93% |
| P4 | 正文 | 81% |
| P5 | **结尾** | 48%（结尾页本来就该疏：CTA + 留白） |

### 6.4 末页欠填 → 升格「结尾」而不是硬塞

末页填充率 < 62% 时：
1. 先尝试与上一页合并（合并后须 ≤ `PAGE_H × 1.02`）
2. 合并不下 → 升格 `closing` 角色

**结尾页的空白读作设计**（色条 + 「收藏 · 下次照着做」CTA + 留白），而不是「没生成完」。

### 6.5 开篇页靠「锚点」成立

airy 版式（design §6 对 M13 的原文：*intentionally airy, required anchors*）：

- **上锚点**：`开篇` kicker + 58px 色条
- **下锚点**：`— 署名` + `往下读 ↓` + 一条细线

中间留白是刻意的。**不给开篇页硬塞内容**——那是「大字引言」的代价，不是排版失误。

## 7. 自检脚本（产物级，22 项）

`node scripts/xhs_canvas_ux_check.mjs`（零依赖 CDP，Node ≥22）

**为什么需要它**：本项目最大的系统性盲区是「有反应 ≠ 产物正确」。所以每一项都验产物：

| # | 用例 | 验的是 |
|---|---|---|
| 1 | 首屏有画布且不是空的 | `.cv-art` 存在 + `.ttl` 有文字 + 尺寸正确 |
| 2 | 胶囊显示当前值 | 每颗 `.v` 非空 |
| 3 | 切版式 → 画布结构真的变了 | `innerHTML` 前后不同 + `state.lay` 跟上 |
| 4 | **版式缩略图用用户自己的文案** | 9 张缩略图 textContent 都含「周末去了趟海边」 |
| 5 | 切「不要图」→ 自动落纯文字版式 | 无 `.ph` 元素 + lay ∈ 纯文字组 |
| 6 | 切回搜图 → 版式回到有图那套 | 有 `.ph` |
| 7 | **换底图 → 图 src 真的换了** | `img.src` 前后不同 |
| 8 | **换配色 → 纸张色真的换了** | `--paper` 变量前后不同 |
| 9 | 竖排 → `writing-mode` 真的变了 | `getComputedStyle().writingMode` |
| 10 | 1:1 → 画布真的 1080×1080 | `style.width/height` |
| 11 | **保存 → 托盘出现且缩略图有内容** | 托盘 on + 缩略图 innerHTML>200 + **与画布零遮挡** |
| 12 | 关托盘 → 画布回原位 | `.tray-open` 类已移除 |
| 13 | 长文分页 > 1 且角色齐全 | 首封面 + 含 opening + 末页非 dense |
| 14 | **长文每页正文真的落版** | 逐句比对：所有段落文字都在某页 DOM 里 |
| 15 | 翻页箭头与胶片条同步 | `aria-pressed` 索引 === `state.page` |
| 16 | 末页不空 | 填充率 ≥ 40% 或 role === closing |
| 17 | 换模板 → 内页骨架真的变了 | `longPageHtml` 前后不同 |
| 18 | 锁色模板 → 色板置灰并给理由 | 全部 `disabled` + 文案含「自带配色」 |
| 19 | 导出整套 → 托盘张数与页数一致 | 文案含「封面 + N 张内页」，N = 页数−1 |
| 20 | 切回标题图 → 布局复位 | 胶片条与箭头都 `hidden` |
| 21-22 | 375px 无溢出 | `scrollWidth` + **元素级逐个检查 `right > innerWidth`** |

## 8. 本轮踩到并修掉的坑（都写进了代码注释）

| # | 坑 | 表现 | 修法 |
|---|---|---|---|
| 1 | **三元运算符优先级** | `photo ? A : '' + B` 解析成 `photo ? A : ('' + B)` → 「左文右图」有图时文字全丢 | 给三元加括号 `(photo ? A : '') + B` |
| 2 | **`[hidden]` 被 `display:flex` 压过** | `.film{display:flex}` 让 `hidden` 失效，空态留 8px 空隙 | 全局 `[hidden]{display:none !important}` |
| 3 | **缩略图缩放写死** | 写死 `320/1080` → 面板列宽变化后内容溢出，只剩左上角一块 | 运行时量 `parent.clientWidth` |
| 4 | **缩略图渲染尺寸叠加缩放** | 传 320×427 又被外层 `scale(0.18)` → 只剩指甲盖大 | 统一按 1080×1440 渲染 |
| 5 | **模板面板全画成同一套** | `longPageHtml` 硬读 `state.tpl` → 6 张缩略图一模一样 | 加 `tplOverride` 参数 |
| 6 | **函数名拼错静默失败** | 调 `analysis()` 但函数叫 `analyze()` → Promise 不抛，只表现「点照片没反应」 | 改正 + `.catch()` 兜底 + 加进自检用例 |
| 7 | **托盘盖住画布** | `fixed` 不参与布局，实测盖住底部 59px（正好是标题） | `.app.tray-open .stage{padding-bottom:112px}` + `fit()` 读实际 padding |
| 8 | **胶片条被切一半** | `fit()` 写死 `filmH=74`，实际 85 | 改 `filmEl.offsetHeight + 8` |

| 12 | **`cdp_measure` 不支持 await** | snippet 里 `await` 报「only valid in async」 | 包成 `async function(){...}()` |

## 10. 取舍说明

| 决定 | 理由 |
|---|---|
| 不做「一屏看全部设置」的开关 | 那是把复杂度交给用户管理，等于没解决 |
| 不砍版式数量（9 套） | 数量是资产不是负担，问题在**呈现方式**（平铺 vs 分组 + 自己的文案预览） |
| 长文不做多尺寸 | 多尺寸会让页数翻倍，用户分不清哪套是哪套 |
| 封面不给单独换版式 | 封面是整套模板的第 1 页；单独换会像两篇（竞品 XHS-TextCard 的 `template` 字段也是整套一个） |
| 弹层而不是侧边抽屉 | 面板最高 70vh 居中悬浮，上方画布仍在视野里——调参数时眼睛不用来回跳 |
| 不给「遮罩浓度 0–100%」滑块 | 用户没有亮度直方图可看，只能瞎试（沿用 design §3 的判断） |
| 文章编辑用全屏层而不是抽屉 | 整篇文章是要静心读改的东西，70vh 的半吊子高度不够 |
