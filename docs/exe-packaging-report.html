📦 SuperSu 封装为 EXE 调研报告

调研日期 2026-07-26 · 目标：让使用者「双击即用」，无需装 Python / Node / 浏览器

一句话结论：对本项目（Flask + Playwright Chromium + Node.js 三件套）而言， 「PyInstaller（--onedir 模式）+ Inno Setup 安装包」是效果最好的 EXE 封装路线。

不要用 --onefile（每次启动解压、卡顿明显），也不要用 Nuitka（本项目不是计算密集型，且无收益却要承担 Playwright/PIL 等 C 扩展库的兼容性风险）。

1. 背景与诉求

使用者双击 app.py 毫无反应——因为 Windows 用系统默认 Python（未装依赖）去跑，秒报错退出。 即便改用一键启动器 start-app.bat，仍依赖本机已有 Python 虚拟环境 + Playwright Chromium + Node.js 三件套。

真正的诉求是：打包成一个（或一套）EXE，双击就起服务并自动弹浏览器，目标机器零环境。

关键事实：Playwright 官方文档明确支持 PyInstaller（有专门章节，使用 PLAYWRIGHT_BROWSERS_PATH=0 将浏览器打进包）；而 Nuitka 对 Playwright、Pillow 这类含 C 扩展的库兼容性需要额外配置，社区踩坑案例较多。

两个外部引擎的硬依赖（来自源码确认）

  • 归藏引擎 core/guizang_renderer.py：p.chromium.launch() → 必须随包带 Playwright Chromium。
  • BLCaptain 引擎 core/blcaptain_bridge.py：subprocess.run([self.node_bin, ...])，node_bin 默认系统 node → 必须随包带 Node.exe 并在代码里改指向。

4. 最终推荐：PyInstaller --onedir + Inno Setup

为什么是它，而不是别的：

  • ✅ Playwright 官方支持：用 PLAYWRIGHT_BROWSERS_PATH=0 playwright install chromium 把浏览器打进包，无需用户联网下载。
  • ✅ Flask 资源处理成熟：海量案例用 sys._MEIPASS 适配 templates/ 与 public/ 路径。
  • ✅ --onedir 优于 --onefile：启动不二次解压、快；且方便把 Chromium、Node、封面引擎目录平铺进同一目录。
  • ✅ Inno Setup 收尾成「一键安装包」：建桌面快捷方式、写卸载、可捆绑运行 playwright install 逻辑，体验最像正常软件。
  • ✅ 本项目非计算密集：Nuitka 的「编译加速」在这里几乎没有可感知收益，却要承担复杂 C 扩展库兼容性风险，不划算。

5. 打包需要做的代码改造

改造点做法
Flask 资源路径在 app.py 用 sys._MEIPASS 判断冻结环境，将 template_folder/static_folder 指向打包内目录
Node 运行时BLCaptainBridge(node_bin=<打包内 node.exe>)，或用环境变量注入；blcaptain_dir 指向打包内目录
Chromium构建前 PLAYWRIGHT_BROWSERS_PATH=0 playwright install chromium；运行时让 PLAYWRIGHT_BROWSERS_PATH 指向打包内浏览器目录
PyInstaller 参数--onedir --add-data "templates;templates" --add-data "public;public" --add-data "blcaptain-style-skill;blcaptain-style-skill" --add-data "node.exe;." --collect-all playwright
自动弹浏览器入口 __main__ 保留 webbrowser.open("http://127.0.0.1:5000")，打包后仍自动开

6. 体积与分发预估

  • 解压后目录 ≈ 580M（Python 251 + Chromium 150 + Node 100 + 封面引擎 74 + 静态 6）
  • Inno Setup LZMA 压缩后安装包 ≈ 280–380M
  • 对比现状（start-app.bat 自动下载）：用户机器首次需联网下载 Chromium ~150MB 且需本机有 Node；EXE 方案一次性包含，离线可用。

7. 风险与坑清单

  • 🔴 杀软误报：含浏览器内核的 EXE 极易被 Windows Defender 误报为病毒。建议代码签名，或安装包内附「加白名单说明」。
  • 🟠 版本锁定：Playwright 库版本与 Chromium 版本必须严格一致，用 requirements.txt 锁定。
  • 🟠 临时目录权限：PyInstaller 运行时解压到 %TEMP%，需保证写权限。
  • 🟡 构建慢：PyInstaller 几分钟；若改用 Nuitka 会到 5–15 分钟且更易失败。
  • 🟡 体积大：安装包 300M+，下载/分发成本高（相对「bat + 在线下载」方案）。

8. 替代方案对比

方案体验工程量适用
A. 现状 bat（已做）需本机有 venv/Chromium/Node低自己/内部分发
B. PyInstaller onedir + Inno Setup双击安装→桌面图标→自动弹浏览器，零环境中给普通用户·推荐
C. 纯 Inno Setup 安装器（装 venv+Chromium+Node）同 B，但底层仍是 Python 项目中低不想折腾 py→exe 时
D. Docker 镜像需装 Docker，映射端口低服务器/云端

9. 给使用者的决策建议

  • 🎯 目标＝「给不懂 Python 的普通用户一个双击即用的东西」→ 选 方案 B（PyInstaller onedir + Inno Setup），一次性包含 Chromium + Node，离线可用、自动弹浏览器。
  • 🛠 目标＝「内部/自己用」→ 现状 bat 或方案 C 安装器足矣，不必 py→exe。
  • 🚫 不建议 Nuitka：本项目无性能收益，且 Playwright/PIL 等 C 扩展库在 Nuitka 下兼容性风险高。
