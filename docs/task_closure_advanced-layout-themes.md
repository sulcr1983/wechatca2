## 1. 需求实现与验证

### 1.1 高级排版（无需 LLM）

**关键调研结论**：92 套主题的 `layout` 字段分布为 `hero` 13 / `card` 4 / `timeline` 1 / 无 74，但引擎**只实现了 `card`** —— 13 套 hero + 1 套 timeline 的配置从未被读取，属死配置。这些是「带语义角色的容器」，本地正则可 100% 稳定转出，**不需要 LLM**。

| 项 | 实现 | 验证 |
|----|------|------|
| 布局分发 | `inject_inline_styles` 第 8 步补 `hero`→`_wrap_hero_sections`、`timeline`→`_wrap_timeline_sections` | 13+1 套主题渲染出深色首屏/大序号/色带/引文/时间线 |
| 模块容器 | 新增 `:::eyebrow` / `:::cards` / `:::summary` / `:::cta`（容器 8→12 种） | 4 个模块在各主题下有样式且配色跟随主题 |
| 模块样式跟随主题 | `_inject_container_styles` 从 `theme.colors` 派生 surface/text/muted/border/页面底色 | 92 套主题模块不再是同一套灰白 |
| 前端入口 | 输入框工具条加 `#module-picker`（11 个模块模板，光标处插入 + 自动渲染） | 有头实测：末尾追加不覆盖、预览自动刷新 |

### 1.2 色带可见性（用户明确要求）

13 套 hero 主题的 `alt_bg` 为 `#fafafa` / `#f7f7f8`，与白底通道差仅 15/23 → 肉眼看不出交替色带，等于特性未生效。

新增 `_resolve_band_bg` + `_BAND_MIN_DISTANCE`(45)：不足则按 accent 逐步混 12%→24% 派生**带主题色系**的色带，低饱和强调色再压 6% 墨色兜底。

**实测**：13 套色带通道差 **15–50 → 46–57**；有头浏览器目视确认「很明显」，且三套主题色带色调各异（冷蓝 `#ECEEF1` / 暖米 `#FDEFD8` / 暖橙 `#FCEBE2`）。

### 1.3 主题体系重构为纯原创（版权了结）

**原风险**：47 套主题的 `source` 全部指向外部仓库（**该仓库无 LICENSE = 保留所有权利**）；文件前缀、展示名、描述文案、样式数值（29–39 键）均为外部原值。本项目已定开源 = 分发 → 真实授权风险。

**做法**：`scripts/theme_specs.py` 写 47 条**设计意图**（底色/墨色/强调色/字体气质 + 9 种排版原型 + 布局），`scripts/build_themes.py` 用**本项目自己的设计标尺**推导全部数值；色带直接复用引擎 `_resolve_band_bg` 保证单真源；命名与描述自拟。

**结果核对**（live `GET /api/themes`）：92 套 = 45 套早期原创 + 47 套 `su-*`；旧前缀 0 张、`source` 字段全清、无重名。

**侵权文字清理**（用户要求「不能完全看得出」）：
- 删除 3 个脚本：旧适配脚本 + 2 个一次性去重脚本（目标 id 均已不存在，属死代码，且是外部来源痕迹的主要载体）
- 清理 `AGENTS.md` / `HANDOFF.md` / `docs/task_closure_social-bg.md` / `files/TODO.md` 中所有外部仓库名与「开源适配」表述，改为中性描述
- 保留历史记录的可读性（历史条目改为「外部仓库」并标注「已被推翻」），不篡改事实

### 1.4 修复本轮发现的问题（共 9 个既有缺陷 + 3 项本批自查）

**A. 高级排版相关（4 个既有缺陷，均实测复现后收掉）**

| # | 缺陷 | 后果 | 修复 |
|---|------|------|------|
| 1 | 容器内层 `<p>` 专属样式从未生效（通用标签注入抢先加 `style`，精确匹配失配） | `:::stat` 的 48px 大数字、引文卡样式全部没生效——**这是「高级排版弱」的直接原因** | 通用注入跳过带 `data-container=` 的元素 |
| 2 | 预处理器把容器**内部**短行标成 `##` | `:::stat` 数字变 `## 42%`、`:::steps` 步骤全废 | `preprocess` 加 `container_depth` 跟踪 |
| 3 | 容器缺收尾 `:::` 会吞掉后面整篇正文 | 静默丢正文，违反「不静默」契约 | 改为整段原样输出 |
| 4 | 容器标记本身会被「短行标题」规则改写 | `:::cta[标题]` → `## :::cta`，容器直接坏掉 | 容器标记原样穿透 |

**B. 代码块相关（3 个既有缺陷，串行正则一族问题）**

| # | 缺陷 | 修复 |
|---|------|------|
| 5 | 每个带语言标记的代码块开头多显示一行 `class="language-xxx">`（高亮器把 code 开标签一起正则高亮，标签被拆碎） | 先摘出 code 开标签、高亮后补回 |
| 6 | 含 f-string 的代码多出 `"color:#ce9178"` 碎片（字符串规则命中前一步自己插入的 style 属性值） | 各步片段存入 `\x00H{i}\x00` 占位符，末尾统一还原 |
| 7 | 手写 ```` ``` ```` 围栏被截断（Python 缩进行被当新代码块，`def` 与 `return` 被拆开） | `preprocess` 新增 `in_fence` 状态，围栏内原样保留（含缩进） |

**C. 有头 E2E 发现（3 个，本轮修复）**

| # | 缺陷 | 修复 |
|---|------|------|
| 8 | 18 套主题的 h2 左边框强调条**静默失效**（生成器值里重复带键名 → `border-left:border-left:…` 被浏览器判非法丢弃） | 生成器改为 `border_left` + `padding_left` 两个键 |
| 9 | `su-deepwater` 的 hero 卡片**浅字白底不可读**（卡面写死 `#ffffff`，暗底主题正文是浅色，对比度约 1.2:1） | 卡面按页面底色向墨色靠 7% 派生：`#0E1726` → `#1C2534` |
| 10 | 37 套亮底主题代码块**语法高亮对比度过低**（亮底仍用深底调色板，关键字对比度约 2.2:1 发灰） | 新增 `_SYNTAX_LIGHT` 调色板 + `_is_light_bg()` 按 `pre` 背景明暗切换 |

**D. 本批自查清理（3 项）**

| # | 问题 | 修复 |
