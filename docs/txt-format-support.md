## 0. 前提与硬约束

1. **只做确定性识别**（AGENTS §10 拍板）：不做散文「主题句提升」、不做「规则发明小节」。新增规则必须能靠字符特征稳定判定。
2. **原文保真优先**：不得改写数字、专有名词、代码、诗词（夹具硬要求 H 类断言）。
3. **微信用途约束**：复制到公众号的 HTML **不能依赖** `<style>`、`class`/`id` 选择器、`:before/:after` 伪元素、外部 CSS —— 一切样式必须内联（引擎现有做法，新容器同样遵守）。
4. **可开关**：会改变现有观感的规则应可关闭；「文本清理类」默认关闭。

## 1. 现有能力盘点（已支持，无需新增）

| 类别 | 已支持写法 |
|---|---|
| 标题 | 首行提升 H1；`#`~`######`；`第一章/第一节/第一篇`；`3.1 / 3.2.1` 点分编号；序数词小节（tutorial） |
| 列表 | `-` `*` `+` 无序（符号后需空白）；标准有序 `1.`；`·•●○` 项目符号；箭头行 `→ -> ➔ ➜ ⇒`；嵌套（保留缩进） |
| 强调 | `**加粗**` `*斜体*` `~~删除线~~` `` `行内代码` `` |
| 引用 | `>` 引用块 |
| 提示 | `注意|提示|警告|重要说明|说明|备注|免责声明|声明|注:` → 引用块（`_NOTICE_RE`） |
| 代码 | ```` ```lang ```` 围栏（多语言）；4/8 空格缩进 → 代码块；行内代码 |
| 表格 | GFM 管道表（含 `---:` 对齐行） |
| 链接媒体 | Markdown 链接/图片；裸链；邮箱；电话；`[图片：…]` 占位保留为文本 |

| 容器 | `:::type[标题]` 12 种围栏容器 |
| 安全 | HTML 片段渲染前 `sanitize_raw_html`（危险标签/事件/协议清除） |

## 4. 明确不做（防止过度工程）

- 支持 BBCode / reStructuredText / AsciiDoc / Textile / Org-mode / wikitext 等另类标记语言——目标场景是 TXT 与公众号，收益低、维护成本高。
- 自动「发明」小节标题、自动改写数字/专有名词、自动生成占位图片——违反原文保真与 AGENTS §10。
- 依赖 `<style>`/class/伪元素/外部 CSS 的样式——微信编辑器不支持。

## 5. 决策结论（2026-10-19 已定，用户授权「按推荐执行」）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 「标签：」短行是否继续当标题 | **保持现状**（当标题） | 既有设计（AGENTS §10 已记录「短标签行保留结尾冒号」），改动会大范围改变观感 |
| 2 | 提示类（`注意：`/`提示：`/`风险：`）边界 | **保持现状**（行首标签 → 引用块） | `_NOTICE_RE` 只认行首标签，含「注意」二字的普通句子本就不触发；不再扩大 |
| 3 | `（1）（2）` 属标题还是列表 | **不再判标题**，保持原文行 | 夹具 §04 明确「看起来像列表，但未必是列表」；原先一律判四级标题是误判 |
| 4 | 诗词是否专门容器 | **保持现状**（换行已保留） | 加容器属过度工程，收益低 |
| 5 | 文本清理（pangu/全角） | **不做**（默认关 = 不做） | 违反「不擅自改写原文」；夹具硬要求 |
| 6 | 数学公式 | **只保留原文**（不引 KaTeX） | 体积 + 微信兼容风险，收益低 |
| 7 | 夹具入库位置 & 断言扩充 | ✅ `tests/fixtures/txt-format-lab.txt` + 断言 **34 → 40** | 原脚本写死仓库外绝对路径（`E:/personal/Downloads/…`），换机即挂 |

**实施时额外决定**：Setext 下划线标题（`标题` + `===`/`---`）**不做** —— 与既有「整行 `===`/`---` → 水平线」行为互斥，且现有断言（S02/S03）钉死了 `====` 分隔线语义。

## 7. 实施结果（2026-10-19 完成）

### 已实现（`core/preprocessor.py`）

| 项 | 实现 |
|---|---|
| GFM 任务清单 | `- [ ]` / `- [x]` → `☐` / `☑`（保留原文文字与原行首缩进） |
| 章节标记 | `NN｜标题`（**全角竖线**，刻意不收半角 `|` 以免撞 Markdown 表格首列）→ `##` |
| 括号编号 | `（1）（2）` **永不判标题**，保持原文行（渲染层按 `<br>` 分行） |
| 无分隔行竖线表 | **整表规整**：补首尾竖线 + 补表头分隔行（python-markdown `tables` 要求行首 `|`） |
| 空格对齐表 | 列间 ≥2 空白、≥2 行、列数一致 → 管道表（保守，防误判） |
| 波浪号围栏 | `~~~` 等价 ` ``` ` |
| GFM Alerts | `> [!NOTE]`/`[!TIP]`/`[!IMPORTANT]`/`[!WARNING]`/`[!CAUTION]` → `> 【中文标签】` |
| admonition 别名 | `::: tip/note/info/warning/caution/danger/important/details`（含带空格写法）→ `:::summary[中文标签]`，复用现有容器 |
| 方括号提示标签 | `【提示】【注意】【警告】【风险】【说明】【备注】【重要】` → 引用块（**不含** `【教程型】` 等体裁标签） |

⚠️ **踩到的坑（已修）**：表格必须**自成一块**——生成表格前要补一个空行，否则会与上一行文字并成同一段落，Markdown 不认表格（实测 `简单的竖线分隔表格（非标准 Markdown）：` 紧跟表格时未渲染）。

### 未实现（按决策 5/6 + 冲突）

Setext 下划线标题、文本清理（pangu/全角）、公式渲染、TSV/CSV、`==高亮==`、脚注渲染、字母编号转列表——理由见 §5。
