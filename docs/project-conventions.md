# SuperSu 项目产出物与文档规范 v1

> 2026-10-18 制定。目的：解决"文档、代码、产出物乱七八糟"的问题。
> **本规范对后续所有任务生效**；历史遗留按 §7 分步清理（不一次性大动，避免误删）。

---

## 一、一句话原则

**三类东西三个家，一个文件只有一个家。**

| 类型 | 只放哪 | 判断方法 |
|---|---|---|
| **源代码** | `core/` `scripts/` `templates/` `app.py` `tests/` `pwa/src/` | 手写的、要维护的、进 Git 的 |
| **生成物** | `output/` `data/` `test_output/` `temp_covers/` `uploads/` `pwa/dist/` | 能被程序重新生成的 |
| **文档** | 根目录 5 个主文档 or `docs/` 专题 | 给人读的 |

**任何新文件先回答三个问题**：① 它是什么类型？② 该进 Git 吗？③ 能重新生成吗？

## 二、目录职责表（放什么 / 禁放什么 / 是否进 Git）

| 目录 | 放什么 | 禁止放什么 | Git | 可再生 |
|---|---|---|---|---|
| `core/` | Python 引擎模块（排版/预处理/发布/封面桥接） | 脚本、测试、临时文件 | ✅ | ❌ |
| `scripts/` | 可独立运行的维护脚本（生成主题、生成缩略图、体检） | 业务逻辑（业务逻辑进 `core/`） | ✅ | ❌ |
| `templates/` | Flask 模板（`index.html`） | 静态资源（进 `public/`） | ✅ | ❌ |
| `tests/` | 测试套件 + 测试脚本 | 测试产物（截图进 `test_output/`） | ✅ | ❌ |
| `public/` | 运行期静态资源：主题 JSON、缩略图、字体、封面模板、vendor | 源码、文档、运行时数据 | ✅（部分） | 主题/缩略图可再生 |
| `docs/` | **只放文档**（`.md`）与文档配图（`docs/assets/`） | 截图堆、原型、产物 | ✅ | ❌ |
| `data/` | 运行时数据：配置、账号、缓存、草稿 | 代码、文档 | ❌ | 部分（缓存可再生） |
| `output/` | **交付级产物**：封面渲染图、审计报告、评审页 | 源码、文档 | ❌ | ✅ |
| `test_output/` | **测试/调试产物**：截图、临时脚本、日志 | 任何要长期保留的东西 | ❌ | ✅ |
| `uploads/` | 用户上传（会话级） | 长期资产 | ❌ | ❌（用户数据） |
| `temp_covers/` | AI 封面临时图（会话级） | 长期资产 | ❌ | ✅ |
| `files/` | 唯一保留：`TODO.md`（待办） | 其他杂项 | ✅ | ❌ |
| `pwa/` | PWA 专属：`index.html` `src/` `public/` `scripts/` `dist/` | **引擎副本**（必须引用 `../core/`） | ✅（dist 除外） | dist 可再生 |
| `blcaptain-style-skill/` | vendored 第三方（自带 git + node_modules） | 我们的代码 | ❌ | ❌（第三方） |
| `reports/` | 一次性诊断报告（可归档） | 长期文档 | ⚠️ 建议移 `docs/archive/` | — |

## 三、文件命名规范

| 类型 | 规则 | 示例 |
|---|---|---|
| Python 模块 | 小写下划线 | `preprocessor.py`、`gen_theme_thumbs.py` |
| 前端 JS | 小写下划线（PWA 内） | `engine_worker.js`、`cover_render.js` |
| 文档 | 小写连字符，**主题名在前、类型词在后** | `pwa-design.md`、`wechat-page-redesign.md`、`project-conventions.md` |
| 任务收尾记录 | **不再单独建文件**，合并进 `CLOSURE.md` | ❌ `task_closure_xxx.md` |
| 测试 / 调试产物 | 前缀标明来源 | `p0_1_main.png`、`full_check.log` |
| 生成物 | 跟生成器一致 | `theme-thumbs/{theme_id}.jpg` |
| 日期 | ISO 格式 `YYYY-MM-DD` | 报告标题内使用 |

**禁止**：`test.py`、`new.html`、`temp.md`、`副本`、`final`、`v2最终版` 这类名字。

## 四、文档体系（5 个主文档，各管一件事）

| 文件 | **唯一职责** | **不该写什么** |
|---|---|---|
| `README.md` | 对外门面：是什么、怎么装、怎么跑、截图 | 变更历史、任务细节、内部 TODO |
| `AGENTS.md` | 项目规则：架构、命令、禁忌、测试契约 | 一次性任务记录、长篇变更流水 |
| `HANDOFF.md` | **变更历史**：按时间倒序，一条变更一节（诉求/实现/验证/影响/风险） | 待办清单、回滚点细节 |
| `CLOSURE.md` | **任务收尾台账**：每次任务的回滚点哈希、改动文件、验收结果 | 长期规则、架构说明 |
| `files/TODO.md` | **待办**：未完成事项，完成即删或打勾 | 已完成项堆积、历史记录 |
| `docs/*.md` | **专题方案**：设计稿说明、技术调研、规范（如本文件） | 变更流水、待办 |

**归档规则**：
- `HANDOFF.md` 超过 100KB 时，把半年以前的变更移到 `docs/archive/HANDOFF-YYYY.md`，主文件保留最近半年 + 索引。
- `docs/task_closure_*.md`（历史遗留 4 份）→ 内容已并入 `CLOSURE.md` 后移到 `docs/archive/`。
- 一次性诊断报告（`reports/`）→ 结论沉淀进文档后删除。

## 五、产出物三级分类（生命周期）

| 级别 | 定义 | 位置 | 生命周期 | 进 Git |
|---|---|---|---|---|
| **L1 交付物** | 用户最终要的文件（封面 PNG、导出文档） | `output/` 或用户指定目录 | 长期（用户决定） | ❌ |
| **L2 运行时数据** | 配置、账号、草稿、缓存 | `data/` | 持久（用户数据） | ❌ |
| **L3 可再生缓存** | 测试截图、临时渲染、审计输出、构建产物 | `test_output/` `temp_covers/` `uploads/` `pwa/dist/` `output/`（旧批次） | **会话级**，任务结束可删 | ❌ |

**清理触发时机**：
- 每次任务收尾：清 `test_output/` 与 `temp_covers/`
- `output/` 超过 500MB 或超过 30 天：只留最近 7 天
- `docs/` 里出现图片/原型：立即移到 `docs/assets/` 或 `docs/prototypes/`

## 六、Git 约定

**分支模型**

| 分支 | 用途 | 说明 |
|---|---|---|
| `main` | 唯一分支：PWA（`pwa/`）+ 共享引擎（`core/`）+ 本地版 | 稳定分支，随时可跑；部署即推 `main` |

> 历史：PWA 曾在独立 `pwa` 分支开发，2026-10 已合并回 `main` 并删除该分支——**现在只有 main**，
> 不要再建 / 切 `pwa` 分支（2026-10-24 审计订正）。

**提交信息格式**

```
type(scope): 中文摘要（不超过 50 字）

- 具体改动 1
- 具体改动 2
```

`type` 取值：`feat` / `fix` / `docs` / `chore` / `test` / `refactor` / `perf`。

**提交纪律**
1. 一次提交只做一件事（改代码 or 写文档，不混）
2. 提交前跑对应测试（改前端 → 有头；改引擎 → E2E；改文档 → 不用）
3. **提交信息里不要用反引号包路径**（会触发 shell 命令替换，已踩过两次坑）
4. 不提交：`.env`、`data/`、`output/`、`test_output/`、`pwa/dist/`、`node_modules/`

## 八、"干净"的验收清单（每次任务收尾逐条对）

- [ ] 根目录没有新增临时文件（脚本/截图/log 都在对应目录）
- [ ] `docs/` 根下只有 `.md`（图片在 `docs/assets/`，原型在 `docs/prototypes/`）
- [ ] 新写的文档能回答"它归 §4 的哪一类"
- [ ] 生成物都在 L3 目录且已 gitignore
- [ ] 废弃文件已删（不留 `_old` / `_backup` / `副本`）
- [ ] 提交信息符合 §6 格式，且不含反引号
- [ ] 对应测试已跑（前端改动 → 有头；引擎改动 → E2E）
- [ ] 文档同步：HANDOFF 一条变更 + CLOSURE 一条收尾 + TODO 勾掉/删除
- [ ] `output/` 与 `test_output/` 没有本轮遗留的大文件
- [ ] 代码文件里没有调试用的 `print` / `console.log` 残留（除非有意保留）

## 九、附：常见错误（本项目已踩过）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用 `bash -c "python -c '...'"` 写含反引号的长文本 | 反引号被 shell 执行，生成垃圾文件 / 文档被污染 | 用 Write 工具写脚本文件再执行 |
| 测试产物留在根目录 | 仓库变脏、误提交 | 一律 `test_output/` |
| 任务收尾单独建 `task_closure_xxx.md` | 记录四分五裂 | 并入 `CLOSURE.md` |
| 生成物手改 | 下次重跑被覆盖 | 改生成器（`scripts/`）再重跑 |
| 文档里写"最新版/final" | 无法判断有效性 | 用日期 + 版本号 |
