## 第一部分 · 版式命名

### 1.1 现有命名体系（必须先对齐）

项目已有一套 2 字中国风族名，`scripts/theme_specs.py` 的 `_FAMILIES`：

| 族 id | 名字 | 它的视觉气质 |
|---|---|---|
| `stamp` | 钢印 | 墨黑粗边 + 右下硬投影，像刚盖下的钢印 |
| `minimal` | 素页 | 大片留白、发丝线、唯一标记 |
| `biz` | 公文 | 小圆角 + 深色标题块 |
| `letter` | 信笺 | 大圆角 + 纸感底色 + 舒展行距 |
| `night` | 夜航 | 暗底 + 冷光面板 |
| `feast` | 节庆 | 大圆角 + 虚线 + 胶囊标题 |
| `dusk` | 暮色 | 暗底 + 暖金 |

**新命名必须落在同一个语感里**：2 字、有意象、不卖弄、看字面能猜到气质。

### 1.2 逐版式的视觉事实（取自 `core/magazine_layouts.py` 真实配方）

| id | 配方要点（原文摘录） |
|---|---|
| `time` | 红色只做细框线；**重点结论外面加一圈细红框**；栏目名置顶 → 主标题居中 → 短导语 → 多留白 |
| `guardian` | 大标题上方压一行 14px 红字（**眉题**）；h2 前 10px 红方块；**引用放大到 19px** + 44px 引号 |
| `economist` | 红色 **「01」「02」序号** + 浅灰细线；**重点句 22px 加粗** + 左侧红线 |
| `natgeo` | 黄色编号 22px；**左 4px 粗线 + 右 1px 细线**；**分隔线只画 52px**；引用浅灰底 |
| `vogue` | 整篇**只有黑白**；大标题 **34px 宋体**；**52px 斜体数字**；重点不上色只垫细线 |
| `forbes` | **数字就是主视觉**（28–32px）；黑白灰 + 一点深蓝 |
| `adidas` | 黑白高对比；**三条纹**；斜向动势 |

### 1.3 命名方案

| id | 建议名 | 为什么 | 备选 |
|---|---|---|---|
| `time` | **朱线** | 整套的识别点就是「红细线 + 重点加红框」，朱=红、线=框线 | 框线 / 红框 |
| `guardian` | **眉批** | 「眉题」是中国报刊的老词（天头处的小字）；「眉批」更通俗，也点出「引用放大」的批注感 | 天头 / 眉题 |
| `economist` | **编号** | 最鲜明的就是 01/02 红色序号 + 细线 | 序目 / 条陈 |
| `natgeo` | **竖栏** | 左 4px 粗 + 右 1px 细，形成一道竖向栏线；短分隔线像栏口 | 双线 / 栏口 |
| `vogue` | **素墨** | 整篇只有黑白，34px 宋体厚重，是「纯墨无色」的表达 | 墨本 / 玄素 |
| `forbes` | **数榜** | 数字即主视觉，直白 | 数列 / 数据 |
| `adidas` | **三道** | 三条纹是唯一识别符；「三道」在中文里也有「三道工序」的稳重感 | 三线 / 横条 |

**连贯性自检**：朱线 / 眉批 / 编号 / 竖栏 / 素墨 / 数榜 / 三道 —— 都是 2 字、都是名词、都不带品牌、都能从字面猜到大概长相。

### 1.4 需要你拍板

上表是**我的推荐**。三个最容易有分歧的点：

1. **`vogue` → 素墨**：「素墨」偏文人气，「玄素」更古雅，「黑白」最直白但没味道。
2. **`forbes` → 数榜**：「数榜」略生造；如果嫌生硬，可退回「数字」。
3. **`adidas` → 三道**：如果觉得太抽象，可用「三条」或「横条」。

> ⚠️ **命名会影响 `docs/` 与测试断言**：`scripts/pwa_theme_drawer_test.py` 里有版式名断言，
> 改名要同步。但**引擎 id 不变**（`time` / `guardian`…），所以主题 JSON 与后端零影响。

## 第二部分 · 入口可发现性（真问题）

### 2.1 先说清「看不见」有多严重（实测数字）

现在的色卡条（`.style-bar`）：

- 高度 60px，右侧硬留 128px 给悬浮更新按钮，`padding-right: 128px`
- 每个 `.cap` 平均宽 **约 92px**（18px 徽标 + 7px gap + 2~4 字名 + 左右 20px padding）
- **`renderCaps()` 里 `slice(0, 40)` —— 最多渲染 40 个**

物理容量实测：

| 视口宽 | 色卡条能放下 | 占 179 套的比例 |
|---|---|---|
| 1920 | **16 个** | 8.9% |
| 1440 | **12 个** | 6.7% |
| 1024 | **7 个** | 3.9% |
| 768（平板） | **5 个** | 2.8% |

**结论：用户首屏能看到的风格不到 7%。** 而且：
- 色卡条**没有滚动条**（`scrollbar-width: none`），用户**不知道右边还有**
- 唯一的提示是末端一个「全部风格」按钮 —— 但它长得像个**次要按钮**（白底描边），不像入口
- 版式（15 个）**完全不在这条里**，只在抽屉第 2 段

这不是「有点难找」，这是**主功能被藏起来了**。

### 2.2 三个 UX 方案（都做，但要分优先级）

---

#### 方案 一：色卡条加「还有更多」的可见信号（成本最低）

**现状问题**：色卡条是 `overflow-x:auto` + `scrollbar-width:none`，滚动条被隐藏了，
用户没有任何「右边还有」的线索。

**改法**：

1. **右端渐隐遮罩**（`mask-image: linear-gradient(to right, #000 85%, transparent)`）——
   最后一张卡自然淡出，视觉上就是「还有」的强信号
2. **左右滚动箭头**（`.style-scroll` 已存在但只在部分宽度显示）—— 改成始终显示，并在滚到头时置灰
3. **「全部风格」按钮改成主行动**：从白底描边 → 深色实底（`background: var(--text); color:#fff`），
   并在按钮上带数字：**`全部 179 套 ›`**
4. **首屏展示「精选 12 + 最近 4」**：不是随机 12 个，而是 curation 里的 `featured` 12 套 +
   用户最近用过 4 套。现在的 `orderedThemes()` 已经是「收藏 / 最近优先」，但**上限 40 掩盖了这个问题**

> 这一条几乎零风险，只动 CSS + 一个按钮样式 + 数字。**建议立刻做。**

---

#### 方案 二：占位式「风格预览墙」（中等成本，效果最大）

**核心洞察**：用户「看不到全部」，本质不是**空间不够**，是**没有「去逛」的动机**。

现在色卡条是一排**抽象色点**（18px 圆），用户看不出「这套主题排出来长什么样」。
而抽屉里的卡片有缩略图 —— 但抽屉要先点开。

**改法**：把**空态**（`#preview-empty`）改成「风格预览墙」：

```
┌─ 预览（空态）──────────────────────────────┐
│                                            │
│   左边写点什么，排版会实时出现在这里       │
│   [ 看示例 ]                               │
│                                            │
│   ── 或者先看看这 6 套长什么样 ──          │
│   ┌────┐ ┌────┐ ┌────┐                    │
│   │缩略│ │缩略│ │缩略│   ← 用用户自己的   │
│   │ 图 │ │ 图 │ │ 图 │      文案实时渲染 │
│   └────┘ └────┘ └────┘                    │
│   公文·湖蓝  信笺·竹青  素页·墨黑           │
│   ┌────┐ ┌────┐ ┌────┐                    │
│   └────┘ └────┘ └────┘                    │
│   夜航·藏蓝  钢印·朱砂  节庆·柿橙           │
│                                            │
│         [ 看全部 179 套 → ]                │
└────────────────────────────────────────────┘
```

**为什么这招有效**：

1. **空态是最容易被浪费的黄金位置** —— 现在那里只有两行字 + 一个按钮
2. **用用户自己的文案渲染缩略图**（项目里封面模块已经是这个做法，
   `docs/design-xhs-studio-final.md` 有记录：示例成品墙改成实时渲染后决策效率明显提升）
3. **6 张缩略图 = 6 次「这套不错」的机会**，比 12 个色点强得多
4. 点任意一张 → **直接应用该主题**，不需要进抽屉

> 这一条改动集中在 `showEmpty()` 与 `#preview-empty` 的 DOM，**不碰抽屉**。
> 但它需要「用当前文案渲染 6 套主题缩略图」的能力 —— 引擎已支持（`doRender` 可复用），
> 只是要**离屏渲染 6 次**，性能需实测（预估每次 50–80ms，6 次约 400ms，可接受）。

---

#### 方案 三：版式从抽屉里「分半步」出来（成本较高，但解决结构问题）

**核心洞察**：方案 B 把版式放在抽屉第 2 段，用户**必须开抽屉**才能换版式。
但版式是**和主题同级**的决策 —— 选完「长什么样」自然要问「怎么排」。

**改法**（这是对方案 B 的**温和修订**，不是推翻）：

在色卡条上方，加一条**极窄的版式二级条**（36px 高），默认收起成一行文字：

```
┌─────────────────────────────────────────────────────┐
│ 版式：默认  ▾                    公文·湖蓝 · 179 套 │  ← 36px
├─────────────────────────────────────────────────────┤
│ ● 公文·湖蓝  ● 公文·朱砂  ● 信笺·竹青  …  全部 179 ›│  ← 60px 色卡条
└─────────────────────────────────────────────────────┘
```

点「版式：默认 ▾」→ **向上弹出**一个横向面板（不遮挡预览），列出 15 个版式分组：

```
│ 通用    默认 图文节奏 卡片流 目录导航 杂志分栏 首屏 卡片组 时间线 │
│ 报刊风  朱线 眉批 编号 竖栏 素墨 数榜 三道                        │
```

**为什么是「分半步」而不是全提出来**：

- 方案 C（版式条常驻）被否，是因为它**吃掉预览高度**且改主布局
- 这个做法只加 **36px**，且**默认是收起的**，不点不开
- 它让「版式」在**首屏可见**（用户知道有这个东西），点开才展开 —— 符合渐进披露

> 代价：色卡条从 60px 变成 96px（含版式行），预览区少 36px。
> 如果嫌挤，可以让版式行与色卡行**共用一行**（左版式、右主题），但那会牺牲可读性。

### 2.3 三个方案的关系（建议全做，但有顺序）

| 方案 | 解决什么 | 成本 | 风险 | 建议顺序 |
|---|---|---|---|---|
| **一** 色卡条信号 | 「不知道右边还有」 | 极低（CSS + 文案） | 无 | **第 1 步** |
| **二** 空态预览墙 | 「没有去逛的动机」 | 中（离屏渲染 6 次） | 低 | **第 2 步** |
| **三** 版式分半步 | 「版式必须在抽屉里」 | 中高（新交互） | 中 | **第 3 步，需先看原型** |

**我的判断**：方案一必须做（它修的是一个明显的可用性缺陷）。
方案二**是三个里性价比最高的** —— 它把「看不见」变成「一次看到 6 个，而且是自己文案的效果」。
方案三可以缓，因为方案二做完之后，用户已经能通过空态墙 + 抽屉找到东西了。

## 2.4 一个被忽略的问题：色卡条 `slice(0, 40)` 本身

即使色卡条能滚，`renderCaps()` 里写死了 `slice(0, 40)` —— 收藏了 50 套也只渲染 40 个。
这是**双重截断**：先截 40，再被容器宽度截到 12。

**改法**：
- 去掉 `slice(0, 40)`，改成**虚拟滚动**或**只渲染可视区 + 缓冲区**
- 或者简单点：`slice(0, 60)` 并**在末尾显示「+119 未显示，点全部风格」**

后者更简单，且**明确告知**，符合项目「不静默」的设计铁律。
