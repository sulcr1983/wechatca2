# 三模块需求梳理（2026-11-02）

> **本文是什么**：把「公众号排版 / 小红书标题图 / 小红书长图文」三个板块的**现有能力、真实缺口、需求优先级**摆到一张表上，供拍板与排期。
> **不是什么**：不是施工图（细则见各 `design-*.md`），不是进度汇报（数字见 `STATE.md`）。
>
> 数据来源：全部为 2026-11-02 对当前源码的实测，非文档转抄。

---

## 0. 一句话看清三个板块

| 板块 | 一句话 | 输入 | 输出 | 成功标准 |
|---|---|---|---|---|
| **公众号排版** | 粘贴纯文本 → 选主题 → 复制进公众号后台 | 一篇文章（任意长度） | 一段可直接粘贴的富文本 HTML | 粘过去样式不丢、手机上看不丑 |
| **小红书标题图** | 一句话 → 出 1080×1440 封面 | 一句话（首行标题，第二行小字） | 1 张 PNG（+ 可切九宫格） | 打开 10 秒内出图、不用改文案也能看 |
| **小红书长图文** | 贴整篇 → 自动分页 → 成套导出 | 一整篇文章 | N 张 PNG（页数自动） | 分页不断句、每页不空、一次打包 |

**三者共用的只有代码，不共用产品面**（`docs/design-module-split-ia.md`）：搜图、渲染管线、配色目录、可读性分析是同一份实现，但输入框、状态、结果区、存储键全部各自独立。

## 1. 公众号排版

### 1.1 现有能力（实测）

| 维度 | 现状 | 数量 |
|---|---|---|
| 主题（配色） | `public/themes/*.json`，模板库抽屉可选 | **179 套** |
| 其中「整篇设计」kit | 带 `kind:"kit"` + `locked_layout`（锁定配色+版式） | 15 套 |
| 可自由组合的版式 | `LAYOUT_OPTIONS`（抽屉底部胶囊条） | **8 项** |
| 引擎能跑的版式 | `LAYOUT_REGISTRY` | **19 个** |
| 段落样式 | 金句 / 数据 / 提示（按内容自动识别） | 3 种 |
| 输出 | 复制富文本 / 长图 PNG / HTML / Markdown / 图片 ZIP | 5 种 |
| 输入增强 | 图片粘贴、上传、搜图（Pexels BYOK）、AI 生成关键词 | 4 项 |

### 1.2 真实缺口

**P-1（唯一的功能性缺口，优先级最高）**

引擎 19 个版式，UI 只有 8 项入口。差的 11 个里：
- `hero` / `card` / `timeline` 走 if-else 分支，**不在** `LAYOUT_REGISTRY`；
- `time` / `guardian` / `economist` / `natgeo` / `vogue` / `forbes` / `adidas` / `muji` / `mori` / `ukiyoe` / `note` / `ikea` / `starbucks` / `brutal` / `deepread` 共 15 个在注册表里，**但没有任何 UI 入口**。

后果：用户想「用《时代》的版式 + 我自己的蓝色」做不到，只能选 `mg-time` 整套（配色也被锁死）。

**判据（已定，可 grep、可进 CI）**：函数里**写死品牌色**的 8 个（muji / mori / ukiyoe / note / ikea / starbucks / brutal / deepread）**不进**版式段 —— 它们换任何配色都会毁；纯 accent 派生的 7 个（time / guardian / economist / natgeo / vogue / forbes / adidas）**进**。

补完后：8 + 7 + 3（hero/card/timeline 已在 UI）= **18 项**。

**P-2 部署落后**
线上 b358（11-01），本地 b379（11-02）。15 套 kit 线上 **0 套**（实测线上 `themes/index.json` = 164 套、kit 0）。这不是需求，是发版动作。

**P-3（待拍板）**
- 移动端 `audit_mobile_typography.py` 已有，但没进默认门禁；
- AI 排版（结构决策 JSON）已上线，但入口藏在 `btn-ai-format-row`，可发现性低。

## 2. 小红书标题图

### 2.1 现有能力（实测）

| 维度 | 现状 | 数量 |
|---|---|---|
| 尺寸 | `COVER_SIZES`：3:4 小红书（1080×1440）/ 1:1 方图 / 21:9 横版 | 3 种 |
| 风格（版式） | `ALL_STYLES` = 产品原有 7 + 归藏 2 | **9 套** |
| 配色 | 每套版式自带推荐色，可切换 | 见 §2.2 |
| 字体 | `FONTS`（跟随 / 黑体 / 宋体 / 得意黑 / 文楷 / 快乐体 / 小薇 / 马善政 / 龙藏 / 志莽） | 10 款 |
| 文字玩法 | `TEXT_MODES`（默认 / 大字压阵 / 竖排 / 错位） | 4 种 |
| 配图 | 搜图（Pexels BYOK）/ 传一张 / 不要图 | 3 条路 |
| 底图可读性 | `analyze.js` 算墨迹覆盖率 + 对比度，给「能不能存」判定 | 1 套 |
| 产物 | 单张 PNG + 九宫格切图（3×3）+ 复制 + 保存 | 3 种 |
| 存储 | `supersu.cover.prefs.v1`（style/size/mode/font/textMode/layoutPick/textPos/frosted/author） | 1 键 |

### 2.2 需要澄清的一点（重要）

「12 风格」是**旧口径且已过期**。实测只有 **9 套版式**（`ALL_STYLES`）：
`image-led / magazine / quote / bigtype / list / number / swiss`（产品原有 7）+ `magazine-tpl / swiss-tpl`（归藏 2）。

`public/cover-templates/` 下是 **10 套归藏模板**，实为 **2 个版式 × 5 种配色**：
- `editorial-*`：dune / forest-ink / indigo-porcelain / ink-classic / kraft-paper
- `swiss-*`：ikb / lemon-green / lemon-yellow / safety-orange

也就是说 **「12 风格」= 9 版式 + 3 个（10 模板里已并入 2 主卡的重复项）**，这个数字既不是版式数也不是模板数，是一句自相矛盾的宣传话。**建议统一口径为「9 种版式 × 各自推荐配色」**。

**原型（`docs/prototypes/v2/`）已设计成 26 套版式 + 20 套配色 + 10 字体**，但**只在原型**，`pwa/src` 一行未改（HANDOFF §0 明确标注）。

### 2.3 真实缺口

| # | 缺口 | 证据 | 优先级 |
|---|---|---|---|
| **T-1** | 原型 V2 的 UX 重做（三栏 236/684/520、版式 5 列、配色 20 套三族、色块黑白择优）**未落地** | `HANDOFF.md` §8.2 八步清单，`pwa/src` 零改动 | P0（用户抱怨最直接） |

## 3. 小红书长图文

> 📌 **2026-11-03 更新：本模块的完整需求台账已独立成 `docs/requirements-xhs-longform.md`**
> （需求真源 + 源码核对 + 缺口 + 待拍板项）。下面保留本节的板块级速览，
> **以新文档为准**；两处冲突时按新文档。
> 本次修正了 3 条过期结论（L-2 / L-3 / L-4），依据是 `python scripts/pwa_longform_test.py` **24/24 通过**。

### 3.1 现有能力（实测）

| 维度 | 现状 | 数量 |
|---|---|---|
| 模板 | `LONG_TPLS`：editorial / swiss / notion / book / memo / polaroid / aura / night / doc / film / starry / blank | **12 套** |
| 配色 | `PALETTES`：dune / forest / indigo / kraft / midnight / ikb / lemon / orange | **8 套** |
| 分页 | `buildLong()` 实际产出 **6 类页型**：封面 / 开篇 / 清单 / 金句 / 正文 / 结尾（`ROLES` 里还有「步骤」，但 buildLong 从不产出 steps 页，见下注） | 6 类 |
| 版式选项 | 显示页码 / 签名 / 内页背景图 | 3 项 |
| 产物 | 成套 PNG + 打包 ZIP + 逐张下载 | 3 种 |
| 输入 | 整篇文章（首行 = 封面标题）；「用正文」从排版页导入 | — |
| 存储 | `supersu.longform.prefs.v1`（longTpl/palKey/longPn/longSign/longBg） | 1 键 |

> ⚠️ **`steps` 角色是死代码（2026-11-03 实测）**：`cards.js: ROLES` 定义了「步骤」，`cardInner` 里有
> `else if (role === 'steps')` 渲染分支、CSS 也有 `.r-steps`，但 **`buildLong()` 里没有任何
> `role: 'steps'` 的 push**（只产 opening/points/quote/dense/closing）。原文里「第 X 步」/「①」
> 这类行会被 `parseBlocks` 标成 `type:'step'`，然后落进 dense 页按普通正文渲染。
> 详见 `requirements-xhs-longform.md` §8 S-9。

### 3.2 真实缺口

| # | 缺口 | 证据 | 优先级 |
|---|---|---|---|
| **L-1** | 12 套模板**一屏看不全**（960 高下右栏要滚） | 右栏 `cover.css:171` 为 `repeat(2,1fr)`、宽 ≤520px，12 套 × 2 列仍堆高超出；模板缩略图是**纯文字卡**不是真实渲染 | P1 |
| ~~L-2~~ | ~~配色 8 套里部分**不达 AA**~~ → **已失效，结论有误** | 2026-11-03 复算：正文 ink 12.81–18.07、次要 muted 4.61–6.22、强调 at 5.59–10.23，**8/8 全部达 AA 4.5:1**。原证据（`HANDOFF.md` §8.1 第 4 条）不可复现 | — |
| ~~L-3~~ | ~~分页口径与「填充分档」未对齐~~ → **已对齐** | `cards.js: packDense` 走 DOM 实测高度装箱 + 四个实测常量；`pwa_longform_test.py` 已按角色分档断言（dense 90.7% / points 95.7% / closing 87.4% / opening 110.5% / quote 92.1%），**24/24 通过** | — |
| ~~L-4~~ | ~~内页背景图**原型未做**~~ → **已落地** | `#cv-longbg-pick/cover/clear` 全在；6 套模板可用、6 套禁用并给提示；铺图 + 纸色 85% 蒙层；封面不受影响；门禁有断言 | — |
| **L-5** | 「撤销上一版」没做（切了 15 次想退回） | 长文模块 `grep undo/撤销` **0 命中**；原型也没有 | P2 |
| **L-6** | `steps`（步骤页）是**死代码**：`ROLES` 定义了、`cardInner` 有分支、CSS 有 `.r-steps`，但 `buildLong()` 从不产出 steps 页 | `cards.js` 里只有 opening/points/quote/dense/closing 五处 push。原文的「第 X 步」行会落进 dense 按普通正文渲染 | P2 |

**明确不做（已拍板）**：长图文配色**不并入**标题图的 20 套。两者来源不同（`cards.js: PALETTES` vs `catalog.js`），合并会让色卡大面积回落。
