左边写、中间看、右边试

两个模块共用同一套三栏骨架：高频切换全部常驻（版式 / 配色 / 字体 / 玩法）， 只把低频且需要大空间的动作收进弹层（搜图 / 编辑全文 / 出片）。 标题图 26 套版式、长图文 6 套模板，每一套都能在 catalog.js 或 references/layout-recipes.md 里找到出处。

三条不能动的结构决定

结构
三栏常驻，不是弹窗

版式 / 配色 / 字体是最高频的切换（选完图会连试 5–10 次）。 把它们收进弹层 = 每次多两次点击。弹层只装搜图、编辑全文、出片。

缩略图
用你自己的文案和配色渲染

现版本右栏是预渲染的 cover-thumbs/*.png， 用户看到的是别人的图。改成实时渲染后，26 张全是「你这句话」的样子； 每张还用自己的默认色板，一眼能分出哪套是什么气质。

保存
出片 → 托盘 → 下载

旧代码 generate() 生成后直接 want.click() 落盘， 用户不知道存到哪、存了几张。现在是两段式，托盘写明张数和尺寸。

每张版式的 pals[0] 就是它的默认色 —— 也决定缩略图第一眼什么颜色。 默认全部换掉了纸黄系，避免 26 张缩略图摆一起像一堵土墙。

这一轮修掉的 8 个真 bug

#现象根因
1缩略图一片米黄调 coverHtml() 时没切 state.pal，26 张全用全局当前色板渲染
2换版式后配色行不更新版式点击处理里漏了 renderPals()
3清单页顶上印「封面 · Cover」kicker 文案写死在函数里，没随版式变
4配色行两个「柠檬黄」lemon（#C5E803）和 lemon2（#FFD500）重名，前者应为柠檬绿
5卡片置灰样式失效卡片从 button 改成 div 后没有 disabled 属性，选择器要改 [aria-disabled]
6纯文字版式上压着一张照片配方渲染没判断 needImg，一律铺图
7大问句断成 6+1 行按 6 字硬切；改成按行数均分（7 字 → 4+3）
8长文模板 6 张长得一样，字还特别大模板缩略图没切色板；正文 font-size 没乘 S

还差什么（落地清单）
