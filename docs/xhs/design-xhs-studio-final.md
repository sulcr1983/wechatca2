# 小红书标题图 / 长图文 · 设计方案 V2

> **状态**：V2 已出原型，待落地（`pwa/src/` 仍零改动）
> **V1 的对抗性复核见 `review-xhs-studio-adversarial.md`**（含全部实测数据与复现命令）
> **本文所有数值都是 1440×900 下的实测值，不是估算**
> **原型**：`prototypes/v2/title.html` / `prototypes/v2/longform.html` / 入口 `prototypes/v2/index.html`

---

## 1. 一句话方案

**左写、中看、右换**：左栏只放「输入与素材」，中栏只放「画布」，右栏只放「版式与它的配色」。
三栏全部常驻、都不弹窗 —— 但**常驻不等于可见**，所以每一栏都有一条明确的「一屏能看到多少」的下限。

V2 相对 V1 的核心改动只有一句：**把宽度从「用不上的中栏」挪给「挤爆了的右栏」**。

| | V1 | V2 |
|---|---|---|
| 左 / 中 / 右 | 224 / 856 / 360 | 236 / 684 / 520 |
| 画布 | 591×788 | 567×756 |
| 中栏横向浪费 | **237px**（画布被高度约束，加宽没用） | 58px |
| 版式同屏可见 | 10 / 16 套（第 4 行切一半） | **16 / 16 套**（不滚） |

## 2. 为什么还是三栏（而不是全弹窗 / 抽屉）

用户原话：「你这个设计又极简过头了。啥都弹窗了……因为要常常切换的」。

三栏成立的真正理由是**切换频率**：一条文案从写完到定稿，平均要换 8–15 次版式。
任何「点开—选—关掉」的动作乘以 15 都是灾难。所以版式、配色、字体必须**同时可见且可直接点**。

但这句理由有个 V1 漏掉的推论：**可见 = 真的看得见，不是「存在于 DOM 里」**。
V1 的 26 套里有 16 套在折叠线以下，等于弹窗只是换成了滚动 —— 用户感受不到区别。

V2 因此新增一条硬约束：

> **高频切换的东西，一屏至少要露出 3 行 / 12 个。**
> 做不到就必须压缩它的表现（换密度、换分组），而不是让它滚。

## 3. 界面结构（1440×900 实测）

```
┌──────────────────────────────────────────────────────────────┐
│ 44  品牌 │ 标题图 · 长图文 │             纯前端生成 · [保存大图]│
├──────────┬────────────────────────────┬──────────────────────┤
│ 236      │  画布 567×756（居中）       │ 520                  │
│          │                            │ 版式 5 列 × 94px     │
│ 文案      │                            │ 16 套一屏全见         │
│ 配图      │                            │                      │
│ 底图可读性 │                            ├──────────────────────┤
│ 尺寸      │                            │ 配色 / 字体           │
│ 署名      │                            │ 玩法 / 位置           │
│ 小贴士    ├────────────────────────────┤                      │
│          │ 1080×1440 · 轻压暗 4.5:1    │                      │
│          │ 复制  九宫格  [保存大图]     │                      │
└──────────┴────────────────────────────┴──────────────────────┘
```

| 区域 | 尺寸 | 为什么是这个数 |
|---|---|---|
| 顶栏 | 44 | 只放模块切换和保存，不放任何设置 |
| 左栏 | 236 | 文案 + 配图 + 可读性 + 尺寸 + 署名，五块刚好 |
| 中栏 | 684（flex，最小 420） | **画布是被高度约束的**，684 已是 567 画布 + 两侧各 58 的舒适上限，再宽就是纯浪费 |
| 右栏 | 520 | 5 列 × 94px 是「一屏露出 16 套」的最小宽度 |
| 动作条 | 56 | 复制 / 九宫格 / 保存大图，宽度跟随画布，**视线不离开预览** |

### 3.1 断点

| 视口 | 行为 |
|---|---|
| ≥ 1281 | 236 / flex / 520，版式 5 列 |
| 981 – 1280 | 214 / flex / 428，版式 4 列，版式区允许滚动 |
| ≤ 980 | 单栏 + 底部页签（文案 / 画布 / 样式），左右栏变抽屉 |

> V1 没有断点：768×1024 下画布 156×240、动作条 360px 溢出到右栏；更窄时画布宽度归零。
> 产品是 PWA，手机是主场景，这条不能没有。

## 4. 左栏：输入与素材

### 4.1 文案
- 上限 500 字，实时计数；`min-height 88 / max-height 190`，超出自身滚动（**不撑高命令区**）。
- 第一行 = 大标题，回车后的行 = 小字。这条规则必须写在 placeholder 里，不能靠猜。
- 动作：`用正文`（落地读 `supersu.article`）/ `示例` / `清空`。

### 4.2 配图：三态，且**任意一态都不需要 API**
```
[搜图] [传一张] [不要图]      ← 三个平级按钮，不是弹窗入口
```
- **搜图**：Pexels Key（免费申请）→ 弹层搜真实图库；没 Key 时给「先用示例图库（本地 8 张）」的降级，并明确写「传自己的图不需要 Key」。
- **传一张**：本地文件，`FileReader` 直接读。
- **不要图**：纯文字模式，不铺任何底图。
- 当前图：60×80 缩略 + 名字 + 来源 + `换一张 / 去掉`。
- 最近用过：最多 8 张，一排 4 个，点即换。

### 4.3 底图可读性（V1 藏起来了，V2 提上来）
画布下方有一条判定，左栏还有一块明细：
```
轻压暗 4.5:1  ▓▓▓▓▓▓░░░
已加 9% 暗角保证可读。想更干净就换一张更暗的图。
```
这是这套产品真正区别于「随便一个封面工具」的地方 —— **它知道你的字压在图上清不清楚**。
V1 把它塞进 10.5px 的信息条里，等于没有。

### 4.4 尺寸 / 署名
从右栏搬过来。理由：尺寸是**输出属性**，署名是**内容属性**，都不属于「版式」。
搬走后右栏腾出 3 行高度给版式区 —— 这是 V2 能一屏露出 16 套的直接原因之一。

### 4.5 小贴士
左栏内容天然比右栏短。空着的 300px 不放装饰，放三条「第一次用一定会卡住」的说明：
第一行是大标题 / 7 个字最容易排 / 清单版式要 2 条以上小字。

## 5. 中栏：画布

- 3:4 画布按可用空间等比缩放，**高度优先吃满**（实测 1440×900 → 567×756，缩放 0.525）。
- 画布正下方 24px 信息条：`1080 × 1440 · 轻压暗 4.5:1 · 大字版`。
- 动作条贴在画布下沿，宽度跟随画布：
  - `复制`：富文本，可直接粘进公众号
  - `九宫格`：切成 3×3
  - `保存大图`：先「定影」（闪一下）+ 出片托盘写明尺寸/体积，**用户自己点下载**，不无声落盘

> V1 的中栏宽 856 但画布只有 591 —— 因为 3:4 且高度受限，加宽中栏对画布毫无帮助。
> V2 把这 237px 让给右栏，画布只小 24px，版式区多出 44% 面积。

## 6. 右栏：版式（这一版的重心）

### 6.1 版式清单：26 套，编号可验证

| 来源 | 数量 | 编号 | 说明 |
|---|---|---|---|
| 产品现有 | 7 | M16 / M01 / M04 / M05 / S01 / — / — | **永远排最前**；「大字版」「编号大字」是产品原有、没有配方出处，标 `—` |
| 配方 · 图文 | 8 | M02 M03 M06 M09 M10 M11 S08 S12 | 来自 `references/layout-recipes.md` |
| 配方 · 纯文字 | 11 | M07 M08 M12 M13 M14 M15 S02 S03 S05 S07 S09 | 同上 |

编号唯一性：V1 里 `S09` 被「编号大字」和「数字塔」同时用了，V2 已修正。

### 6.2 呈现：密度两档 + 一屏下限

| 密度 | 列 × 卡宽 | 一屏可见（16 套） | 用途 |
|---|---|---|---|
| 紧凑（默认） | 5 × 94px | **16 套全见，不滚** | 日常快速切换 |
| 舒适 | 4 × 117px | 12 套 | 需要看细节、比较排版 |

- 版式区是右栏**唯一**的滚动容器（V1 是「版式区自己滚 + 右栏也滚」，两层嵌套）。
- 「另有 8 套要图 →」做成**头部 pill**，不进列表。
  （V1 把它放在列表底部占 42px，正好把最后一行卡顶出可视区，实测差 27px。）
- 头部还有「全部 ↗」：全屏总览 6 列 × 190px，一屏 18 套 —— 解决「26 套想看全」。

### 6.3 卡片规格

```
┌─────────────┐
│[图]      M04│  ← 左上：图/文角标（只有「图」才显示）  右上：配方编号
│   缩略图     │     按 300×400 渲染再 CSS scale 到卡宽
│          ✓  │  ← 选中：2px 主色描边 + 左下角勾
├─────────────┤
│ 金句         │  ← 名字独立一行，11px，超长省略 + tooltip
└─────────────┘
     行距 12px，名字距图 3px
```

**V1 的错**：编号右对齐、紧贴下一张卡的名字，`金句 M04 大字版` 读起来像一张卡叫「金句M04大字版」。
V2 把编号挪进缩略图右上角，名字与图 3px、行与行 12px —— 名字只可能属于上方那张。

### 6.4 可见性规则（**唯一入口**）

```js
// 原型里就是这一个函数，所有路径都走它
layVisible(l, hasPic) = !l.needImg || hasPic
```

- **有图**（上传 / 搜到 / 示例库）→ 现有 7 → 图文 8 → 纯文字 11，共 26 套
- **无图** → 现有 7 里去掉要图的 2 套 + 纯文字 11 = **16 套**；
  头部留一个 pill「另有 8 套要图 →」，点它去**选图**（不是去配 Key）

> ⚠️ **这是对原需求的一处修订，需要确认。**
> 原话是「没有登陆图的 api 就只显示纯文字版式」。按字面实现会有一个死结（已复现）：
> 用户上传了自己的照片 —— 完全不需要 API —— 图文版式依然 0 套可见，
> 还挂着「配个免费 Key 就出现」。**Key 只该决定「能不能搜」，不该决定「能不能用」。**

### 6.5 置灰规则
不满足前提的版式**置灰但保留**，并说明原因：
- 图文版式但当前无图 → 「这套要一张底图，先选张图」（点击直接开选图）
- 清单版式但小字不足 2 条 → 「清单要 2 条以上小字」

## 7. 配色：20 套，三族，全部过 WCAG

### 7.1 为什么 V1 的「多巴胺」没解决问题

V1 的 10 套多巴胺只改了 `accent`，`paper` 一律是 `#FFF1F4` 这一档近白。
缩略图 94px 时**纸色占 90% 面积**，所以「一片淡黄」变成了「一片淡粉」——
用户抱怨的是「不好看」，本质是**画面没有色彩重量**，不是强调色不够艳。

### 7.2 V2 的分族

| 族 | 数量 | 特征 | 例子 |
|---|---|---|---|
| 纸感 | 9 | 纸色浅、靠强调色出彩 | 沙丘暖纸 / 森林墨绿 / 克莱因蓝 |
| **浓郁** | 6 | **纸色本身就是饱和色** | 黄油 `#FFE066` / 青柠 `#C6F432` / 珊瑚 `#FF8A75` / 天蓝 `#8FD0FF` / 薄荷 `#7FE3B4` / 丁香 `#CDB9FF` |
| 暗夜 | 5 | 深底亮字 | 午夜墨金 / 墨夜 / 夜霓青 / 品红夜 / 深海军 |

### 7.3 每套版式必须同时有「纸感 + 暗夜」

V1 把大字版的配色洗成了 4 个暖色（番茄红/亮橙/酸性黄/柑橘橙）——
**想做一个安静的封面，在大字版上无路可走**。而真实产品 `catalog.js: LAYOUT_PALETTES`
给版式的是 paper / ink / bold（暖纸 / 墨夜 / 亮橙）。

V2 规则：`pals = [自己的主色, …纸感基座, 暗夜基座, …原推荐]`，去重后 ≥4 个。
实测 26 套全部满足；大字版 = 暖纸 / 经典墨色 / 午夜墨金 / 克莱因蓝。

### 7.4 色块上的字：不是「选黑还是选白」，是「够不够黑」

V1 的 `inkOn()` 是亮度阈值：`lum > 0.42 ? 黑 : 白`。中间调两边都到不了 4.5：

```
mint  #00C48C → 判白 → 2.26:1
ink   #d8a24a → 判白 → 2.29:1
citrus#FF7A00 → 判白 → 2.61:1
```

V2 两件事一起做：
1. `inkOn()` 改成**黑白各算一遍取高的**；
2. `accentText` / `blockInk` **不手填，由脚本反解**：保持色相、只压明度，直到达标。

校验（`scripts/gen_v2_palettes.mjs`）：

| 指标 | 阈值 | 结果 |
|---|---|---|
| 正文 paper/ink | ≥ 7 | 20/20 |
| 强调小字 paper/accentText | ≥ 4.5 | 20/20 |
| 色块 blockBg/blockInk | ≥ 4.5 | 20/20 |
| 次要字 paper/muted | ≥ 4.5 | 20/20 |

## 8. 字体 / 玩法 / 位置

| 行 | 内容 | 形式 |
|---|---|---|
| 字体 | 10 款（跟随/黑体/宋体/得意黑/文楷/快乐体/小薇/马善政/龙藏/志莽），全部 SIL OFL | 30px 高胶囊，**用该字体写自己的名字**，13.5px |
| 玩法 | 7 种（默认/大字/竖排/错位/变色/描边/错开） | 12px 小胶囊，**一行排得下 7 个** |
| 位置 | 自动/上/中/下 + 磨砂 | 同上一行 |

两条从实测来的规矩：
1. **字体胶囊不能小于 13px**：10.5px 时中文书法字体的笔画断成点，看起来像「被裁了一半」。
2. **玩法/位置用 12px**：它们是工具字（UI 字体），小一号能一行排完，省 31px 给版式区。

> 已知取舍：`跟随` 与 `宋体` 同为 Noto Serif SC，字形相同（10 款 9 个字形）。
> 语义不同（一个跟版式走、一个锁死衬线），保留两个胶囊。

## 9. 九宫格：先算，再给下载

V1 的问题不是切片错（切片是对的，第 4/5 格正好是标题被切开的两半），
而是**大字版的内容集中在中间横带，切完 7 张是空纸，界面一句话不说**：

```
逐格墨迹：1, 0, 0, 3428, 2662, 0, 0, 0, 0
```

V2 打开就逐格算**内容覆盖率**（文本用 Range 取真实行盒、色块/图片用元素盒，>2% 算有内容），
不足 3 格就出黄条：

```
这套版式只有 3 / 9 格有内容，其余 6 张会是空白图      [把标题放大铺满]
```

「把标题放大铺满」复用已有能力（`tmode = poster`），不新造「九宫格版式」。
另外保留「换成别的图」——用一张外部图铺 1080×1440 再切。

## 10. 长图文：同一套骨架，换中栏

- 左栏：文章条（标题 / 字数 / 自动分几页）+ 编辑全文 + 分页列表 + 封面配图。
- 中栏：当前页 + 下方胶片条（P01 封面 / 开篇 / 正文 / 金句 / 章节 / 清单 / 收尾）。
- 右栏：**12 套真实长文模板**（`cards.js: CARD_CSS_RAW` 332 行整段搬，不是换配色）+ 配色 + 字号 + 选项 + 署名，**一屏不滚**。

V2 修的两处：
1. 右栏 360 → 520、模板 4 列（12 套正好 3 行）→ `sideScroll 854/854`，署名行底边 885。
2. 配色名不再大面积回落成「沙丘暖纸」（长图文有自己的一套色板，不能硬塞标题图的新表）。

**自动排版**（参考公众号）：先认结构再套版式，不是按段落平均切页。
`##`→章节页、`- `→清单页、`>`→金句页；list/quote 先切出来独占一页，再对剩余正文装箱。
默认 313 字文章 → 7 页。

## 11. 交互约定（V2 定版，共 8 条）

1. **切版式不重排画布**：画布尺寸只由容器决定，与版式无关。
2. **版式列表不过滤，只按「有没有图」重排**：没图时图文版式不渲染，但必须在头部留一行
   「另有 N 套要图 →」，且点它是去**选图**，不是去配 Key。
3. **现有 7 套永远排最前**：用户已经认识的东西，不能因为加了新东西就挪走。
4. **配色独立成行**，不做卡内小色点（94px 卡里的小圆点既看不清也点不准）。
5. **每套版式的配色里必须有纸感和暗夜各一**：不允许出现「这一套只有暖色」。
6. **高频控件一屏至少露出 3 行 / 12 个**：做不到就压缩表现，不让它滚。
7. **导出前必须有一次明确确认**：定影 → 托盘写明尺寸体积 → 用户自己点下载。
8. **窄屏必须有断点**：≤980 走单栏 + 页签，不允许「画布宽度归零」。

> 已删除的 V1 条款：原文「版式列表永远 22 套，不按有没有图过滤」与「没配 Key 只出纯文字版式」
> 互相矛盾（2b vs 2e），且「22」与正文「26」不一致。V2 合并为第 2 条。
