# 对抗性复核：小红书封面工坊 V1 方案与原型

> 复核对象：`docs/xhs/design-xhs-studio-final.md`（766 行）+ `docs/prototypes/xhs/ux-a-three-col.html` / `ux-longform.html`
> 复核方式：**有头 Chrome 多状态截图 + DOM 量取 + 逐格像素统计**，不是读代码猜
> 结论一句话：**方案自己写着「右栏 3 列 3 行是唯一能一屏看全 9 套的解」，但版式已经涨到 26 套，

## 1. P0 · 阻断级（5 条，都会让核心任务失败）

### P0-1 版式选择器的几何还在按「9 套」设计，版式已经是 26 套

**证据（1440×900 实测）**

| 项 | 数值 |
|---|---|
| 右栏宽 / 版式区宽 | 360 / 335 px |
| 列数 / 卡宽 / 缩略图 | 3 列 / 107 px / 107×143 |
| 版式区可视高度 | 524 px（16 套时内容 984 px） |
| 可见行数 | **3.2 行 ≈ 10 张 / 16 套**；配 Key 后 26 套只露 4.5 行，第 5 行被切成半张 |
| 同屏可见比例 | 62%（无 Key）/ 17%（有 Key） |

方案 §6 第 1 条的原话是：

> 「曾想改 2 列把缩略图放到 148px，但那样 **9 套**要滚一屏，违背「高频常驻」。
> 3 列 3 行是唯一能「一屏看全 **9 套** + 缩略图还不小于现在」的解」

这段论证的前提是 9 套。**9 → 16 → 26 之后结论直接反转**：3 列 3 行只能装 9 张，
现在需要 6 行（16 套）到 9 行（26 套）。论证没重做，布局没重算。

**用户三次抱怨的其实是同一件事**
- 「版式为啥只剩下 5 套！」
- 「版式也是非常重要的啊！」
- 「很多原来的风格没加入」

不是「加得不够多」，是**加进去了但看不见**。

### P0-2 「有图」不能解锁「图文版式」——核心链路断在 Key 上

实测（`scripts/snippets/…`）：上传一张自己的图之后

```
start lays=16 mode=color
after upload lays=16 mode=search ST.img=p1
imgLayoutsVisible=0          ← 有图了，图文版式还是 0 套
needKeyBtn=true              ← 还挂着「还有 8 套图文版式 · 配个免费 Key 就出现」
```

用户上传自己的照片**根本不需要任何 API**，却被告知要配 Key 才能用图文版式。
可见性规则绑错了对象：绑在「Key」上，应该绑在「有没有一张图」上。

同一处还有第二个失步：点「更换 Key」清空后

```
after reset lays=26 PEXELS_KEY="" needKeyBtn=false
```

Key 已经没了，26 套还留着，回流按钮也不出现 —— **状态机没有单一入口**。

### P0-3 「点更换 → 版式不回落」是第 6 次同类 bug：改了状态没重渲染

上表已列。前五次记录在案：`state.pal` ×2、`LF.tpl`、`pals[0]`、`LF.size`。
共同点都是「数据表改了，渲染读的还是旧的」。
V1 的写法是散落的裸赋值（`PEXELS_KEY = ''`）+ 手写重渲染清单，漏一个就失步。

### P0-4 九宫格：产物 7/9 张是空白，且没有任何预警

逐格像素统计（截 `h_nine.png`，数每格深色像素）：

```
cell1 darkpx=1     cell2 0     cell3 0
cell4 darkpx=3428  cell5 2662  cell6 0
cell7 0            cell8 0     cell9 0
```

切片本身是对的（第 4、5 格正好是标题被竖切线切开的两半）。
问题是**大字版把内容全放在中间横带**，切成 3×3 之后 7 张是空纸。
界面既不预警，也没有「让内容铺开」的办法 —— 用户点「下载 9 张」会得到 7 张空白。

> 这正是项目记忆里那条：「有反应 ≠ 产物正确」。截图里九宫格弹窗看起来完全正常。

### P0-5 小于 1024px 直接失效，而方案通篇没提窄屏

| 视口 | 画布 | 动作条 | 结果 |
|---|---|---|---|
| 1440×900 | 591×788 | 591 宽 | 正常 |
| 1024×768 | 412×581 | 412 | 勉强 |
| 900×700 | 288×416 | 360（**溢出到右栏**） | 不可用 |
| 768×1024 | 156×240 | 360（**溢出 176px**） | 不可用 |
| 584×（窄） | **0 宽** | — | 画布消失 |

`body{overflow:hidden}` 没有兜底，三栏是 224 + flex + 360 的硬编码。
产品是 PWA，手机是主场景 —— 而 `design-xhs-studio-final.md` 全文 0 次提到 375 / 窄屏 / 断点。

## 2. P1 · 严重（7 条，可用性与方案自洽）

### P1-1 空间分配自相矛盾：左栏空 300px，右栏挤 26 套

- 左栏 224×848，最后一个区块底边在 **545px**，下方 **355px 纯空白**（截图可见）
- 右栏同一屏把 16–26 套塞进 524px 的嵌套滚动区

方案说「中栏画布是唯一的主角」，但没有一条规则回答：**当一个栏没有内容时，它的宽度归谁**。

### P1-2 中栏 237px 横向纯浪费（画布被高度约束，宽度加不进去）

画布 591×788 撑在 856px 宽的栏里 —— 因为 3:4 且高度受限，**加宽中栏一点用都没有**，
左右各留 132px 空白。这 237px 本可以给右栏换 20% 更大的缩略图。

### P1-3 缩略图承担不了「比较」职责，而方案说它就是干这个的

方案 §3.3 原话：「缩略图只画版式本身…… **而比较版式正是这排东西唯一的职责**」。
实测 107×143 下：

- 16 张缩略图**只有 7 种底色**（去重统计），其余全是同一档近白
- 带 Key 时「纪实照片 / 证据墙 / 左右分栏」三张用的是同一张雾天海图，肉眼无法区分

**方案定义了职责，但没定义「多小就不能比较」。** 107px 显然低于这个阈值。

### P1-4 「颜色单调」没被解决：多巴胺只改了强调色，没改画面重量

10 套所谓多巴胺，`paper` 全是 `#FFF1F4` / `#F2F5FF` / `#FAFFD8` 这一档近白，
只有 `accent` 是饱和的。缩略图 107px 时**纸色占 90% 面积** —— 于是：

- 修之前：一片淡黄
- 修之后：一片淡粉

用户的原话是「默认的颜色都是淡黄色，不够好看」。换了色相没换明度/饱和度，等于没修。
真正的「多巴胺」应该是**纸本身就是颜色**（黄油 #FFE066 / 青柠 #C6F432 / 珊瑚 #FF8A75），
再配深色暗夜族做对比。

### P1-5 为了「配色跟随版式」把中性色和深色删了

大字版（bigtype）实测只有 4 个色卡：番茄红 / 亮橙 / 酸性黄 / 柑橘橙 —— **全是暖色**。
而真实产品 `catalog.js: LAYOUT_PALETTES` 给版式的是 paper / ink / bold（暖纸 / 墨夜 / 亮橙）。

方案 §6 第 7 条把「全局 8 组」改成「跟随版式」，语义对，但实现成「每个版式只留自己那一挂」，
**结果是「想做一个安静的封面」在大字版上无路可走**。
这是「为了系统一致删功能」——和用户反复强调的「不要为了精简删功能」正面冲突。

### P1-6 色块压字：23 套里 11 套不达 4.5:1，最差 2.26

`inkOn()` 的实现是**亮度阈值**：`lum > 0.42 ? 黑 : 白`。中间调色块两边都到不了 4.5：

| 配色 | accent | 判定字色 | 对比度 |
|---|---|---|---|
| mint 薄荷绿 | `#00C48C` | 白 | **2.26** |
| atmosphere/ink 墨夜 | `#d8a24a` | 白 | **2.29** |
| midnight 午夜墨金 | `#d4a04a` | 白 | **2.35** |
| citrus 柑橘橙 | `#FF7A00` | 白 | **2.61** |
| sky 天光青 | `#0EA5E9` | 白 | **2.77** |
| orange 安全橙 | `#FF6B35` | 白 | **2.84** |

正确做法不是「选黑还是选白」，而是**黑白各自算一遍取高的；两边都不够就把色块本身压深**。
（复核脚本：`scripts/gen_v2_palettes.mjs`，20 套全过。）

### P1-7 长图文右栏要滚，与「全部常驻，一屏不滚」直接矛盾

```
side-scroll client=854  scrollHeight=1013
配色:949  字号:982  选项:1015  署名:1049      ← 四项全在折叠线以下
```

方案 §3.3 标题写的是「**全部常驻，一屏不滚**」，正文还给了实测数字「848 = 848」。
那是标题图页的数字，长图文页从来没量过。

## 3. P2 · 一般（8 条，一致性与细节）

| # | 问题 | 证据 |
|---|---|---|
| P2-1 | 文档里同时出现 **9 / 22 / 26** 三个版式数量 | §6「9 套」、§5-2b「永远 22 套」、§3.3「26 套」 |
| P2-2 | §5-2b 与 §5-2e **正面冲突** | 2b「不按有没有图过滤，条目不能直接消失」；2e「没配 Key 就只出纯文字版式」。2e 自称例外，但 2b 没改，实现者读到哪条算哪条 |

| P2-5 | 卡片名与编号视觉粘连 | 编号右对齐在下个卡名左侧，「金句 **M04** 大字版」读成一张卡叫「金句M04大字版」；26 套时整行糊成一片 |

| P2-7 | 键盘无法换版式 | 卡是 `div[role=button][tabindex=0]`，可聚焦但 `Enter` 无效（实测 `enterChanged=false`） |

### 顺手确认「不是问题」的两条（避免我自造问题）

- **渲染性能没问题**：改一个字端到端 **14.4ms**，26 套版式重渲染 **19.8ms**，DOM 560 → 628 节点。
  方案里担心的「9 张全尺寸合成层卡住」在 300×400 方案下不存在。
- **配方出处可验证**：26 套里 19 套能在 `references/layout-recipes.md` 找到编号，这一点做得对。

## 4. 被质疑的 5 个核心前提

| # | 方案的前提 | 实测反例 | 我的判断 |
|---|---|---|---|
| 1 | **「三栏常驻 = 切换零成本」** | 零成本的是「点击」，不是「看见」。看不见的选择等于不存在 —— 16 套里 6 套在折叠线以下 | 前提方向对，但**少了一半**：常驻 ≠ 可见。可见性要有下限（一屏能看到多少） |
| 2 | **「版式越多越好」** | 9 → 26 之后同屏可见率从 100% 掉到 17%，边际价值转负 | 用户要的是**更多可选**，不是更多看不见。数量增长必须伴随**呈现方式升级**，否则是负价值 |
| 3 | **「没 Key 就隐藏图文版式」** | 把主场景的可发现性交给了第三方 API；上传用户被误伤（P0-2） | 规则要绑在**「有没有一张图」**，不是「有没有 Key」 |
| 4 | **「画布是唯一主角」** | 画布 591×788 撑在 856 宽栏里，两侧 237px 空白；左栏下方 355px 空白 | 主角地位没错，但**几何没按这句话算**：中栏该窄、右栏该宽 |
| 5 | **「配色跟随版式」** | 实现成「每个版式只剩自己那一挂」，大字版 4 个全是暖色 | 语义对、实现错。跟随应该是「默认值跟随」+「通用色永远可选」 |

## 6. V2 改了什么（逐条对账）

已产出：`docs/prototypes/xhs/v2/`（`title.html` / `longform.html` / `v2-shared.js` / `v2-data.js`）

| 对应问题 | V2 的做法 | 实测结果 |
|---|---|---|
| P0-1 版式看不见 | 右栏 **400 → 520**，默认 **5 列**（94px），可切 4 列（117px）；宽度从中栏的闲置空间里拿 | 16 套 **全部一屏可见**（`layScroll 632/632`，不滚），26 套滚 1.2 行 |
| P0-1 附带 | 「另有 8 套要图 →」做成头部 pill，不再占列表底部一行（那一行会把最后一行顶出可视区，实测差 27px） | 网格底边 704 < 容器底 726 |
| P0-2 有图不解锁 | 可见性改成 `layVisible(l, hasPic)` **单一入口**；Key 只决定「能不能搜」 | `usePic` 之后 `lays=26 need=false` |
| P0-3 状态失步 | 所有影响可见性的路径统一走 `renderAll()`；不再裸赋值 | 切图 / 清 Key / 上传 / 九宫格换图 四条路径复测通过 |
| P0-4 九宫格空白 | 打开时**逐格算内容覆盖率**（文本用 Range 取真实行盒，色块/图片用元素盒，>2% 算有内容），<3 格就出黄条预警，并给「把标题放大铺满」一键 | 大字版：`只有 3/9 格有内容，其余 6 张会是空白图`，6 格标「空白」 |
| P0-5 窄屏 | 1280 收窄左右栏；980 以下左右栏变抽屉 + 底部页签 | 1024 下画布 346×461 可用；768 进抽屉模式 |
| P1-1 左栏空白 | 尺寸/署名搬进来，空白处放「三个小贴士」（都是实测里真会卡住的点） | 左栏底边 545 → 900 |
| P1-2 中栏浪费 | 中栏 856 → 684，右栏 +120 | 画布 567×756，两侧各 58px |
| P1-3 缩略图不可比 | 94px + **每张用自己的默认色**（20 套按明度轮转，相邻不撞） | 16 张底色去重 **11 种**（原 7 种） |
| P1-4 颜色单调 | 配色重做为三族 **20 套**：纸感 9 / 浓郁 6 / 暗夜 5。浓郁族的 `paper` 本身就是饱和色 | 缩略图里出现黄绿、亮黄、珊瑚、黑、紫 |
| P1-5 删了中性色 | 每套版式固定包含「纸感 + 暗夜」各一，实测 26 套全部 ≥4 个色 | `bigtype`：暖纸/经典墨色/午夜墨金/克莱因蓝 |
| P1-6 色块压字 | `inkOn` 改黑白择优；`accentText` / `blockInk` 由脚本反解生成并校验 | **20/20 全过**（正文 ≥7、小字 ≥4.5、色块 ≥4.5、次要字 ≥4.5） |
| P1-7 长图文要滚 | 右栏 360 → 520，模板 4 列（12 套正好 3 行） | `sideScroll 854/854` 不滚，署名行底边 885 |
| P2-4 S09 重号 | `number` 的 code 改 `—`（产品原有，无配方出处） | 26 套编号唯一 |
| P2-5 名字粘连 | 编号挪进缩略图**右上角角标**，名字独立一行；行距 12px | 名字只可能属于上方那张 |
| P2-6 破图 | 图片先 `new Image()` 预解码，失败就回退「不要图」并提示 | broken=0 |
| P2-7 键盘 | 版式卡改**原生 `<button>`** | 可 Tab、Enter/Space 直接生效 |
| P2-8 字体同形 | 保持 10 款，`auto` 标「跟随版式」区分语义 | 仍是 9 个字形，属已知取舍 |

### 顺带修掉的一个真 bug（影响所有版式）

`renderReal` 的大字版把字号**写死 148px**：7 个字 148×7=1036 > 内容宽 904，贪心换行切成 **6+1**，
画面上「周末去了趟海 / 边」。改成按内容宽求字号（上限仍 148），并加「孤字否决」：

```js
// core: renderReal 的 bigtype 分支
h1(Math.min(148, fitTitle(t, 1080 - 176, 148, 2)), ...)
// v2-shared: fitTitle 里否决「最后一行只剩 1–2 个字」
if (lines > 1 && last === 1 && n >= 4) continue;
```

## 7. 仍然没解决 / 需要你拍板的 4 件事

1. **26 套要不要一屏全看？**
   现在 1440×900 是 16 套全见、26 套滚 1.2 行。要「26 套一屏全见」只能 5 列 × 74px ——
   缩略图会小到看不出排版，我认为不值得。**备选**：加一个「全部版式」全屏总览（6 列 × 190px），
   V2 里已经做了入口（头部「全部 ↗」），要不要保留由你定。

2. **「有图才出图文版式」这个修订要不要落？**
   我按「有图」而不是「有 Key」判断可见性，理由写在 `v2-data.js` 的注释里。
   这**偏离了你的原话**（原话是「没有登陆图的 api 就只显示纯文字」），需要你确认。

3. **九宫格要不要配一套「九宫格版式」？**
   现在的做法是「预警 + 把标题放大铺满」（复用已有能力，不新造版式）。
   如果你要的是「切出来 9 张都好看」，得专门设计一套内容分布，那是新功能。

4. **长图文的 13 套配色还是老表**（11 套里有一部分不达 AA）。
   本轮只把 `inkOn` 换成黑白择优（治标），配色表本身没重做 —— 因为长图文和标题图用的是
   两套不同的色板来源（`cards.js: PALETTES` vs `catalog.js`），合并需要你确认口径。

## 8. 验收口径（别再靠人肉核对）

以下判据都能机检，建议进 `scripts/ux_v2_accept.mjs`：

```js
// 1. 一屏可见
assert(layScroll.scrollHeight <= layScroll.clientHeight + 2)   // 无 Key 时 16 套必须全见
// 2. 可见性单入口
assert(hasPic() ? lays===26 : lays===16)
// 3. 对比度
PALS.every(p => cr(p.paper,p.ink)>=7 && cr(p.paper,p.accentText)>=4.5 && cr(p.blockBg,p.blockInk)>=4.5)
// 4. 编号唯一
new Set(LAYS.map(l=>l.code).filter(c=>c!=='—')).size === LAYS.filter(l=>l.code!=='—').length
// 5. 缩略图底色去重率（防「一堵同色墙」回归）
uniqueThumbBg >= Math.ceil(lays * 0.6)
// 6. 九宫格产物
openNine(); assert(blankCells === 0 || warnVisible)
// 7. 无破图 / 无 404
document.images.filter(i=>i.complete && i.naturalWidth===0).length === 0
```

只有量化去重率能拦住第三次。
