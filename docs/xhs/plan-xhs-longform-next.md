## 0. 本轮要解决的问题（按第一性原理重排）

用户要的最终产物只有一件事：**一篇文章 → 一套好看、能被认作「设计过」的图 → 发小红书**。
「模板多」不是目的，是手段。所以排序依据是「**哪一项决定了图好不好看**」，不是「哪一项用户抱怨最多」。

| 序 | 问题 | 现状 | 决定什么 |
|---|---|---|---|
| **①** | 12 套模板**只有皮肤差异，没有骨相差异** | 专属 CSS 81 条 / 4532 字符，57/95 在摆装饰位置；`columns`/`::first-letter`/正文分栏 **全 0** | **图的观感上限** |
| ② | 同一套页在**中栏预览**和**下方结果画廊**各显示一遍 | `#cv-deck` + `#lf-gallery` 同源 | 用户是否觉得「产品没做完」 |
| ③ | 切错模板**回不去** | 无 undo | 试错成本 → 用户不敢试新模板 |
| ④ | 12 套**看不全** + 缩略图是**文字卡** | `#cv-ltpls` 2 列堆叠 + 纯文字 | **只在容器里装的是真有差异的东西时才有价值** |

### 0.1 为什么把「一屏看全」从 ① 降到 ④

原计划把 ④ 当第一优先级，理由是「用户抱怨看不全」。
但按第一性原理追问：**看得全 12 套雷同的模板，对「图好看」没有任何贡献。**
陈列优化是**放大器** —— 输入有差异，它放大差异；输入雷同，它放大雷同。
**顺序必须是：先让模板有骨相差异 → 再让差异可被高效浏览。**

这与审计文档 §3 S-1 的结论一致：`docs/xhs/review-xhs-longform-templates.md`。

## 2. B1 · 版式骨相（主目标 ①）

### B1-1 从 19 套杂志版式里挑出可迁移的「编排语法」

**现状**：`core/magazine_layouts.py`（1457 行）有 19 套真杂志版式，**长图文模块完全没用它**。

**做法**：不是把 19 套全搬，而是**先提取语法、再适配竖屏**。
审计文档 §6 已钉死一条硬约束：**1080 宽 / 52px 正文下，双栏每栏只有 8 字/行，不可读**。
所以搬的是**编排语法**，不是双栏本身：

| 杂志手法 | 竖屏适配 |
|---|---|
| 首字下沉 | 可用（中文需单独调字号） |
| 小节序号徽章 | 可用（比现有页码强） |
| 重点句结构级放大 + 左竖线 | 可用 |
| 装饰线体系（细线 / 双线 / 条纹） | 可用（成本极低、观感提升大） |
| 大字引文块 | 可用（已有 quote 角色，加大字号与留白） |
| **双栏正文** | **不做**（见上） |
| 图文绕排 | 改为「图占整宽 + 文字在下方」 |

### B1-2 首批三套：Economist / Vogue / MUJI（原型已验证）

**这三套的差异不是配色，是分页密度与排印骨架**：

| 版式 | 手法 | 分页密度 |
|---|---|---|
| **Economist** | 红色只画线不铺底；红底序号徽章「01」；重点句放大 1.27 倍 + 左红竖线；正文深灰非纯黑 | **密** — 每页约 170 字 |
| **Vogue** | 整篇黑白无彩；标题下压一粗一细双线；每节前巨大斜体数字；重点只垫细线不上色 | **中** — 每页约 110 字 |
| **MUJI** | 米白 + 酒红只用于序号；字距 .5px；引用铺浅米底不用竖线；强调只加粗 | **疏** — 每页约 100 字，大留白 |

> 原型：`docs/prototypes/xhs/xhs-longform-layouts.html`（已实测：eco 5 页 / vog 7 页 / muj 6 页，
> **三套 clipped 全 0**，缩略图 clipped 0，1360 与 375 两档均无横向溢出）。

**落地要点**：
- **复用现分页器，不改装箱算法**：`buildLong()` 的 `measureDense`/`packDense` 是实测 DOM 高度装箱，
  已验证 24/24。三套版式只改 **`cardInner()` 里每页的 HTML 结构 + 字号阶梯 + 密度常量**，
  **不动装箱逻辑** —— 否则会同时引入分页回归，两个变量一起改就无法归因。
- **密度常量必须按版式分开**：现在 `DENSE_MIN_FILL_CHARS=140` 是全局值。
  三套版式要各自一份（170 / 110 / 100），否则「密度差异」落不了地。
- **溢出兜底两级**：原型里 Vogue 封面曾溢出 27px，根因是 `margin-top:auto` 把大数字撑到底。
  修法是**封面不用自动撑底**，另加「去重型元素 → 缩字号」两级降级。
  这条必须写进实现，否则真机上长标题必裁字。

**验收（进 `pwa_longform_test.py`，新增用例）**：
- 三套版式各用**同一篇标准夹具**出页，**每页 `scrollHeight <= clientHeight`（零裁切）**；
- 三套的**页数必须不同**（同一篇文章下 eco < vog < muj 不成立则说明密度没生效）；
- 三套的**最小字号 ≥28px**（沿用现有门禁判据）；
- 逐句比对**零丢字**（沿用现有判据）。

### B1-3 差异必须可机检（LF-TPL-10）

「看起来不一样」不能作为验收。每套版式要能被断言认出：
- 序号徽章：DOM 里存在 `.r-eco-num` 且其 `background` 非透明；
- 首字下沉（若启用）：首段首字符的 `font-size` ≥ 正文 2 倍；
- 装饰线：每页至少 1 条 `border-top/bottom` 或伪元素线；
- 密度：`charsPerPage` 落在声明的档位区间内。

**不做这一步的后果**：以后任何人改 CSS 都能悄悄把三套改回同构，而门禁全绿。

## 3. B2 · 结果区去重 + 撤销（主目标 ②③）

### B2-1 结果区去重

**现状**：中栏上半是 `#cv-deck`（实时预览，横滑），下半是 `#lf-gallery`（生成后的结果画廊），
两者渲染的是**同一套页**，只是尺寸不同。

**备选（B0 拍板 C-6）**：
- **方案 A（推荐）**：删掉 `#lf-gallery`，中栏只留 deck + 自检条 + 导出按钮。
  生成后 deck 每一格右上角出现「下载这一张」小按钮（现在的结果卡才有的能力），能力不丢。
- **方案 B**：保留画廊，deck 退化为「略缩预览条」。→ 不推荐：用户真正要看的是大图。

**验收**：
- 中栏 DOM 里不再有两套同源卡片；
- 单张下载能力仍在（点击 deck 格子 → 打开灯箱 → 下载）；
- 导出整套 / ZIP 两个按钮仍在。

### B2-2 撤销上一版

**范围（C-7）**：先做**最轻的一种** —— 只撤「模板 / 色板 / 三项开关」的切换，不撤正文编辑。

**实现要点**：
- 一条内存栈，深 20，记录 `{longTpl, palKey, longPn, longSign, longBg}` 的**前一个完整快照**；
- 每次用户主动改任一项前先 push；
- 正文 textarea 变化**不 push**（否则一打字就淹掉模板历史）；
- 撤销按钮放在模板区头部（`#cv-ltpls` 上方），无可撤时 `disabled`；
- **不写进 localStorage**（刷新即清空，避免用户以为能跨会话恢复）。

**验收（进 `pwa_longform_test.py`）**：
- 切 A→B→C 后连点两次撤销，回到 A；
- 撤销到栈底后按钮 disabled；
- 正文改了之后撤销，**正文不回退**、只有模板/色板回退；
- 无可撤状态下点按钮不报错。

## 4. B3 · 模板区陈列（主目标 ④，**必须等 B1 落地**）

### B3-1 模板缩略图改成真实渲染

**现状**：`renderLongTpls()` 产出的是「名称 + 一句描述」文字卡（`longform-page.js:82-97`）。

**目标**：每张卡显示**用户当前文章在该模板下的第 1 页**（缩到 96×128 左右）。

**实现要点**：
- 复用已有能力，不新造渲染：`buildLong()` 出页 → `cardInner()` 出 HTML → 塞进一个缩放容器
  （现成的 `ensureCardsEnv()` 已经在主文档注入卡片 CSS + 封面字体，直接可用）。
- **12 套 × 每次输入变化都重渲 = 性能雷区**。必须做：
  1. **防抖 300ms**（用户还在打字时不渲）；
  2. **按模板缓存**，key = `模板 id + 文章首 200 字哈希 + 色板`，命中不重渲；
  3. 首屏只渲**可见的 6 张**，滚动到再渲剩下 6 张（`IntersectionObserver`）。
- **降级**：`ensureCardsEnv` 未就绪（卡片 CSS/字体还没加载）时回落现在的文字卡，**不允许空白卡**。
- **缩略图也要走实测分页**：不能按字符数截断，否则缩略图里会出现被裁的字（原型踩过这个坑）。

**验收**：
- 12 张卡全部有内容（非空白、非文字卡降级）；
- 改一次正文，模板区在 **≤600ms** 内更新完（含防抖）；
- 切换色板时，3 套跟随色板的模板缩略图跟着变色，9 套锁色的**不变**；
- **缩略图内零裁切**（`scrollHeight <= clientHeight`）；
- 无 JS 异常。

### B3-2 模板区一屏看全

**现状**：`cover.css:171` `.cv-ltpls { grid-template-columns: repeat(2,1fr) }`，右栏最宽 520px，
12 套 × 2 列 = 6 行，在 900px 高视口下必然超出，且与下方色板/版式选项**共用同一个滚动容器**。

**目标**（两个都做，缺一不可）：
1. **模板区独立滚动**：`.cv-ltpls` 自己 `overflow-y:auto` + `flex:1`，
   色板与版式选项**永远在它下面不被挤走**；
2. **密度提升到 4 列**，让 **12 套一屏全见**（原型实测：1280×900 下 4 列卡片 103×157、
   3 行共 12 张全部落在模板区内，内容高 483px < 容器高 562px，无横向溢出）。

> **⚠️ 此条已由原型实测修正**：原计划写「3 列、≥8 张」，理由是「12 张全露每张只剩 60px」。
> 实际在 103×157 下缩略图仍能看清标题与版式特征（`docs/prototypes/xhs/xhs-longform-plan.html` 已可亲眼看），
> 所以 4 列全见是可行的。独立滚动仍要保留 —— 视口更矮（如 800px）时它是保底。

**验收（机检，进 `pwa_longform_test.py`）**：
- 1280×900 与 1440×900 下：模板区**可见卡数 = 12**，且模板区内容高 ≤ 容器高（不需要滚动）；
- 视口缩到 1280×720 时：模板区出现独立滚动条，**色板与版式选项仍在原位不被挤走**；
- 375 宽下无横向溢出（原型实测：`document.documentElement.scrollWidth === innerWidth`）。

## 2. B1 · 模板区改造（主目标 ①）

### B1-1 模板缩略图改成真实渲染

**现状**：`renderLongTpls()` 产出的是「名称 + 一句描述」文字卡（`longform-page.js:82-97`）。

**目标**：每张卡显示**用户当前文章在该模板下的第 1 页**（缩到 96×128 左右）。

**实现要点**：
- 复用已有能力，不新造渲染：`buildLong()` 出页 → `cardInner()` 出 HTML → 塞进一个缩放容器
  （现成的 `ensureCardsEnv()` 已经在主文档注入卡片 CSS + 封面字体，直接可用）。
- **12 套 × 每次输入变化都重渲 = 性能雷区**。必须做：
  1. **防抖 300ms**（用户还在打字时不渲）；
  2. **按模板缓存**，key = `模板 id + 文章首 200 字哈希 + 色板`，命中不重渲；
  3. 首屏只渲**可见的 6 张**，滚动到再渲剩下 6 张（`IntersectionObserver`）。
- **降级**：`ensureCardsEnv` 未就绪（卡片 CSS/字体还没加载）时回落现在的文字卡，**不允许空白卡**。

**验收**：
- 12 张卡全部有内容（非空白、非文字卡降级）；
- 改一次正文，模板区在 **≤600ms** 内更新完（含防抖）；
- 切换色板时，3 套跟随色板的模板缩略图跟着变色，9 套锁色的**不变**；
- 无 JS 异常。

### B1-2 模板区一屏看全

**现状**：`cover.css:171` `.cv-ltpls { grid-template-columns: repeat(2,1fr) }`，右栏最宽 520px，
12 套 × 2 列 = 6 行，在 900px 高视口下必然超出，且与下方色板/版式选项**共用同一个滚动容器**。

**目标**（两个都做，缺一不可）：
1. **模板区独立滚动**：`.cv-ltpls` 自己 `overflow-y:auto` + `flex:1`，
   色板与版式选项**永远在它下面不被挤走**；
2. **密度提升到 4 列**，让 **12 套一屏全见**（原型实测：1280×900 下 4 列卡片 103×157、
   3 行共 12 张全部落在模板区内，内容高 483px < 容器高 562px，无横向溢出）。

> **⚠️ 此条已由原型实测修正**：原计划写「3 列、≥8 张」，理由是「12 张全露每张只剩 60px」。
> 实际在 103×157 下缩略图仍能看清标题与版式特征（`docs/prototypes/xhs/xhs-longform-plan.html` 已可亲眼看），
> 所以 4 列全见是可行的。独立滚动仍要保留 —— 视口更矮（如 800px）时它是保底。

**验收（机检，进 `pwa_longform_test.py`）**：
- 1280×900 与 1440×900 下：模板区**可见卡数 = 12**，且模板区内容高 ≤ 容器高（不需要滚动）；
- 视口缩到 1280×720 时：模板区出现独立滚动条，**色板与版式选项仍在原位不被挤走**；
- 375 宽下无横向溢出（原型实测：`document.documentElement.scrollWidth === innerWidth`）。

## 3. B2 · 结果区去重 + 撤销（主目标 ②③）

### B2-1 结果区去重

**现状**：中栏上半是 `#cv-deck`（实时预览，横滑），下半是 `#lf-gallery`（生成后的结果画廊），
两者渲染的是**同一套页**，只是尺寸不同。

**备选（B0 拍板 C-6）**：
- **方案 A（推荐）**：删掉 `#lf-gallery`，中栏只留 deck + 自检条 + 导出按钮。
  生成后 deck 每一格右上角出现「下载这一张」小按钮（现在的结果卡才有的能力），能力不丢。
- **方案 B**：保留画廊，deck 退化为「略缩预览条」。→ 不推荐：用户真正要看的是大图。

**验收**：
- 中栏 DOM 里不再有两套同源卡片；
- 单张下载能力仍在（点击 deck 格子 → 打开灯箱 → 下载）；
- 导出整套 / ZIP 两个按钮仍在。

### B2-2 撤销上一版

**范围（C-7）**：先做**最轻的一种** —— 只撤「模板 / 色板 / 三项开关」的切换，不撤正文编辑。

**实现要点**：
- 一条内存栈，深 20，记录 `{longTpl, palKey, longPn, longSign, longBg}` 的**前一个完整快照**；
- 每次用户主动改任一项前先 push；
- 正文 textarea 变化**不 push**（否则一打字就淹掉模板历史）；
- 撤销按钮放在模板区头部（`#cv-ltpls` 上方），无可撤时 `disabled`；
- **不写进 localStorage**（刷新即清空，避免用户以为能跨会话恢复）。

**验收（进 `pwa_longform_test.py`）**：
- 切 A→B→C 后连点两次撤销，回到 A；
- 撤销到栈底后按钮 disabled；
- 正文改了之后撤销，**正文不回退**、只有模板/色板回退；
- 无可撤状态下点按钮不报错。
