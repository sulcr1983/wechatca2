## 3. 分阶段实施

### 阶段 A：骨架与状态（不改渲染内核）

**目标**：先把页面结构改成三栏，旧 10 套版式仍能工作；可回滚。

任务：

1. `title-page.js` 重写 DOM：
   - 顶栏：历史 `↺`、`?`、保存大图
   - 左栏：文案 textarea + 用正文/示例/清空；配图三段 + 当前图卡；尺寸；署名；贴士
   - 中栏：画布 + 状态条 + 复制/九宫格/保存
   - 右栏：版式头 `30 套` + 全部 ↗ + 密度；版式网格；配色/字体/玩法/位置/磨砂
   - 删除 `#cv-gallery` 结果画廊；灯箱改挂画布
2. 状态单一真源：`state = { text, layout, palette, size, font, mode, pos, frost, image }`，所有控件只改 state 再重绘。
3. 旧 10 套版式先接到新右栏（数量显示 30 由阶段 B 完成）。
4. 出片托盘：保存后显示缩略图/尺寸/复制/下载/关闭。
5. 历史：`supersu.cover.history.v1`，保存后写入，最多 24 条。

验收：

- 三栏在 1440×900 下尺寸正确，无横向滚动。
- 旧 10 套每套可选中并改变画布。
- 保存 PNG 尺寸正确；托盘可用。
- 375px 折成三页签，无横向溢出。
- 现有 `pwa_cover_test.py` 的入口/版式/尺寸用例仍通过（选择器迁移同步改测试）。

回滚：保留旧 `title-page.js` 的 DOM 构建函数在 feature flag 后，或整文件回滚到上一提交。

---

### 阶段 B：30 套版式全量

**目标**：右栏 30 套，全部可渲染；需图版式置灰不隐藏。

任务：

1. 建立单一版式清单（建议新文件 `pwa/src/cover/layout-registry.js`）：
   - 字段：`id / name / code / group / needImg / pals / render`
   - 30 条与设计文档 §5.2 一致；禁止在 UI 与渲染各写一份。
2. 复用现有 7 套实现；移植 23 套配方：
   - 先做纯文字 13 套（验证字体/排版/多行），再做图文 10 套（底图、亮度、磨砂）。
   - 每套必须有：缩略图渲染（300×400）+ 正式画布渲染（1080×1440）。
3. 需图版式：
   - 无图时 `disabled` + 原因；点击 toast + 「去选图」。
   - 有图时恢复可选；不因切回“不要图”而丢失当前版式（回落到最近可用纯文字版式）。
4. 全部版式弹层复用同一清单，不维护第二套。
5. 配色映射：每套版式 3–10 个色板；切版式保留同名色板，不存在则回落第一个。

验收：

- 右栏 30 套全部存在；无图时 10 套置灰且原因可读。
- 30 套逐套选中，画布 HTML 变化且不报错。
- 全量截图/差异审计：30 套 × 3 尺寸不空、不溢出、不丢字。
- 单套渲染失败不影响其他套；失败有 toast。

风险与缓解：

- 23 套配方是最大工作量；先按组交付（纯文字 → 图文），每完成 5 套跑一次回归。
- 不要把 `xhs-ux-core.js` 整文件复制进产品（含原型状态/演示代码）；只移植渲染函数与常量，避免死代码。
- 字体未就绪时缩略图可能闪烁；统一等 `document.fonts.ready` 后再出正式图。

---

### 阶段 C：输出与历史

任务：

1. PNG：2× 渲染 → 目标尺寸；文件名 `xhs-title-<yyyyMMdd-HHmmss>-<layout>-<size>.png`；失败给原因。
2. 九宫格：3×3、顺序 1→9 / 蛇形、间距 0–20；ZIP `nine-01..09.png`；空白 ≥3 格预警。
3. 复制：`text/html` 写入剪贴板；图片能内嵌则内嵌；失败原因可见。
4. 历史：保存成功才写入；恢复时还原版式/配色/尺寸/文案/底图；上限 24；localStorage 不可用降级内存态。
5. 出片托盘：复制/下载/关闭；关闭后仍可从历史找回。

验收：

- 三种尺寸 PNG 像素精确；文件名合法（Windows 不允许字符已过滤）。
- 九宫格 9 张尺寸/顺序/裁剪正确；ZIP 可解压。
- 复制内容在公众号后台可粘贴（或明确记录“无法验证”的原因）。
- 刷新后历史仍在；第 25 条淘汰最旧。

---

### 阶段 D：响应式、状态与可访问性

任务：

1. 断点：≥1281 / 980–1280 / <980；<980 三页签 + 底部操作条。
2. 375px：右栏卡横向滚动，不压缩到不可点；画布单列。
3. 所有按钮 `aria-pressed` / `disabled` / `aria-label`；键盘可达；焦点可见。
4. 失败态：无 Key、无结果、坏图、字体失败、渲染失败、下载失败、存储不可用。
5. 对比度：文字/底图、按钮禁用态、提示文字达到可读标准。

验收：

- `audit_mobile_typography.py --browser` 0 FAIL；375px 无横向溢出。
- 键盘 Tab 能走完左/中/右主要控件；Esc 关闭弹层。
- 所有失败场景都有可见文案，不出现“点了没反应”。

## 6. 兼容与迁移

- **URL / 入口**：标题图页签不变；`#title-root` 保留，避免 `index.js` 与测试失联。
- **localStorage**：
  - 旧键（最近使用/收藏）继续读；新历史单独键，不覆盖旧数据。
  - 旧版式 ID 与新 30 套有重叠（7 套），保留同名 ID；改名/合并的旧 ID 做别名映射。
- **旧选择器**：`pwa_cover_test.py`、`pwa_nine_test.py`、`pwa_online_e2e.py` 中 `.cv-card`、`#cv-gallery`、`.cv-style-pick` 等会变化；阶段 A 同步更新，避免“测试绿但页面坏”。
- **回滚**：整个标题图改造在一个功能开关后（如 `localStorage['supersu.cover.v3']` 或 URL `?cover=v3`），出问题可切回旧版；开关默认值在阶段 E 再决定。
