## 2. 用户原话（需求的最上游，不要转述）

出处：`research/research-2026-10-31-xhs-longform-generators.md` §1/§四、`handoff-xhs-studio-redesign.md` §11、
`design-module-split-ia.md` §1。

| # | 原话要点 | 硬约束 |
|---|---|---|
| L-R1 | 「标题图和长图长文应该是两个没有关联的模块，做标题就是做标题」 | 长图文是独立顶级模块，**首屏零标题图概念** |
| L-R2 | 「也有人需要长图长文，就再到长图长文模块，搜图，填写长文，生图」 | 长图文有自己的完整工作流 |
| L-R3 | 「整篇文字肯定是放在最左上啊，不然粘贴文字，选图，选版式，导出。这才是正常吧？」 | 左栏顺序定稿：**① 整篇文章 → ② 封面配图 → 导出** |
| L-R4 | 「假如是长图长文的第一页和其他页完全不同，也很奇怪啊」 | **一套模板管整套**，封面 = 该模板的第 1 页 |
| L-R5 | 「长图长文这个不一定要和标题图的 12 套一样啊……至于背景图那是搜图模块增加的功能，和版式不同啊！」 | 不复用标题图版式；背景图与版式**正交** |
| L-R6 | 「我让你去调研是去调研人家小红书生成器是怎么做的，不是搜论文啊！」 | 形态以**真实产品**为准，不自行拍脑袋 |
| L-R7 | 「上面的标题图 长图文要表明是小红书的」 | 顶栏全称「小红书长图文」，任何断点不缩词 |
| L-R8 | 「长图长文的模版版式已经很多了！你又自己造轮子！要在原来的基础上增加，去重新设计，不要删除」 | **只在既有 12 套上增强，不新造一套替换** |
| L-R9 | 「模板都是千篇一律，只是改了个颜色，没有啥意义，希望有更多的真正设计和排版的风格」 | **差异必须落在「骨相」**：分页密度 / 排印骨架 / 序号系统 / 装饰线体系。只在纸色、页眉页脚上变化，不算一套新模板 |
| L-R10 | 「参考杂志的设计模板，先搜索开源组件和参考其他人的优秀方案」 | 版式意图**以真实杂志排印为源**，不凭印象自造；引入外部实现前先做开源调研 + license 审查 |

> ⚠️ **L-R8 与 L-R9 的张力，必须一起读**：L-R8 要求「不删除既有 12 套」，
> L-R9 说这 12 套「千篇一律」。两者同时成立的处理方式是——
> **既有 12 套一套不删（保住用户已收藏/已习惯的），但要把它们的差异从「皮肤」做到「骨相」；
> 同时补入以杂志排印为源的真正版式。**不是用新套替换旧套。
>
> L-R9 的量化证据见 `docs/xhs/review-xhs-longform-templates.md` §2：12 套模板专属 CSS 共 81 条 /
> 4532 字符，其中 57/95 条在摆装饰元素的 `right/top/bottom/z-index`，
> `columns` / `float` / `::first-letter` / 正文分栏 **全部为 0 条**。

## 4.1 色板与版式的耦合（2026-11-03 用户补充观察，本轮新增结论）

用户原话：「**不同的颜色纸板占据选择的位置太大了。而且很多颜色切换了整体就不好看了。**」

这两句是**同一个问题的两面**，不是两个独立的 UI 抱怨：

| 观察 | 表面是 | 真正的原因是 |
|---|---|---|
| 色板占位太大 | 尺寸问题 | 色板被当成**全局维度**，所以永远要占一行位置 |
| 换色后整体不好看 | 配色问题 | **版式的视觉语法本身是有色彩的**，随便换色等于让用户破坏版式设计 |

**量化事实**：`PALETTES` 8 套 × `LONG_TPLS` **12 套** = 96 种组合，
但只有 **3 套跟随色板**（editorial / swiss / blank，`palette: null`），**9 套锁色**。
（原写「15 套 / 120 组合 / 12 套锁色」是把原型里三套杂志版式当成了产品现状，见开头勘误区。）
若将来落地杂志源版式，它们**应全部锁色** —— Economist 的红、Vogue 的黑白、
MUJI 的米白+酒红是版式身份的一部分，换掉就不是那套版式了。

**结论（写进需求）**：

- **LF-PAL-6**：版式自带配色时，**色板区整块收起**（不是置灰占位）。
  置灰仍占一行位置，等于「告诉你这里有个你用不了的东西」。
- **LF-PAL-7**：色板从「全局维度」降级为「**该版式允许的微调**」。
  跟随色板的版式展开色板；锁色版式不展开。
- **LF-PAL-8**：若某套版式要做「同版式不同色系」（如 Economist 红 / 蓝 / 墨），
  那是**该版式的内部变体**，不是全局色板 —— 两者不能混成一层 UI。

> 这条结论与既有 D8「锁色模板 → 色板置灰 + 明说原因」**有冲突**：
> D8 是「置灰」，本轮改为「收起」。理由是用户实测反馈「占位太大」——
> 置灰的可点区域仍是占位，而 **9/12** 套都是锁色的，这个区域 75% 的时间在做无用功。

## 4.2 三套杂志版式的「密度差异」是版式身份，不是参数（⚠️ 原型侧结论，产品未落地）

> ⚠️ **本节全部是原型实测**（`prototypes/xhs-longform-layouts.html`），
> **不是产品现状**。Economist / Vogue / MUJI 三套从未写进 `cards.js`，见开头勘误区。
> 保留本节是因为「密度差异应由 CSS 几何决定、不是由常量决定」这条工程结论仍成立，
> 且已被 [`prototypes/xhs/longform-v4/SPEC.md`](../prototypes/xhs/longform-v4/SPEC.md) §3 沿用。

原型实测（同一篇 439 字文章）：

| 版式 | 页数 | 每页字数 | 密度档 |
|---|---|---|---|
| Economist | 5 页 | ~170 字 | 密 |
| MUJI | 6 页 | ~100 字 | 疏 |
| Vogue | 7 页 | ~110 字 | 中 |

**页数不同本身就是排版差异** —— 它意味着同一篇文章在 Economist 下是紧凑的信息流，
在 MUJI 下是被大留白拉开的呼吸节奏。

**代码层怎么实现（已核实，比原先的判断更省事）**：
`packDense()` 调 `denseMaxHeight(tpl, pal)`，后者**用 `tpl.cls` 建真实 DOM 并实测 `.body` 高度**
（`cards.js:713-727`）。所以只要 CSS 改掉该版式的 `--fs` / `--pgap` / `line-height` / `.body` 的
`top`+`bottom` 内边距，**装箱容量自动跟着变，不需要为每套版式手写一份 `DENSE_MIN_FILL_CHARS`**。

> ⚠️ 我先前在 §4.2 初稿写过「必须把全局常量按版式拆开」——**这句是错的，已修正**。
> 全局 `DENSE_MIN_FILL_CHARS=140` 只用于一处：`buildLong` 里「末段摘去做 closing 前先验算上一页
> 是否还够填」（`cards.js:922`）。它管的是**摘段守卫**，不是分页容量。
> 真正决定「每页多少字」的是实测 DOM 高度，与常量无关。
> 拆常量的唯一必要场景是「该版式的 68% 填充下限要变」——本轮三套都不改下限。

**因此「骨相差异」在代码层落地的位置只有两处**：
1. `LONG_TPLS` 新增条目（`palette` 锁色 + `head/foot`）；
2. `CARD_CSS_RAW` 新增该 `cls` 的几何与排印规则（字号 / 行距 / 内边距 / 装饰线）。

**验收必须能证明密度真的不同**：同一篇夹具下三套版式的**页数不相等**。
若相等，说明 CSS 只改了装饰、没改几何 —— 那就是又一次「换皮」。

## 6. 需要先定方向、再谈落地的（本轮先做原型，评完再选）

> 这些是**方案之间互相冲突**的地方，不是缺细节。逐条给冲突点与备选，等原型评审后由项目所有者裁定。
> 本表不替用户选择。

| # | 冲突 | 备选 |
|---|---|---|
| C-1 | **页面比例**：只出 3:4（现产品 / D13）vs 补竞品那 3 种比例 | 补的话「切比例 = 重新分页」，页数会翻倍，需重做上限策略 |
| C-2 | **模板呈现**：文字卡（现状）vs 真实渲染缩略图 vs 两者混排 | 真实缩略图能让「一屏看全」成立，但要为每套模板各渲一张、且随文章内容变化 |
| C-3 | **封面**：必出（现状）vs 加「启用封面」开关（竞品有） | 加开关会牵动页数上限与自检口径（页数−1） |
| C-4 | ~~模板分组~~ **已撤回（2026-11-03）** | 撤回理由：分组维度是装饰属性，给雷同的东西分组不产生价值。**改为「按差异维度选模板」**（见 §6 下方 C-11） |
| C-5 | **分页可干预度**：纯自动（现状，只有 `---`）vs 逐页手动调整 | 后者要引入页面编辑器，复杂度陡增，与「极简至上」冲突 |
| C-6 | **结果区存废**：保留「整套图文结果」画廊 vs 只留实时预览 + 出片托盘 | 现状是同一套页展示两次 |
| C-7 | **撤销粒度**：只撤「模板/色板切换」vs 连正文编辑一起撤 | 前者轻（一条状态栈），后者要与 textarea 历史合并 |
| C-8 | **水印 / 社交图标**要不要补（竞品有，签名已覆盖大半） | 补的话是右栏新增一组控件，仍受「右栏已满」约束 |
| C-9 | **`steps` 步骤页**：接上产出（原文「第 X 步」/①②③ 独立成步骤页）vs 删掉死分支 | 接上是**补能力**（清单式内容更易读）；删掉是**减法**（少一类页、少一套 CSS）。现状两边都不算，属半成品 |
| C-10 | **5 套拟物道具风**（备忘录 / 大厂文档 / 胶片 / 拍立得 / 效率笔记）如何在 UI 里表述：仍称「模板」vs 另起一组「拟物」标签 | 另起标签能让用户预期对齐（他要的是「像认真设计过的一页」，不是「像截图的备忘录」）；但会让模板区多一层分组，与刚撤回的 C-4 形态相近 |
| C-11 | **模板怎么选**：平铺 vs 按「差异维度」筛（先选排印骨架 → 再选纸色） | 维度筛是把 §7 的 A/B/C/D 做成 UI，能让「差异」被看见；代价是多两步操作，与「高频控件常驻」有张力 |
| C-12 | **杂志源版式补几套、补哪几套**：先补 3 套（Economist / Vogue / MUJI）验证 vs 一次补 8 套 | 先 3 套能把「骨相差异」这条路验穿；一次补 8 套则在没验证前就铺开，返工面大 |

### C-4 撤回记录（为什么上一轮的判断是错的）

上一轮把「12 套要不要分 3 组（纸感 / 暗夜 / 强背景）」当成一个正经决策项。审计后看：
**这三个分组维度全部是装饰属性**（纸色、底色明暗、是否支持背景图）。
给 12 套雷同的模板分组，只是把雷同分门别类，不产生任何价值。
真正该问的是「**一套模板的差异维度是什么**」，见 `review-xhs-longform-templates.md` §7。
