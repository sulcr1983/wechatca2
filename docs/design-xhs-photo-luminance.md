## 0. 为什么需要这份东西

用户原话两条：

> 「文字和底图区分不开」
> 「不能把照片压成灰雾」

这两句其实是同一个问题的两面。过去三轮迭代一直在调「遮罩浓度」这个参数上打转：

| 试过的做法 | 结果 |
|---|---|
| 整页铺图 + 整页压暗 | 照片压成灰雾，浅色图最明显 → 等于白放一张图 |
| 图铺上半屏 + 正文下移到纸面 | 可用高度 1124→630，页数 3→7 → 图把版面吃掉了 |
| 刊头照片带 + 只压页眉条 | 成立（记在 `research-2026-10-30` §8.2） |
| **但压多少才算够？** | **一直没有依据，只能试** |

**这份文档要解决的就是最后一行**：把「压多少」从试出来变成算出来，
并且在「算了也不够」的时候给出一条明确的退出路径（换构图），而不是继续加浓度。

## 1. 方法：怎么测一张照片能不能压字

用无头 Chrome 把照片缩到 60×80 像素（够判断亮度分布，又不至于慢），逐像素算
WCAG 相对亮度，横向均分 **10 条带**，每条带取四个量：

| 量 | 含义 | 用它回答什么 |
|---|---|---|
| `mean` | 平均亮度 | 整体明暗（不判可读性） |
| `variance` | 亮度方差 | 这条带**干不干净**（低 = 细节少 = 安静） |
| `p05` | 第 5 百分位 | **黑字**的下限（最暗处决定黑字能不能站住） |
| `p99` | 第 99 百分位 | **白字**的下限（最亮处决定白字能不能站住） |

⚠️ **必须用 p99 而不是 mean 或 p95**。实测 `analyze.js` 早期用 p95 时，
某张图 p95=0.34（看着 scrim 0.30 就够），但真实最亮处 0.93 ——
白字怕的正是那 1% 的亮块（路灯、天空、白墙），平均值救不了它。

复现命令（本地，无网络依赖）：

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless --disable-gpu \
  --no-sandbox --allow-file-access-from-files --user-data-dir=output/probe \
  --dump-dom "file:///$PWD/output/xhs-vision/lum-probe.html"
```

## 3. 从数据反解：scrim 到底该给多少

白字要达标 4.5:1 → 背景亮度必须 ≤ `1.05/4.5 − 0.05 = 0.1833`。

在 **sRGB 空间**解 α（不能直接 `L×(1−α)`，会严重低估）：

```
α = (s − invLin(0.1833)) / (s − 12)        s = invLin(L)
```

### 3.1 分级判定表（这就是产品该执行的规则）

| 文字带亮度 L | 白字裸对比 | 需要 α | 判定 | 产品动作 |
|---|---|---|---|---|
| ≤ 0.15 | ≥ 5.25 | 0 | **免 scrim** | 直接压字，照片零改动 |
| 0.15 – 0.25 | 3.50 – 5.25 | 0.00 – 0.147 | 局部 scrim 可解 | 压文字那条带，α 按公式给 |
| 0.25 – 0.373 | 2.63 – 3.50 | 0.147 – 0.300 | 局部 scrim 可解 | 同上，但要复核压完的观感 |
| **> 0.373** | **< 2.63** | **> 0.300** | **❌ 不合格** | **换构图，不许加浓度** |

**两个关键数字（都是解出来的，不是估的）：**

1. **α 的上限是 0.30，不是 0.40。**
   α=0.40 时照片暗部被抬到 40% 灰，明暗对比压掉近一半；浅色图（L≈0.9）要压到
   4.5:1 需要 α=0.54，那时已经完全是一块灰板。
2. **α=0.30 对应的亮度临界点是 L = 0.373，不是 0.40 或 0.45。**
   解 `(invLin(L) − invLin(0.1833)) / (invLin(L) − 12) = 0.30` 得 L = 0.3730。
   换句话说：**L > 0.373 的照片，压字这条路就已经死了**，必须换构图。

### 3.1.1 ⚠️ 不要用 `α = 1 − 0.1833/L`（线性近似）

这是最容易写错的一步。α 混合发生在 **sRGB 空间**，不是在相对亮度空间：

```
✅ 正确（sRGB 空间）：α = (invLin(L) − invLin(0.1833)) / (invLin(L) − 12)
❌ 错误（线性近似）：α = 1 − 0.1833 / L
```

两者差距很大，而且是**双向**错的：

| 文字带 L | 正确 α | 线性近似 α | 差 | 后果 |
|---|---|---|---|---|
| 0.60 | 0.443 | 0.695 | +0.252 | 压成灰雾 |
| 0.50 | 0.392 | 0.633 | +0.241 | 压成灰雾 |
| 0.40 | 0.323 | 0.542 | +0.218 | 压成灰雾 |
| 0.373 | **0.300** | 0.509 | +0.209 | 临界点被误判 |
| 0.30 | **0.221** | 0.389 | +0.168 | **本来能救，被判不合格** |
| 0.25 | **0.147** | 0.267 | +0.120 | **本来免压，被压成灰** |
| 0.20 | 0.044 | 0.084 | +0.039 | 轻微过度 |

**具体危害**：按线性近似，文字带亮度在 **0.262 – 0.373** 之间的照片会被判成「不合格」
（因为近似 α 已 > 0.30），而这些图实际用 α = 0.22–0.30 就能救回来 —— 白白丢掉一批可用图。
反过来在 L < 0.262 的区间，近似 α 又会过度压暗，正是用户抱怨的「灰雾」。

> 项目里 `pwa/src/cover/analyze.js` 的注释已经写对了这一点
> （「alpha 混合必须在 sRGB 空间做，不能直接乘 L」），落地时照它写即可。

### 3.2 三条派生规则

1. **字色先于遮罩**。先按 `p05/p99` 比出「白字划算还是黑字划算」，再决定要不要压。
   `山野秋千` 就是典型：白字全局最高 4.3:1（不合格），但黑字有 12.6:1 ——
   **换成黑字就好了，一滴遮罩都不用加**。产品里 `analyze.js` 的 `analyzeZone()`
   已经在做这个比较，问题只在于版式把文字位置钉死了，导致比较结果用不上。
2. **判定要按整个文字块，不是按主标题那 2 带**。
   实测 `C3 顶压` 时主标题落在 y10–20% 天空（黑字 11.6:1，很漂亮），
   但 104px 标题 + 副标实际占到 3 带，副标掉到山脊上就看不清。
   → 判定窗口取 `[z, z+2]`，宁可报不合格，也不要交出「标题清楚、副标糊掉」的图。
3. **scrim 必须跟着文字带走，而不是钉在固定的百分比上**。
   版式给的是**范围**（如「下半部」），具体落哪条带由这张图的实测决定。
   实验室里 `C2` 在夜街图落在 y80%（白 14.8:1），在雾晨图落在 y80%（白 8.7:1），
   在旧照片堆上直接报不合格 —— 同一套代码，三种正确行为。

## 4. 六种构图按「文字保护方式」分三类

这是把上面数据变成设计语言的翻译层。**分类的意义：第一、三类永远不需要判断照片**。

| 类 | 构图 | 文字在哪 | scrim | 适用 |
|---|---|---|---|---|
| **Ⅰ 空间分离**（零判断） | C1 刊头带 | 纸面（图 0–520px） | 无 | **默认**。任何图都能用，包括不合格图 |
| | C4 左文右图 | 左侧 542px 纸面 | 无 | 竖构图 / 人像 / 单品 |
| | C5 上图下文 | 下方纸面 | 无 | 图是主体、标题短 |
| **Ⅱ 容器分离**（零判断） | C6 纸卡浮层 | 纸色卡片内 | 无（卡片即底板） | 图很美不能压、但标题长 |
| **Ⅲ 局部压字**（需判断） | C2 全出血·底沉 | 底部带区 | 按 §3.1 | 图有 ≥20% 安静带 |
| | C3 全出血·顶压 | 顶部带区 | 按 §3.1 | 同上，但更苛刻（要 3 带干净） |

**产品含义**：`Ⅰ + Ⅱ = 4 种构图` 是**无条件可用**的兜底集合。
只要用户选了搜图底图，这 4 个选项永远点得亮；
`Ⅲ` 的 2 个选项由实测决定是否置灰，并在置灰时给一句人话：

> 「这张图太花了，压字会看不清 · 已为你切到「刊头带」」

这比让用户自己去猜「文字位置该选偏上还是偏下」有用得多。

### 4.1 实测出来的两个构图级坑

| 坑 | 实测现象 | 修法 |
|---|---|---|
| **中文标题在窄栏里被硬断** | C4 原设计栏宽 445px + 标题 76px = 5.8 字/行 → 「周末去了趟海边」(7 字) 断成「周末去了趟海 / 边」，断在词中间 | 栏宽 445→**542px**、标题 76→**68px**（7.9 字/行）。**中文窄栏必须按「字数 × 字号 ≤ 栏宽」反算字号，不能沿用全宽的字号** |
| **上图下文的文字顶在接缝上** | 正文从 y720 起排，结束在 y1000 左右，下方 350px 空白 → 读起来像「内容没写完」 | 文字**贴底**（距页脚 200px），与 C2 同一种收口方式 |

## 5. 长文页的密度核算（另一处需要定口径的地方）

按 `layout-recipes.md` 的硬规则「内容覆盖 ≥75% 画布高」，用 52px 正文实测各角色：

| 角色 | 内容组成 | 实测高度 | 填充 | 判定 |
|---|---|---|---|---|
| 开篇 | 色条 + 74px 引言 2 行 + 斜体副标 + 署名 | 404px | **36%** | 欠填 |
| 清单 4 条 | 4 × (编号 + 1 行正文) + 细线 | 710px | **63%** | 欠填 |
| 清单 4 条 + 标题 | 上行 + 56px 标题 | 820px | **73%** | 边缘 |
| 金句（仅引文） | 引号 + 78px 引文 2 行 | 529px | **47%** | 欠填 |
| 金句（引文 + 上下文） | 上行 + 30px 上下文 | 621px | **55%** | 欠填 |
| 正文 1 段 130 字 | 52px / 1.74 / 段距 43 | 724px | **64%** | 欠填 |
| 正文 2 段 200 字 | 同上 | 767px | **68%** | 欠填 |
| 结尾（仅结论） | 色条 + 66px 结论 + CTA | 401px | **36%** | 欠填 |
| 结尾（结论 + 补充） | 上行 + 31px 补充 | 442px | **39%** | 欠填 |

**没有一个角色能靠「自然排版」达到 75%。** 这不是 bug，是 52px 正文 + 1440px 画布的算术结果。

### 5.1 口径建议（不是放松规则，是把规则用对）

`layout-recipes.md` 的 75% 规则原文分两句，第二句才是可迁移的那句：

> 「纯空白带 >15% 画布高度（>216px）**需要说明理由**」

而且 `M04 Pull Quote` 明确开了口子：

> 「this is the **one recipe** where ≤60% canvas content is allowed (hero statement =
> intentional whitespace)。**BUT** you must add (a) source row, (b) kicker, (c) hairline rule」

所以正确的落地口径是：

| 页型 | 门槛 | 附加要求 |
|---|---|---|
| **正文 / 清单 / 步骤 / 对比** | **≥ 68%**（≈ 170 字/页 @52px） | 无需 |
| **开篇 / 金句** | **≥ 45%** | **必须 ≥2 个承托锚点**：kicker 条 / 署名行 / 上下文段 / 超大淡色装饰 / 页码 |
| **结尾** | **≥ 60%** | **必须 ≥3 条 ledger 行**（`M07` 明确要求 4–6 条带 sub-line 的行，纯大字结尾不成立） |

**换句话说：结尾页不该是大字页。** 现在 `closing` 用 66px 结论 + CTA 只有 36%，
按 `M07 Closing Note` 应该是「结论 + 3–4 条 ledger + CTA」，这样才既好看又够满。

### 5.2 单段字数的安全上限（会溢出，别再往上试）

52px / 1.74 在 904px 宽、1124px 高里：

- 每行 **17 字**（904 ÷ 52）
- 每行高 **90.5px**（52 × 1.74）
- 单页最多 **12 行**（1124 ÷ 90.5 = 12.4）
- → **单段硬上限 204 字**（12 × 17）

所以分页时若用「230 字一段才拆」的估算规则，**230 字必溢出**：
230 ÷ 17 = 13.5 → 14 行 → 1267px > 1124，超出 143px。

| 页内情况 | 安全字数 |
|---|---|
| 纯正文单段 | ≤ 204 |
| 有页标题（71px + 26px 间距） | ≤ 187 |
| 两段并列（多一个 43px 段距） | 合计 ≤ 196 |

> 建议：分页不要用字数估算（`Phase 3` 会踩溢出），
> 直接搬 `docs/prototypes/xhs-text-card-v2.html` 的 `measureBlocks()` 探针实测——
> 它有真 iframe，量 `offsetHeight` 是准的，且不需要新依赖。

## 8. 照片 → 推荐构图 对照表

这一节回答的不是「构图长什么样」，而是**「搜到这张图，该选哪个构图」**。
它是 Phase 3「用户选完图自动推荐构图」的实现依据，也是本实验室的核心产出。

### 8.1 判定口径（三条必须同时成立）

1. **判定窗口固定 3 条带（=30% 画布 = 432px）**。
   104px 标题 + 36px 副标实际占 ~250px ≈ 1.8 带，取 3 带是保守值。
   用 2 带判定会漏掉「主标题在天空很漂亮、副标掉到山脊上糊掉」这种情况（实测踩过）。
2. **zone 是在构图给的范围里搜出来的，不是钉死的百分比**。
   C2 在 `y50–70%` 起搜、C3 在 `y0–30%` 起搜，取「对比度最高且最安静」的那个窗口。
   构图给范围，具体落点由这张图的实测决定。
3. **α 用 sRGB 精确式，上限 0.30；判不合格就不压**（压了是灰雾，不如换构图）。

### 8.2 矩阵（6 张真实照片 × 6 构图）

C1 / C4 / C5 / C6 四种构图的文字**不在图上**，所以对任何照片都**恒可用**，
不参与判定（这也是为什么它们必须保留在推荐列表里兜底）。

| 照片 | C2 全出血·底沉 | C3 全出血·顶压 | 推荐 |
|---|---|---|---|
| 夜街路灯 | ✅ 免压暗 9.2:1 @y60–90% | ✅ 免压暗 8.3:1 @y30–60% | **C2 / C3 都行** |
| 雾晨海边 | ✅ 免压暗 8.7:1 @y70–100% | ✅ 免压暗 4.5:1 @y0–30% | **C2 / C3 都行** |
| 山野秋千 | ❌ α0.33（超上限） | ❌ α0.56 | **Ⅲ 类全废 → C1/C4/C5/C6** |
| 台灯记忆 | ❌ α0.42 | ✅ 免压暗 4.5:1 @y0–30% | **只 C3 顶压** |
| 旧电话亭 | ✅ 免压暗 6.6:1 @y70–100% | ❌ α0.45 | **只 C2 底沉** |
| 旧照片堆 | ❌ α0.50 | ❌ α0.51 | **Ⅲ 类全废 → C1/C4/C5/C6** |

### 8.3 三个非显然的结论

**① 「能不能压字」不是照片的属性，是「照片 × 构图」的属性。**
`台灯记忆` 底部压不住（α0.42）但顶部能压（4.5:1）；`旧电话亭` 正好相反。
如果只在照片层面判一次「这张图能不能压字」，这两张图会被一起判死 ——
而它们各自都有一个完全可用的构图。**所以推荐逻辑必须是 6×N 的矩阵，不是 1×N 的黑名单。**

**② 「整图最大 sd」不能当 busing 判据，必须用「推荐区内的 sd」。**
按整图 sd > 0.15 判 busy：台灯记忆 0.186、旧电话亭 0.236 都会被判「交错」，
但它们在各自推荐区里的 sd 只有 **0.046 / 0.030**（干净得很）：

| 照片 | 整图最大 sd | 推荐区内 sd | 整图判 busy 会怎样 |
|---|---|---|---|
| 夜街路灯 | 0.147 | 0.010 | 否 → 正确 |
| 雾晨海边 | 0.084 | 0.010 | 否 → 正确 |
| 山野秋千 | 0.320 | — | 是 → 正确（确实无可用区） |
| **台灯记忆** | **0.186** | **0.046** | **是 → 误杀** |
| **旧电话亭** | **0.236** | **0.030** | **是 → 误杀** |
| 旧照片堆 | 0.253 | — | 是 → 正确 |

→ 正确做法：**先按构图搜出 zone，再算这个 zone 内的 sd**。
照片层面的 sd 只能用来做「要不要提示用户换图」的软判断，不能当硬门禁。

**③ 山野秋千是「换字色也救不了」的典型，说明必须做白/黑比较。**
它的天空极其干净（band 1–2 白字只有 1.0:1，但**黑字 12.6:1**），
而下方草地明暗交错（band 7–9 黑字 2.8:1、白字 2.7:1，两头都不达标）。
所以它的正解不是「找个带压字」，而是**要么用黑字压天空（只放标题、不放副标）、
要么直接换纸面构图**。任何「只会用白字」的实现都会把它判成废图。

### 8.4 落地伪码

```js
// 常量（全部来自实测，不要凭感觉调）
const TARGET_L = 1.05 / 4.5 - 0.05;        // 0.1833，白字 4.5:1 需要的背景亮度
const MAX_ALPHA = 0.30;                    // 超过就不压，改换构图
const ZONE_BANDS = 3;                      // 判定窗口 = 文字块实际占位
const ZONES = { c2: [5, 7], c3: [0, 3] };  // 构图允许的搜索范围（band 起点）

function alphaFor(maxL){                   // sRGB 空间解，不是 1 - TARGET/maxL
  if (maxL <= TARGET_L) return 0;
  const s = invLin(maxL), t = invLin(TARGET_L);
  return (s - t) / (s - 12);
}

function judge(bands, z0){
  const seg = bands.slice(z0, z0 + ZONE_BANDS);
  const maxL = Math.max(...seg.map(b => b.p99));   // 白字看最亮
  const minL = Math.min(...seg.map(b => b.p05));   // 黑字看最暗
  const cWhite = 1.05 / (maxL + 0.05);
  const cBlack = (minL + 0.05) / 0.05;
  const ink = (cBlack >= 4.5 && cBlack > cWhite) ? 'black' : 'white';
  const needA = ink === 'white' ? alphaFor(maxL) : 0;
  return { ink, needA, best: ink === 'black' ? cBlack : cWhite, sd: maxSd(seg) };
}

function recommend(bands, compId){
  const [lo, hi] = ZONES[compId];
  let best = null;
  for (let z = lo; z <= hi; z++){
    const j = judge(bands, z);
    const score = j.best - meanVariance(bands, z, ZONE_BANDS) * 8;
    if (!best || score > best.score) best = { ...j, z, score };
  }
  if (best.needA === 0)   return { ...best, verdict: 'free' };      // 免压暗
  if (best.needA <= MAX_ALPHA) return { ...best, verdict: 'tint' }; // 局部 scrim
  return { ...best, verdict: 'reject' };                            // 换构图，不要压
}
```

**三条不可违反的约束：**

1. **判不合格时不许偷偷换成「更浓的 scrim」**。只能换构图，并告诉用户为什么。
2. **判定窗口 = 压暗窗口 = 文字实际占位**，三者必须同源。改一个就要改另外两个。
3. **白/黑字必须比一次**。只实现白字的版本会把「亮天空 + 暗草地」这类图全判成废图。
