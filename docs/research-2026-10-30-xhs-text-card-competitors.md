# 小红书「文字卡」竞品调研与方案（2026-10-30）

> 状态：**调研定稿 + 可交互原型已跑通实测**，尚未并入产品代码。
> 原型：`docs/prototypes/xhs-text-card.html`（双击即可用，无需构建/服务）
> 结论先行：内页不该复用封面骨架，应新做「文字卡片」渲染器，正文 **44px 起步**（现 34px），
> 分页用**浏览器实测**（我们有真 iframe，比竞品的估算公式更准）。

**9/9 PASS**：完整性（421 字原文 = 421 字输出，逐块拼回一致）、无溢出、标题未落页尾、无重复块。

### 实测发现的两个真实结论

1. **44px 是最佳平衡点**：`mid @44` 每页 141 字、3 页，填充 96/96/70 —— 既看得清又不碎。
   52px 页数涨到 5、60px 涨到 7，字数掉到 60–85 字/页，碎片化明显。→ **默认 44，不默认大字号**。
2. **"合并优化"收益有限，但保留了**：贪心装页本身已接近满页，相邻页加起来必然超上限，
   所以合并只在"标题被搬走留下短页"这类场景触发（如 `long@44` 的 18% 页）。
   不指望它救所有留白，真正治留白的是**字号档位选择**（44 让每页装得满）。

## 3. 竞品共识（直接抄的排版标尺）

- **尺寸**：1080×1440（3:4），左右内边距 90px，可用宽度 ~900px
- **正文**：42–48px，行高 1.7–1.8，段距 30–35px → 每行 18–21 个汉字，每页 250–300 字
- **页内标题**：h1 72px / h2 56px / h3 48px；**页码** 36px 右下
- **结构**：封面 + 2–6 张正文卡 + （可选）尾页签名/CTA 卡
- **分页**：按渲染高度贪心装页；标题不落页尾（keep-with-next）；列表/代码块/图片整块迁移
- **主题**：封面与正文卡共用同一色板，封面竖向渐变、正文对角渐变

## 4. 方案：新「文字卡片」渲染器 cards.js

### 架构决策（与竞品的差异点 = 我们的优势）

竞品分页两条路：RedBookCards **估算高度**（公式猜，会错）、Auto-Redbook **Playwright 逐段重渲染**（准但慢）。
我们在浏览器里有真 iframe → **实测分页**：把块逐个 append 进测量容器量 `offsetHeight`，超了就封页。
准确且一次完成，不需要新依赖（截图仍走 modern-screenshot）。

### Phase 1：cards.js（核心）

1. **轻量块解析**（~100 行，不引 markdown 库）：标题 h1–h3 / 列表 / 引用 / 段落 / 分割线 / `---` 手动分页符
2. **实测分页**：贪心装页 + 三条保护
   - keep-with-next：标题后至少跟 2 行正文，否则标题一起搬下页（RedBookCards 定义了没实现，我们做上）
   - 图片/引用/代码块整块迁移不裁切
   - 单块超高时按标点回退拆段（抄 RedBookCards `_try_split_paragraph` 思路）
3. **文字卡版式**（新骨架，不是封面骨架）：正文 44px / 1.78 / 段距 34px；h2 64px；页眉放文章标题小字 + 页脚品牌/页码；色板继承用户所选封面色板（paper/ink/muted/accent 已在 catalog.js）
4. **字号档位**：标准 44 / 大 52 / 特大 60（显式回应"手机上看清"）

### Phase 2：接线

- story.js 内页改走 cards.js；封面仍走现有封面管线（单张封面逻辑零改动）
- UI：内页风格切换「文字卡（默认）/ 复用封面版式（旧）」+ 字号档位
- 可选尾页签名卡（默认关）

### Phase 3：门禁（产物级断言，不是「有反应」）

- 渲染 HTML 断言正文 `font-size ≥ 44px`
- **完整性断言**：正文的每个文本块都出现在某张内页里（拼回比对，杜绝截断）
- 每页 `scrollHeight ≤ 可用高度`（无溢出）

# 7. v2：版式系统（2026-10-30 第二轮，回应「要好看」）

> 用户反馈：v1「其他都挺好，就排版样式」——能用但不好看。
> 原型：`docs/prototypes/xhs-text-card-v2.html`

## 7.1 v1 的病根：所有页都是同一个 layout

查了小红书设计资料与项目自带的 `references/style-system.md`，v1 违反了多条硬规则：

| v1 的问题 | 违反的规则 | 出处 |
|---|---|---|
| 7 页全是一个版式（大标题+正文块） | ❌「不要所有页都用同一种 layout」「不能连续 3 页同一 layout」 | esther-design-system 绝对禁忌 |
| 引用块用「左侧彩色竖线」 | ❌「不要用左侧彩色竖线的卡片」「不要 HTML 默认 blockquote」 | 同上 |
| 列表是圆点平铺 | ❌「不要千篇一律列表（每项前一个圆点）」 | 同上 |
| 标题 weight 700 | ❌「the larger, the lighter」：大字必须 200–500，700+ 会退化成「信息图横幅」 | `references/style-system.md` L34/L130 |
| 正文 44px 但无层级 | 字号层级应在四级内且差距拉开 | youmind 内页规范 |

**结论：v1 不是「排版不好看」，是没有版式系统。**

## 7.2 v2 的解法：7 种页面角色

内容形态决定版式（不是选个好看的模板再塞内容）。角色由 `assignRoles()` 按每页内容自动判定：

| 角色 | 触发条件 | 视觉结构 | 参考配方 |
|---|---|---|---|
| **开篇 opening** | 首页 且 ≤90 字 | 短色条 + serif 大字引言（74px）+ 斜体副标 + 署名 | M01 / M13 |
| **清单 points** | 页内 ≥2 个列表项 | 右侧超大淡色数字（300px, opacity .10）+ 编号行 + 细线分隔 | M05 Checklist |
| **金句 quote** | 页内含 `>` 引用 且 ≤200 字 | 居中 78px 大字 + 背后 560px 淡引号 + 上下文小字 + 署名 | M04 Pull Quote |
| **步骤 steps** | 页内 ≥2 个「第一步/①/1.」 | 竖排编号圆 + 连接线 + 标题/说明双层 | M14 Vertical Pipeline |
| **对比 compare** | 两段并列正文 | 左 ✕ 右 ✓ 分栏（细线分隔，不用红蓝满底） | M15 Before/After |
| **正文 dense** | 其余 | serif 正文 + 段首小色条（**不做首字下沉**） | M03 Editorial Essay |
| **结尾 closing** | 末页 且 ≤160 字 | 色条 + 66px 结论 + 补充说明 + CTA + 超大页脚数字 | M07 Closing Note |

### 关键设计决策（都是踩坑后定的）

1. **大字版式必须有容量上限**（`BIGTYPE_CAP`）
   opening/quote/closing 只把文字合并成一段大字。若整页字数超上限却仍用这些版式，**必然丢内容**。
   → 超上限就退回 dense。这条约束是自检报错逼出来的。

2. **引用块不孤立成页**
   第一版把 `>` 引用单独抽一页 → 实测填充只有 **17%**，整页空荡。
   改为「引用当页内主体 + 同页段落作上下文」→ 填充 **93%**。

3. **中文不做首字下沉**
   硬做会把「两」「到」「那」放大成怪字（实测很丑）。改用 40px 小色条做段首锚点。

4. **列表整组成页**
   贪心装页会把列表塞进正文页，退化成圆点平铺。改为「连续 ≥2 个 li 优先独立成页」。

5. **装饰元素必须够重才看得见**
   金句页背后的大引号初版 `opacity:.055` 在暖纸底上**完全不可见**，提到 `.13` 才成立。

## 7.3 自检升级：从「数据结构」到「渲染产物」

v1 的自检比对的是**分页数据结构**，显示「315=315 通过」，但 opening 渲染时只取了前 60 字，
**实际画面丢了半页正文**——数据结构没丢，HTML 里丢了。

v2 改为从**渲染后的 DOM** 取文字比对（`textFromCardHtml()`），并逐块定位缺失：
- 完整性：原文每一块都必须出现在某张卡片的 `.body` 里
- 比对前两边都要先剥掉 `**bold**` / `==mark==` 标记（否则误报，实测误报 6 处）
- 无溢出 / 标题不落页尾 / 无连续 3 页同版式 / 字号 ≥28px

## 7.4 v2 实测结果（长篇 518 字 @44px）

| 页 | 角色 | 填充 |
|---|---|---|
| 01 | 正文（开篇） | 80% |
| 02 | 金句 | 83% |
| 03 | 正文 | 83% |
| 04 | 结尾 CTA | 24% |

- **4 页 · 3 种版式**，自检全绿（完整性 512 字 / 无溢出 / 无版式单调）
- 手机视角（375px）下正文清晰，等效字号 15.3px
- 末页 24% 是**刻意的**：结尾页本就该留白（M07 规范：结尾是「杂志文章收尾」，不是塞满）

## 7.5 风格与现有封面同族

8 套风格直接映射 `public/cover-templates/` 的色板（沙丘暖纸 / 森林墨绿 / 靛蓝瓷白 /
牛皮纸 / 午夜墨金 / 克莱因蓝 / 柠檬黄 / 安全橙），**封面用哪套、内页就用哪套**，
不会出现「封面暖纸、内页墨绿」的撞色。

瑞士系（克莱因蓝/柠檬黄/安全橙）自动切无衬线 + 去纹理 + 去圆角，遵守 Swiss 硬规则。

# 8. v3：字号与底图文字保护（2026-10-30 第三轮）

> 用户反馈两条：「文字和底图区分不开」「正文字体有点小，放手机看不清」。

## 8.1 字号：44 → 52（实测换算，不是拍脑袋）

1080 宽卡片在手机上按屏宽等比缩放，等效字号 = 卡片字号 × 屏宽 / 1080：

| 卡片字号 | 375px 屏 | 390px 屏 | 414px 屏 |
|---|---|---|---|
| 44 | **15.3** | 15.9 | 16.9 |
| **52（新默认）** | **18.1** | 18.8 | 19.9 |
| 60 | 20.8 | 21.7 | 23.0 |

微信正文通常 16–17px。**44px 在主流 375 屏上只有 15.3px，确实偏小** —— 用户反馈准确。
改默认 52（18.1px，略大于微信正文，适合图片场景）。

代价：长篇 518 字从 3 页变 4 页。这个代价值得——**宁可多一页，不能字小看不清**。

面板上每个档位都标了手机等效值（`52（18.1）`），用户不用自己算。

## 8.2 底图文字保护：三次迭代才找到正确做法

用户说「文字没有用阴影，和底图区分不开」。实测了三种方案：

| 方案 | 结果 | 判定 |
|---|---|---|
| ① 整页铺图 + 整页压暗 | 照片被压成**灰雾**（浅色图最明显），等于白放一张图 | ❌ |
| ② 图铺上半屏 + 正文下移到纸面 | 可用高度 1124→630，页数 3→7，图把版面吃掉了 | ❌ |
| ③ **刊头照片带 + 页眉条 scrim** | 照片清晰、文字清晰、页数基本不变 | ✅ 采纳 |

### 方案③ 的三个要点

1. **图只做「刊头照片带」**（顶部 0–520px，占 36%），正文起点 166→566，可用高度仍有 724。
   符合编辑式排版「照片作刊头」惯例（`style-system.md`：照片是证据，不是装饰）。

2. **scrim 只压页眉那一条（顶部 0–150px）**，下方照片完全不受影响。
   这才是 Material「局部 scrim」的本意：**只盖文字，不盖图**。
   峰值按底图亮度分级：浅色 0.62 / 高反差 0.55 / 深色 0.10。

3. **text-shadow 三层叠加**（`0 1px 2px` + `0 2px 8px` + `0 0 24px`）：
   单一投影在大图上不够；三层做「近处清晰 + 远处柔化」。
   只给照片上的页眉用，纸面上的正文不加投影（加了会让字发虚）。

### 一次走错路（记录在案）

我先试了「transform 缩放正文」来兜底有底图时的高度不足 —— 结果正文被压到 62%，
**字反而更小了，直接违背用户诉求**。正确做法是**在分页阶段就按 724 排**，
让页数自然增加，字号一个不变。

## 8.3 实测

| 场景 | 页数 | 版式 | 各页填充 | 自检 |
|---|---|---|---|---|
