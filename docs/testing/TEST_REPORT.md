## 五、工具评估（要不要加 Playwright）

**结论：不需要新增任何测试框架。**

现状：
- 已有 Python Playwright **1.64.1**，通过 `core/browser_utils.launch_browser` 走
  Chrome → Edge → bundled Chromium 回退链，实测用的是系统 Chrome。
- 已有 **61 个脚本**（`scripts/*.py`），门禁 22 个套件，覆盖相当完整。
- 未安装 Playwright bundled Chromium（`chromium-1248` 目录不存在）——这是**刻意**的（`AGENTS.md` 记载 183MB 国内会卡死）。

真正缺的不是工具，而是**断言的层次**：
现有套件大量断言停在「按钮可用 / toast 出现 / 元素存在」。
例如 `pwa_headed_full_e2e.py:530-532` 对「复制到公众号」只检查 `#toast` 是否可见，
**从不读剪贴板内容**。本轮补的 `qa_independent_e2e.py` 才第一次验证了
「剪贴板里真的有带内联样式的 text/html」——而这是本产品的核心交付动作。

建议（不是新增框架，是补断言）：
1. 把 `qa_independent_e2e.py` 的剪贴板断言并入门禁（成本极低，价值最高）。
2. 把「清除本地数据后 localStorage 必须无 supersu.* 残留」并入门禁。
3. 下载类断言统一改成「读文件字节/尺寸」，而不是「有 download 事件」。
