## 一、先修的真 bug（优先级最高）

### 1.1 实测复现

```python
# mg-time.json 的字段
['name', 'description', 'kind', 'locked_layout', 'colors', 'styles']
#                          ↑ 没有 layout 字段

# core/format_engine.py L2390
_layout = theme.get("layout")        # → None
if _layout == "card": ...
elif _layout == "hero": ...
elif _layout in LAYOUT_REGISTRY:     # None in {...} → False
```

```
grep -n "locked_layout" core/format_engine.py  →  0 处命中
```

**实测渲染**（`.venv/Scripts/python.exe` 直调引擎）：

| 检查 | mg-time 渲染结果 |
|---|---|
| h1 居中（`layout_time` 的核心特征） | ❌ False |
| 红细线（`layout_time` 的另一特征） | ❌ False |

**结论：15 套整篇设计的版式函数一次都没被调用过。**
用户选中「时代周刊」，只得到它的**配色和字号**，得不到它的**版式**。

### 1.2 影响面

| 对象 | 影响 |
|---|---|
| 15 套 `mg-*.json` | 全部只有皮肤、没有骨架 |
| 15 张 `kit-thumbs` 缩略图 | 15 张实际只有 **1 种骨架**，差异全在配色（见 `docs/wechat/kit-thumbs-audit.md`） |
| 164 套 `su-*.json` | **无影响** —— 它们本来就没有 `locked_layout` |
| 线上用户 | 选了 kit 但版式不生效，且**界面还告诉他「版式已锁定」**（误导） |

### 1.3 修法（最小改动）

在 `convert_markdown_to_wechat_html()` 入口处做一次归一化：

```python
# 若主题只有 locked_layout 没有 layout，视为 layout
# 必要性：mg-*.json 只声明 locked_layout（设计意图），而布局分发读 theme["layout"]
if not theme.get("layout") and theme.get("locked_layout"):
    theme = {**theme, "layout": theme["locked_layout"]}
```

**为什么放在入口而不是改 15 个 JSON**：
- 改 JSON 要动 15 个文件，且与 `design-kit-themes.md` §7 的「`locked_layout` 不复用 `layout`，避免被本机 `layoutOv` 覆盖」设计意图冲突
- 入口归一化是「运行时视图」，**不改数据真源**

**回归判据**：
- 164 套 `su-*` 无 `locked_layout` → 不进该分支 → **产物字节一致**（用 `theme_render_dump.py --diff` 验证零差异）
- 15 套 `mg-*` → 版式装饰出现（h1 居中、红细线等）

### 1.4 落地结果（2026-11-02 实测）

改动位置：`core/format_engine.py` 的 `convert_markdown_to_wechat_html()`，`json.load` 之后。

**A/B 验证（真实入口，不是 `theme_render_dump.py`）**：

| 指标 | 结果 |
|---|---|
| 主题总数 | 179（kit 15 / 非 kit 164） |
| 产物有变化 | **15 套（全是 kit）** |
| 产物无变化 | **164 套（全部非 kit）** |
| 结论 | **PASS —— 15/15 版式生效，164/164 字节不变** |

**单套实测**（`mg-time`，同一个样本）：
| 检查 | 修前 | 修后 |
|---|---|---|
| h1 居中 | False | **True** |
| 红细线（`#E3120B`） | False | **True** |

**缩略图差异度**（15 张两两对比，共 105 对）：
| 指标 | 修前 | 修后 |
|---|---|---|
| 平均差异 | — | **46.0%** |
| 最相似一对 | — | 18.9%（adidas vs forbes） |
| <5% 的「几乎一样」对 | 15 张只有 1 种骨架 | **0 对** |

**门禁**：`scripts/run_gates.py --quick` → **4/4 通过**。

> ⚠️ **踩坑记录**：`scripts/theme_render_dump.py` **不能**用于验证这次改动 ——
> 它走 `inject_inline_styles(md_to_html(MD), theme)`，**不经过**
> `convert_markdown_to_wechat_html()`，而归一化加在后者里。
> 用它跑会得到「0 套变化」的**假阴性**。真正的 A/B 要直接调入口，
> 并 monkeypatch 掉归一化做对照。

## 二、kit 体系的扩展规则（用户核心决定）

### 2.1 两类东西，物理隔离

```
public/themes/
├─ su-*.json     164 套  配色主题（无 locked_layout）  ← 不动
├─ mg-*.json      15 套  整篇设计（有 locked_layout）  ← 体系
└─ mg-<新来源>-*.json    后续采集的整套设计           ← 同一体系，同目录
```

**规则：凡是「配色 + 版式配套设计」的，一律进 `mg-*` 体系；凡是「只有配色、版式可自由组合」的，进 `su-*`。**

### 2.2 判定一条新采集的「是 kit 还是 palette」

| 判据 | kit（mg-*） | palette（su-*） |
|---|---|---|
| 版式是否写死 | ✅ 有 `locked_layout` | ❌ 无 |
| 能否自由换配色 | ❌ 配色配套 | ✅ 任意换 |
| 能否自由换版式 | ❌ 版式固定 | ✅ 任意换 |
| 是否带品牌识别符号 | 常有（三条纹/黄框/红序号） | 无 |

### 2.3 从 md2wechat 采集的 4 套，怎么归

**实测它的 4 套排版风格**（`设置 → 设计 → 排版风格`）：

| # | 名称 | 它的一句话描述 | 归类 |
|---|---|---|---|
| 1 | 技术编辑 | 清晰层级 · 克制留白 | 待定 |
| 2 | 理性技术 | 强对比 · 非对称秩序 | 待定 |
| 3 | 国际瑞士 | 统一对齐轴 · 非对称构图 | 待定 |
| 4 | 轻刊阅读 | 暖橙标题 · 松弛图文节奏 | 待定 |

**关键问题：它们属于哪一类？**

它自己的 UI 把「排版风格」和「文章配色」**分开**：

```
排版风格  4 款   ← 结构
文章配色  3 组   ← 只改颜色，不改结构（它自己写的）
背景风格  4 款   ← 独立组合
```

**这说明它的「排版风格」是结构 + 配色的套装** → 按我们的判据，**应归入 `mg-*` 体系（kit）**。

⚠️ **但需要现场看它的每套风格是否真的「结构不同」**，如果只是字号/间距差异、骨架相同，
那就该归 `su-*`（配色主题）。**这一步必须在采集时逐一核对，不能凭描述判断。**

### 2.4 命名规范（避免冲突）

```
mg-<来源>-<风格>.json
```

| 字段 | 规则 | 例 |
|---|---|---|
| `id` | `mg-` + 来源缩写 + `-` + 风格名 | `mg-m2w-tech` |
| `name` | 中文风格名（用户界面显示） | `技术编辑` |
| `source` | 来源站点（新增字段，仅在说明里用） | `md2wechat` |
| `kind` | 固定 `"kit"` | |
| `locked_layout` | 必须指向 `LAYOUT_REGISTRY` 里已有的键 | `time` |

⚠️ **`source` 字段**：现有 15 套 `mg-*` **没有**该字段（都是自研）。
新增采集的应带上，便于追溯来源与合规审查（`THIRD_PARTY_NOTICES.md` 要同步）。

## 三、UI 结构调整（用户 2026-11-02 的 UX 意见）

### 3.1 把「背景」从顶级 tab 降为二级

**用户原话**：「你新增了个 tag 是背景，我感觉不对，应该是在配色主题和整套设计下面的二级内容才是。」

**改法**：

```
改前：
  [配色主题 164] [整篇设计 15] [背景 4]   ← 三个平级 tab（错）

改后：
  [配色主题 164] [整篇设计 15]            ← 两个 tab 不变
       │
       └─ 下方可折叠「微调」区（默认收起）
            ├ 版式（8 项）
            ├ 段落样式（3 开关）
            ├ 背景（4 款）
            ├ 配色微调（三取色器）
            └ 正文字号（14–18px）
```

**理由**：这 5 项是**同一层的调整项**（对当前主题的微调），不该有任何一个升格为顶级 tab。

### 3.2 加顶栏「设置」入口（收容低频项）

用户已选：**顶栏齿轮 → 弹窗**。

```
顶栏：[S] SuperSu | 公众号排版 · 标题图 · 长图文 |  [引擎就绪] [导出] [AI] [⚙] [⋯]
                                                                        ↑ 新增
```

**设置弹窗内容**（低频操作，配一次就不再动）：

| 组 | 项 |
|---|---|
| **排版** | 正文字号、背景风格 |
| **内容** | 页尾（Markdown）、显示链接网址、首段作为导语、预览公众号标题 |
| **数据** | 备份/恢复本机数据、清除本地数据（从「⋯」迁入） |

**这样做的收益**：
- 抽屉只留高频（选风格 + 版式），不再密密麻麻
- 「⋯」菜单瘦身（只剩草稿/更新/关于）
- 低频项集中在一处，找得到

### 3.3 关于「弹窗」的取舍（符合项目历史）

HANDOFF §6.2 记着**「全弹窗版被否」**（用户原话「啥都弹窗了……因为要常常切换的」）。

所以原则是**按频率分家，不是全部弹窗**：

| 频率 | 放哪 | 例 |
|---|---|---|
| 高频（每次用） | 常驻 | 主题、版式、复制 |
| 中频（一篇一次） | 面板内可见 | 段落样式、字号 |
| 低频（配一次） | 设置弹窗 | 页尾、链接开关、数据管理 |

## 四、顺手要对齐的两件事

### 4.1 前端要认 `kit-thumbs/`

审计发现：`pwa/src/app.js:775` 的 `drawerCard()` **写死引用 `theme-thumbs/`**，
而 `theme-thumbs/manifest.json` 里**没有任何 `mg-*`** → 15 套 kit 的缩略图**前端根本没用上**。

**改法**：按 `kind === 'kit'` 切目录前缀：
```js
const dir = t.kind === 'kit' ? 'kit-thumbs' : 'theme-thumbs';
```

### 4.2 给缩略图脚本加「版式已生效」断言

现有 `gen_kit_thumbs.py` 的 `_guard()` 只保证**不丢字**，不保证**有版式装饰** ——
所以上面那个 bug 能一直藏着。

**加一条断言**（每个版式给一个可 grep 的特征）：
```python
LAYOUT_SIGNS = {
  'time': 'text-align:center',      # h1 居中
  'guardian': '44px',               # 大引号
  'economist': '01',                # 红序号
  'adidas': '三条纹相关标记',
  ...
}
# 缺失即失败，不再静默
```
