# 公众号排版页方案 B · 四段式抽屉（2026-11-02）

> **决策**：用户在 A/B/C 三方案对比后选定 **B**。
> **范围**：只改**风格库抽屉**（`.drawer`）的内部结构；**主界面、顶栏、色卡条一律不动**。
> **不做**：小红书标题图 / 长图文（用户明确「先搁置」）。
>
> 对比原型：`docs/prototypes/wechat/wechat-abc.html`（A/B/C 可切换，抽屉真实尺寸）
> 本方案原型：`docs/prototypes/wechat/wechat-v3.html`

---

## 0. 一句话

现在抽屉里「主题 / 整篇设计 / 版式 / 段落样式 / 自定义配色」五样东西平铺在一起，
用户不知道自己在改什么。改成**四段式**，每段回答一个问题：

```
① 我要什么风格？    →  179 套配色主题（按族浏览）
② 文章结构怎么排？  →  15 种版式，分「通用 8」+「报刊风 7」
③ 段落怎么强调？    →  金句 / 数据 / 提示 三开关
④ 配色微调          →  底色 / 正文 / 强调 三取色器
```

每段有编号圆点、一句人话说明、一个上限提示（如「179 套 · 按族浏览」）。

## 2. 目标结构

### 2.1 抽屉骨架（自上而下）

```
┌─ 风格库 ─────────────────────────────── [搜索…] [×] ─┐
│                                                      │
│ ●1  我要什么风格              179 套 · 按族浏览      │
│     [全部] [收藏 12] [公文] [节庆] [信笺] [素页]     │
│     [夜航] [钢印] [暮色]                             │
│ ─────────────────────────────────────────────────── │
│ ●2  文章结构怎么排                        15 种      │
│     通用                                            │
│     [默认] [图文节奏] [卡片流] [目录导航]            │
│     [杂志分栏] [首屏] [卡片组] [时间线]              │
│     报刊风 · 换任何配色都成立                        │
│     [报刊头条] [栅格] [专栏] [纪实]                  │
│     [时装] [榜单] [条纹]                             │
│ ─────────────────────────────────────────────────── │
│ ●3  段落怎么强调                    按内容自动识别   │
│     ☑ 金句 含引号   ☐ 数据 含数字   ☑ 提示 「提示：」│
│ ─────────────────────────────────────────────────── │
│ ┌─ 主题网格（可滚动，占剩余全部高度）─────────────┐  │
│ │ [卡] [卡] [卡]                                  │  │
│ │ [卡] [卡] [卡]                                  │  │
│ └─────────────────────────────────────────────────┘  │
│ ●4  配色微调  [底色■] [正文■] [强调■]  [恢复]        │
└──────────────────────────────────────────────────────┘
```

**与现状的差异**：① 新增编号圆点与副标题；② 版式分两组并补 7 项；
③ 段落样式从底部**提到第 3 段**（在网格之上，永远可见）；④ 自定义配色仍在底部（它是低频微调，留在原处合理）。

### 2.2 为什么第 4 段不提到上面

自定义配色是**低频、且会覆盖主题**的操作。用户的正常路径是「选一套主题」，
只有主题不满意才会去调三色。把它放在最底下 = 渐进披露；提到上面会诱导用户跳过选主题。

## 3. 版式命名（关键决策）

### 3.1 为什么不用原品牌名

引擎里的 id 是 `time / guardian / economist / natgeo / vogue / forbes / adidas`，
全部是**真实商标**。2026-10-29 项目刚因为「6 套品牌名主题」改名一次（当晚又回滚了，因为用户喜欢英文名）。但那次是**主题**（用户自己选的商品名），这次是**功能按钮** —— 用户在点一个叫「时代周刊」的按钮时，会预期它长得像《时代》，而实际它是「红细框 + 重点结论加框」这一个技法。

**功能按钮用技法命名，比用品牌命名更诚实、也更好找。**

### 3.2 命名映射（基于引擎里的真实配方）

| 引擎 id | 配方核心（`core/magazine_layouts.py` 实测） | 建议命名 | 备选 |
|---|---|---|---|
| `time` | 红色只做细框线；**重点结论加一圈细红框**；栏目名置顶 | **报刊头条** | 头条 / 框线 |
| `guardian` | 眉题 14px 红字 + 1px 浅灰线；**引用放大到 19px** | **眉题** | 导语 / 肩题 |
| `economist` | 红色序号「01」「02」+ 浅灰细线；**重点句 22px 加粗** | **编号专栏** | 序号 / 特写 |
| `natgeo` | 黄色编号 22px；左 4px 粗线 + 右 1px 细线；分隔线只画 52px | **画报** | 图册 / 纪实 |
| `vogue` | 整篇只有黑白；大标题 34px 宋体；斜体数字 52px | **画报大标** | 时装 / 时装刊 |
| `forbes` | 数字本身是主视觉，放大到 28–32px；黑白灰 + 一点深蓝 | **数字榜** | 榜单 / 数据刊 |
| `adidas` | 黑白高对比；**三条纹**；斜向动势 | **三条纹** | 硬边 / 斜切 |

> **命名原则**：说技法，不说品牌；说它「长什么样」，不说它「抄谁」。
> 用户搜「框」「序号」「三条纹」都能命中。

### 3.3 需要你确认

上表「建议命名」是我按配方拟的。如果你更喜欢备选列、或有别的想法，
改一个词的成本极低（`LAYOUT_OPTIONS` 里一个字符串）。

## 4. 逐段详细说明

### 4.1 第 1 段：我要什么风格

**保留现有族筛选**，但从一行 chip 改成**带计数的 chip**（现在已经有计数，保留）。

```
[全部 179] [收藏 12] [公文 24] [节庆 12] [信笺 24]
[素页 24] [夜航 12] [钢印 12] [暮色 12]
```

**新增**：右侧一句「179 套 · 按族浏览」，让用户知道总量和浏览方式。

**不变**：点族 chip 后，网格只显示该族；族视图隐藏族 chip（现状已实现，保留）。

### 4.2 第 2 段：文章结构怎么排

**分组依据**（已定的判据，可 grep、可进 CI）：

> **函数里写死品牌色的不进版式段** —— 换任何配色都会毁。
> **纯 accent 派生的才进** —— 换配色依然成立。

| 组 | 项数 | 成员 |
|---|---|---|
| 通用 | 8 | 默认 / 图文节奏 / 卡片流 / 目录导航 / 杂志分栏 / 首屏 / 卡片组 / 时间线 |
| **报刊风** | **7** | 报刊头条(time) / 眉题(guardian) / 编号专栏(economist) / 画报(natgeo) / 画报大标(vogue) / 数字榜(forbes) / 三条纹(adidas) |

**被排除的 8 个**（写死品牌色，只在 kit 里以整套形式出现）：
`muji / mori / ukiyoe / note / ikea / starbucks / brutal / deepread`

**分组标题的文案我建议写成**：

```
报刊风 · 换任何配色都成立
```

这半句解释为什么它们能自由组合，也暗示「上面通用组同理」。比只写「报刊风」信息量大。

### 4.3 第 3 段：段落怎么强调

**从底部移到第 3 段（网格之上）**，三个开关加一句人话说明：

```
☑ 金句 含引号     ☐ 数据 含数字     ☑ 提示 「提示：」开头
```

右侧提示：**「按内容自动识别」**（现状 `db-note` 的文案，保留）。

**为什么提到上面**：这是「排版效果」的直接开关，和版式同属「结构层」；
而配色属于「皮肤层」。现在它和「自定义配色」挤在一起，层级是错的。

### 4.4 第 4 段：配色微调

**保持现状不动**：底色 / 正文 / 强调 三取色器 + 恢复按钮。

只在段首加 `●4` 编号与「配色微调」标题，与前三段视觉统一。

### 4.5 kit 锁定态（D4 修复）

选了整篇设计（kit）后，**第 2 段与第 4 段都置灰**，并在第 2 段下方替换为一条说明条：

```
┌────────────────────────────────────────────────────┐
│ ⓘ 这是整篇设计，版式与配色已锁定                    │
│   它的结构和配色是配套设计的，改了就不成立。        │
│                              [改回可组合版式]       │
└────────────────────────────────────────────────────┘
```

**现状只有一行小字 + 一个按钮**，用户不知道为什么灰了。补一句「为什么」。

## 7. 顺带修的隐私缺陷（D6，独立提交）

`clearSupersuStorage()` 现在只删白名单里的 5 个键，而 `supersuKeys()` 实际扫出 18 个，
其中包含 `supersu.ai`（API Key）与 `supersu.cover.stock.v1`（Pexels Key）。

**修法**：改成**按 `supersu.` 前缀统一清除**，并建立键登记表（`supersuKeys()` 已有扫描能力，直接复用）。

**为什么单独提交**：它是隐私修复，和 UI 改动没有逻辑关系；混在一起会让回滚粒度变粗。

## 8. 回滚点

- **UI 改动**：`git revert <commit>` 即可，无数据迁移、无存储键变更。
- **版式新增**：只是往 `LAYOUT_OPTIONS` 加 7 行，删掉即回到 8 项。
- **段落下移**：`pwa/index.html` 里 `.drawer-blocks` 的位置改动，还原即可。

**无破坏性变更**：不删任何存储键、不改 `supersu.*` 命名空间、不动主题 JSON。

## 9. 明确不做（防止范围扩大）

| 不做 | 理由 |
|---|---|
| 主界面重排（方案 C） | 用户已选 B；换版式非最高频操作 |
| 版式条常驻预览下方 | 同上，且会吃掉预览高度 |
| 配色主题并入整篇设计 | 两者是不同层（皮肤 vs 皮肤+结构） |
| 小红书模块改动 | 用户明确「先搁置」 |
| 自定义配色提到上面 | 低频操作，渐进披露更合理 |
