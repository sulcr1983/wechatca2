## 零、本次定稿的三条边界（用户 2026-11-03 拍板）

这三条决定了后面所有工作的性质，先写在最前面：

| 边界 | 含义 | 由来 |
|---|---|---|
| **① 原型只做交互骨架** | 原型证明「点了会怎样」，**不写真实状态管理与持久化**。刷新后状态丢失是预期行为，不是 bug。 | 用户：「你怎么写代码？我们还在方案啊！」 |
| **② 先写方案文档，原型暂停** | 文档定稿后再谈实现，避免用原型反推实现方案。 | 同上 |
| **③ 一次只做一个模块** | 公众号排版先做完，小红书两个模块（标题图 / 长图文）搁置。 | 用户：「先做好这个，然后小红书其他两个模块再做」 |

**为什么边界 ① 重要**：v7 原型一度写进了 `localStorage` 持久化、真实 `toggleFav`、`applyBg` 优先级仲裁。
这些是实现决策，不是设计决策 —— 混进原型会让「评审界面」和「评审架构」搅在一起，
一旦架构要改，原型里那套逻辑就得跟着重写。**已全部降级**（收藏改为内存 `Set`）。

## 一、四项已定决策

四项均由用户用选择器拍板，**已定稿，实现阶段照此执行**。

### 1.1 配色微调：接通，且初值跟随主题

| | 内容 |
|---|---|
| **现状问题** | 设置弹窗里「底色 / 正文 / 强调」三个 `<input type="color">`，**全文件零监听、零读取**。用户能点、能选色，但预览毫无反应，且不报错。初值是写死的 `#FFFFFF / #134E4A / #FF0000`，切主题后不更新。属于「能点但没用」的假控件。 |
| **决策** | 改色实时应用到预览；初值从当前主题真实色值回填；提供「恢复」回原色。 |
| **交互规则** | ① 改色 → 立刻重绘预览，不需要确认按钮<br>② 切换主题 → 微调**自动清空**（微调是针对某套主题的临时覆盖，不该压在新主题上）<br>③ 整篇设计（kit）下**禁用** —— 配色是整套设计的一部分，与「背景」同一条规则<br>④ 底色微调优先于背景预设的底色（用户刚手动挑的颜色应盖过预设），但保留背景底纹图 |
| **色值来源** | `themes/index.json` 的 `background`（底色）/ `primary`（正文墨色）/ `accent`（强调色）。三个字段现成，无需改数据。 |

> ⚠️ 实现阶段注意：本项在原型里只是**骨架**（存在内存 `S.tune`），真实接线要落到 `pwa/src/app.js`。
> 落点见 §四。

### 1.2 收藏：复用现有实现，不另造轮子

| | 内容 |
|---|---|
| **事实** | **线上 PWA 早已有完整收藏功能**，`pwa/src/app.js` 里 `LS.fav`（键 `supersu.pwa.fav`）+ `favList()` + `toggleFav()` + 收藏筛选 + 收藏置顶排序，一应俱全。只是**未经测试**。 |
| **决策** | 原型的收藏交互对齐现有实现，**不设计第二套**。 |
| **原型的坑（已修）** | 星标 `<span class="d-fav">` 嵌在卡片 `<button data-th>` 内部，点星标会**顺带切换主题**。修法：点击处理里把 `[data-fav]` 排在 `[data-th]` **之前**并 `stopPropagation()`。线上存在同款结构，实现阶段要一并核验。 |
| **原型现状** | 内存 `Set`，刷新即清空（符合边界 ①）。 |

### 1.3 缩略图：卡片预览区改为 2:1，不裁图

| | 内容 |
|---|---|
| **问题** | 配色缩略图是 **480×240（2:1）**，卡片框原是 221×132（1.677:1）。`object-fit:cover` 会裁掉**左右各约 8%**，而缩略图的标题贴着左缘，有切字风险。 |
| **决策** | 卡片预览区改为 **2:1**，与缩略图原始比例一致，裁剪归零。整篇设计卡片为 **4:3**（其缩略图是 480×360）。 |
| **实现方式** | 用 `aspect-ratio` 而非写死高度 —— 列宽变化（两列 / 一列 / 移动端）时也不会重新裁切。 |
| **实测验证** | 改后：预览区 221×111，比例 2.0；缩略图 480×240，比例 2.0；**裁剪 0%**（改前 16.2%）。 |
| **代价** | 卡片比原来矮 22px，首屏可见行数略增（是收益，不是损失）。 |

### 1.4 版式条：8 项全显示

| | 内容 |
|---|---|
| **问题** | 底部版式条 `renderLayBar()` 用 `all.slice(0, 6)` 只露出 6 项，而抽屉里是 8 项。「卡片组 / 时间线」只在抽屉出现，用户会以为这两个功能不存在。 |
| **决策** | 版式条显示全部 **8 项**，两处一致。 |
| **8 项清单** | 默认 / 图文节奏 / 卡片流 / 目录导航 / 杂志分栏 / 首屏 / 卡片组 / 时间线 |
| **⚠️ 不要动的** | 这 8 项是**原有版式**，保持原样。19 套杂志版式**只属于整篇设计**（走 `locked_layout`），**不得**加进这张表 —— 否则同一个东西两个入口、两种名字。 |
| **实测验证** | 版式条渲染出 8 个按钮，顺序与抽屉一致。 |

> 背景说明：v5 曾把 md2wechat 借来的 7 个报刊风版式（朱丝栏 / 天头 / 鱼尾…）塞进版式区，
> 用户否决：「引擎和我们 15 套是不同的，我们 15 套这个是单独的」。已全部移除。

### 1.5 卡片标题条：深墨底白字（四轮才定）

**这是本项目最反复的一处，四版演进必须留档，否则会被第五次重做。**

| 版本 | 做法 | 用户反馈 |
|---|---|---|
| v1 | 12.5px / 500 灰字 + 3px 彩色竖线 + 一行 desc + 「整篇」徽章 + 米黄 tip-box | 「太 ai 了」 |
| v2 | 衬线编号 `01`–`19` + 衬线名字 + 两行 desc | 「只需要突出的标题」（否掉 desc 与编号） |
| v3 | 白底标题条 + 1px 细线 | 「区别还是不太明显」 |
| v4 | 白底 + 缩略图留白 + 投影 | 「区别还是不太明显」 |
| **v5（当前）** | **深墨底白字，两侧 tab 统一** | 已确认 |

**为什么 v3 / v4 怎么调都没用（实测数据）**：

```
缩略图底部平均色  rgb(243,243,242)   ← 整篇缩略图本身就是纸白文章预览
标题条底色        rgb(255,255,255)
                    明度对比  1.11 : 1   ← 两张白纸贴在一起
分隔线 #EAE6DD    on #FFFFFF
                    明度对比  1.25 : 1   ← 等于没画
```

结论：**问题从来不是线的深浅或字的粗细，而是「白图 + 白条」之间不存在明暗差。**
在同一块白面上叠阴影也只是两层修饰，边界依然靠不住。反白是唯一一次到位（15:1）的做法。

**最终规格（两 tab 共用，`pwa/src/style.css` 同改）**：

```css
.d-body{ padding:10px 12px; background:var(--color-foreground); border-top:0; }
.d-name{ font:700 15px/1.3 Georgia,'Songti SC','SimSun',serif;
         letter-spacing:.02em; color:#F7F4EE; }   /* 白字压深墨 */
.d-fav { color:rgba(247,244,238,.55); }            /* 星标必须跟着变浅 */
.d-fav[data-on="1"]{ color:#E8A08C; }              /* 已收藏：浅朱砂 */
```

⚠️ **三个易错点**：

1. **底色用 `--color-foreground`（墨 `#191713`）不是纯黑** —— 保留暖调，与暖纸朱砂体系一致。
2. **`.d-fav` 必须同步改浅** —— 星标原为 `--color-muted-fg`，压在深墨上几乎不可见。
3. **删掉 v4 的缩略图留白与投影** —— 黑条边界已经够硬，再叠投影就是脏。缩略图恢复满幅。

| | 内容 |
|---|---|
| **统一范围** | 配色主题 164 套 + 整篇设计 19 套，**两侧完全一致**（用户 2026-11-03 选「两边都改」）。 |
| **唯一差异** | 只有缩略图比例不同：配色主题 2:1、整篇设计 4:3（因源图尺寸不同）。 |
| **实测验证** | 两侧 tab 截图核对，标题条同为深墨底、白字 15px/700；`node --check` 语法通过。 |
| **备选（已否决）** | B 浅暖灰底（发闷显脏）、D 朱砂短横（分离度够但弱于反白）。对比页 `kit-title-abc.html` 已删除。 |

## 二、本轮实测修掉的三个 bug

原型阶段不是只画图 —— 下面三个是**真 bug**，已在 v7 原型里修掉，并留下验证数据。

### 2.1 【严重】164 张卡片全部重叠

**现象**：配色主题网格看起来像「细条纹」，卡片被压扁。

**根因**（不是视觉错觉）：

```
.d-grid 的 gridTemplateRows = 1.33333px × 82 行
卡片实际高度               = 176px
相邻两行 top 差            = 17.5px
```

`.d-grid` 是 `flex:1` 的 flex 子项，高度被父容器钉死，网格自动行被压成 `1.33333px`，
**82 行全挤在 422px 里**，而卡片本身 176px 高 —— 每张卡片都覆盖着后面 10 张。
之前所有「图片被压扁」的判断都是这个 bug 的症状。

**修法**：`.d-grid` 加 `grid-auto-rows:max-content`（配合已有的 `align-items:start`）。

**验证**：

| | 修复前 | 修复后 |
|---|---|---|
| 行高 | 1.33px | **176px** |
| 行距 | 17.5px | **192px**（176 + 16 gap） |
| 滚动高度 | 1596px | **15776px** |

### 2.2 空态文案会指错方向

切到「整篇设计」tab 后搜索一个不存在的词，提示「缩略图未生成，先跑 `scripts/gen_kit_thumbs.py`」——
但**19 张缩略图一张不缺**，实际是搜索没命中。这会让人去跑一个根本不需要跑的脚本。

**修法**：区分两种空态 —— 搜索没命中（提示「清除搜索」，可点）／缩略图真缺失（提示跑脚本）。

### 2.3 页面标题写死旧套数

`<title>` 里是 `179 套`，实际 `183 套`。已改为 v7 并显示 183。

> 这类数字属于**活数据**，实现阶段不要手写在第 UI 里，应从 `themes/index.json` 现算。

## 三、界面结构（已定，不再讨论）

### 3.1 抽屉：两个并列 tab

```
风格库
├─ [配色主题 164 套 · 换皮不换骨] [整篇设计 19 套 · 成套的稿子]
```

- **配色主题**：164 套，按族浏览，可自由组合版式 → 「换皮不换骨」
- **整篇设计**：19 套，配色 + 版式成套设计，`locked_layout` 锁定 → 「成套的稿子」

两者**平行**，不是上下级。用户原话：「我们新增的 4 套应该归入这个 15 套里面，
以后去其他同类网站采集到的都是这样单独处理。和之前的分开。不影响之前的。」

### 3.2 频率分层：高频常驻，低频进弹窗

> ⚠️ **2026-11-03 修订（用户拍板）**：本节早期把「字号」归到低频弹窗，
> 与 `design-kit-system-v2.md` §3.3 的频率表**自相矛盾**（那张表把字号列为「中频 · 面板内可见」）。
> 用户已定：**字号回归抽屉常驻**，理由见下。文档以本节为准。

| 位置 | 内容 | 理由 |
|---|---|---|
| 抽屉内（高频 / 中频） | 配色主题 / 整篇设计 / 版式 / 段落强调 / **字号** | 每次排版都要动 |
| 顶栏 ⚙ 弹窗（低频） | 背景 / 配色微调 / 页尾 / 内容开关 / 数据 | 设置一次管很久 |

**为什么字号不进弹窗**：调字号是「边看效果边试」的动作。抽屉开着时预览仍然可见，
拖滑块就能看到结果；塞进设置弹窗就变成「开齿轮 → 调 → 关 → 看」四步，试错成本高。
这是 §3.3 频率表原本的结论，早期文档写错了。

**为什么不是「全部塞进抽屉」**：v3 的四段式抽屉 4 段并排，用户评价「很乱」。
低频项留在一个弹窗里，抽屉就只剩「选什么风格」这件事。

**为什么不是「全部进弹窗」**：HANDOFF 记录过全弹窗版本被否决。

### 3.2.1 字号的作用范围（2026-11-03 用户拍板）

| 项 | 决定 | 依据 |
|---|---|---|
| 管辖元素 | **正文一组 = 段落 `p` + 列表 `li` + 引用 `blockquote`** | 主题里三者同为 15px 一档，只改 `p` 会让列表比正文小一号、同段文章里割裂 |
| 标题 | **h1–h6 按同一比例缩放**（`ratio = 字号 / 15`） | 保持层级关系不被破坏；h1 22 / h2 18 / h3 16 是设计好的阶梯 |
| 基准 | 15px = 主题原值，`ratio=1` 时产物与不设字号一致 | 保证默认态零回归 |
| 范围 | 14–18px（滑块 + `−`/`+` 步进 + 重置） | 对标 md2wechat；20 会被夹到 18，不是 bug |
| 提示文案 | 同时显示正文与标题的**实际 px**（如「15 px · 标题 22 px」） | 避免用户「拖了没感觉」|

> 早期 `engine/benchmark-md2wechat.md` B-2 建议「只改 `p`」，当时已标注风险但未定；
> 现已由用户改为正文一组，**以本节为准**。

### 3.3 背景降级为二级（用户纠正）

用户：「你新增了个 tag 是背景，我感觉不对，应该是在配色主题和整套设计下面的二级内容才是。」
→ 背景不再是一级 tab，改为设置弹窗内的一个区块。

### 3.4 手机外壳必须保留

预览区永远是 `420px` 的 `.phone-shell`（圆角 + `shadow-lg` + 40px `.wx-nav`「‹ 标题 ⋯」），
**不允许**把 HTML 直接铺在画布上。真实实现见 `pwa/src/style.css` 的 `.phone-shell`。

> 用户原话：「我们原来的预览有个手机外壳的边框的，不是直接展现的，有个边框，不会很难看」

### 3.5 顶栏两个菜单：按线上完整还原（2026-11-03 用户定）

原型早期只有 `⚙ / 导出 / AI / ⋯` 四个**装饰性死按钮**，线上 `pwa/index.html` 其实有两套真实菜单。
用户选「全部按线上还原」，现已补齐：

| 按钮 | 菜单 id | 项数 | 内容 |
|---|---|---|---|
| `导出 ▾` | `#menu-export` | 4 | 长图 PNG / HTML 文件 / Markdown / 图片 ZIP |
| `⋯` | `#menu` | 8 | 导出与分发 / AI 工具 / 恢复草稿 / 清空草稿 / 备份·恢复本机数据 / 清除本地数据 / 更新记录 / 关于·源码 |

**交互约定**（照线上）：两个菜单互斥、点外面收起、`aria-expanded` 同步；
`⋯` 里的「导出与分发」不是执行导出，而是**打开导出菜单**。

**「备份 / 恢复」「清除本地数据」在设置弹窗里也有一份** —— 这是有意的：
「⋯」是全局操作入口，设置弹窗的「数据」段是排版场景下的就近入口，两处都成立。

### 3.6 死按钮一律给最小反馈（2026-11-03 用户定）

用户：「全部接上最小反馈（toast 或状态变化）」。原型里不存在「点了没反应」的按钮：

| 按钮 | 原型行为 |
|---|---|
| 插图 / 搜图 | toast 说明线上能力（本地上传 / Pexels 联网搜图需 Key） |
| 看示例 | 载入 `SAMPLE` 并同步字数与预览 |
| 清空 | 清空输入区；已空时提示「已经是空的了」 |
| 复制到公众号 | toast（原型不写剪贴板） |
| 导出四项 / ⋯ 八项 | 各自 toast，菜单关闭 |

## 六、原型使用说明

打开 `docs/prototypes/wechat/wechat-v7.html`（需本地静态服务，仓库根目录起服务后访问）。

**它是交互骨架，不是成品**：

- ✅ 能看的：两 tab 切换、183 套真缩略图、族筛选、搜索、收藏星标、版式切换（8 项）、
  字号（抽屉 4 号位，正文一组 + 标题同比例）、设置弹窗、配色微调联动、
  顶栏导出菜单（4 项）与「⋯」菜单（8 项）、内容区四个按钮的最小反馈
- ❌ 不做的：状态持久化（刷新即重置）、真实排版引擎渲染（预览是简化的 DOM，不是引擎产物）、
  真实上传/联网搜图/剪贴板写入
- 数据来源：`docs/prototypes/data/themes-index.json`（从构建产物拷贝）+ `public/theme-thumbs/*.jpg`
  + `docs/prototypes/data/mg-*.jpg`（19 套整篇设计缩略图，由 `scripts/gen_kit_thumbs.py` 跑真引擎渲出）

**已在浏览器实测过的行为**（2026-11-03）：

| 项 | 实测结果 |
|---|---|
| 导出菜单 / ⋯ 菜单 | 4 项 / 8 项；互斥、点外收起、`aria-expanded` 同步 |
| 字号 15→18→14→15 | p/li/blockquote 同步 15/18/14/15；h1 22/26/21/22；h2 18/22/17/18 |
| 字号上下限 | 14px 时 `−` 自动禁用；20 被夹到 18 |
| 抽屉结构 | 4 段：我要什么风格 / 文章结构怎么排 / 段落怎么强调 / 字号 |
| 字号位置 | 在抽屉内，**不在**设置弹窗 |
| 布局 | 1280 / 1920 宽均无横向溢出（`docScrollW == innerW`） |
