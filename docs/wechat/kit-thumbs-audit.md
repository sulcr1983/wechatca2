# 整篇设计缩略图质量审计（public/kit-thumbs/ 15 张）

审计日期：2026-11-02　范围：`public/kit-thumbs/mg-*.jpg`（480×360）
用途：抽屉「整篇设计」tab 的卡片预览（卡片约 230×148px）

---

## 0. 结论先行

**这批缩略图目前无法反映版式差异。** 15 张图里**没有任何一张**出现该套设计本该有的版式装饰
（居中大标题、眉题、序号、线条、框、大引号、三条纹、硬阴影等）。肉眼能区分的只有
**底色 / 字体是否衬线 / 列表圆点颜色 / h1·h2 字号**这几项——它们全部来自 `mg-*.json` 的
`colors` 与 `styles` 字段，**不是版式**（版式实现在 `core/magazine_layouts.py`）。

所以「15 套整篇设计」在抽屉里看起来像「同一套模板换了 15 个配色」，与产品主张
（每套是一套独立版式）直接矛盾。

尺寸问题排第二位：**480×360 本身够用**（见 §3），真正的病根是渲染链路没接上版式。

## 2. 相似组清单与根因

### 2.1 「几乎一样」的分组

| 组 | 成员 | 组内肉眼差异 | 判定 |
|---|---|---|---|
| **A. 纯白无衬线组（最严重，6 张）** | `mg-time`、`mg-guardian`、`mg-economist`、`mg-ikea`、`mg-starbucks`、`mg-adidas` | 仅 h1 字号 24/28/24/24/24/26px + 圆点颜色（红/红/红/蓝/绿/黑）。h1 左对齐、h2 左对齐、圆点列表、底部引用——**骨架完全一致** | **无法区分**，只有圆点颜色可当线索 |
| **B. 彩色底 · 同骨架组（3 张）** | `mg-muji`、`mg-mori`、`mg-note` | 底色米白 / 浅绿灰 / 浅蓝灰；圆点色酒红 / 深绿 / 蓝。骨架同 A 组 | **只能靠底色区分**，属「换配色」而非「换版式」 |
| **C. 衬线组（2 张）** | `mg-ukiyoe`、`mg-vogue` | 一个米底一个纯白；都衬线；h1 26 vs 34px | **弱区分**（字体差异 ≠ 版式差异） |
| **D. 大字号组（2 张）** | `mg-brutal`（36/28px）、`mg-forbes`（26px） | brutal 明显更大更黑 | **中等**；但两者的设计语言（硬阴影海报 vs 数字驱动）一个都没表现出来 |
| **E. 单例** | `mg-natgeo`（黄圆点）、`mg-deepread`（暖褐字） | — | 各自靠一个色彩点缀勉强立足 |

**归零结论**：15 张按「结构骨架」归类，实际只存在 **1 种骨架**；差异全部落在
「颜色 + 字体族 + 字号」这三个**主题层**维度上，而**版式层贡献为 0**。

### 2.2 根因（三层，从直接到根本）

**根因 1（决定性）：`locked_layout` 没有被引擎当成 `layout` 读取。**

- `public/themes/mg-*.json` 声明的是 `"locked_layout": "time"`（见 `mg-time.json:5`、`mg-vogue.json:5` 等）。
- 但版式分发的判据是 `layout`：`core/format_engine.py:2390` 处 `_layout = theme.get("layout")`，
  紧接 `elif _layout in LAYOUT_REGISTRY: html = LAYOUT_REGISTRY[_layout](html, theme)`（:2403-2404）。
- `mg-*.json` **没有 `layout` 字段** → `_layout` 为 `None` → `None in LAYOUT_REGISTRY` 为假
  → **版式函数一次都没有被调用**。
- 而 15 个版式函数其实都已实现并注册：`core/magazine_layouts.py:1099-1115` 的 `MAGAZINE_LAYOUTS`
  含 `time/guardian/economist/natgeo/vogue/forbes/muji/mori/ukiyoe/note/ikea/starbucks/adidas/brutal/deepread`
  共 15 个键，并在 `format_engine.py:3196` 用 `LAYOUT_REGISTRY.update(MAGAZINE_LAYOUTS)` 合并进注册表。
- `convert_markdown_to_wechat_html()`（`format_engine.py:3416-3440`，正是 `gen_kit_thumbs.py:66` 调用的入口）
  只是 `json.load` → `md_to_html` → `inject_inline_styles`，**全程没有 `locked_layout` → `layout` 的归一化**。
  同样，`load_theme()`（`format_engine.py:131-141`）也是原样返回 JSON 内容。

> 一句话：**实现写好了、注册好了，但从来没被触发过。** 缩略图忠实记录了「版式没生效」。

**根因 2（放大问题，即使修好根因 1 仍然存在）：SAMPLE 不含触发多数装饰的元素。**

`scripts/gen_kit_thumbs.py:48-61` 的 SAMPLE 只有 h1 / 一个普通段 / 两个 h2 / 无序列表 / 引用。
多套设计最抢眼的识别符号却依赖样本里没有的元素：

| 缺哪种元素 | 谁会因此看不出特色 |
|---|---|
| 图注（以 `↑` `图` `注` 开头的段落） | Vogue（头顶细线）、时代周刊（灰色小号图注） |
| 带单位的数字（`30%` / `3 倍`） | 福布斯（数字即主视觉，30px） |
| `###` 三级标题 | 深度阅读（h3 前 ✦） |
| `**粗体**` 强调句 | 经济学人（重点句放大 22px + 红左线）、阿迪达斯、深度阅读（高亮）、笔记纸（荧光底） |

合计约 5 套：**即便补上 `layout` 唤醒，这些符号仍会留在画框之外。**

**根因 3（不在「图片质量」范畴但直接影响这批图有没有用）：前端卡片没引用 `kit-thumbs/`。**

- `pwa/src/app.js:775` 的 `drawerCard()` 写死 `src="./theme-thumbs/${t.id}.jpg"`。
- `public/theme-thumbs/manifest.json` 的 164 条里**不含任何 `mg-*`**。
- 因此卡片会请求 `theme-thumbs/mg-*.jpg` → 404 → 退化到 `.d-fallback` 色块占位。
- 也就是说，`kit-thumbs/` 这 15 张图**当前不会被用户看到**（app.js 里没有按 `kind === 'kit'`
  切换目录前缀的逻辑）。

## 3. 480×360 够不够？

**够用，不建议为「看得更清」去提高分辨率。** 理由：

1. **瓶颈不是像素，是内容。** 现存 15 张在 480×360 下已经把「h1 位置 / h2 位置 / 列表样式 /
   引用样式」全部读出来了——问题是这些信息本身就是空的（同一骨架）。版式一旦接通，480×360
   足以承载：1 个 h1（24–36px）+ 1 段正文 + 2 个 h2 + 2 条列表 + 1 个引用块（含 44px 大引号），
   纵向约 300px，装得下。
2. **卡片只有 230×148px。** 缩略图在卡片里按宽度约 230px 显示时，480px 宽只缩到约 0.48 倍，
   h1 24px 在卡片上约 11.5px，仍可读。提到 960×720 不会带来可辨收益，只会让文件变大
   （当前 18–24KB，已经很轻）。
3. **4:3 是正确取舍，不要退回 2:1。** `gen_kit_thumbs.py:39-42` 已记录 240px 高只装得下标题、
   15 套会被裁得一样的实测教训。本次审计再次印证：**截图高度每少一分，套与套之间就少一个可见差异点。**

**结论**：维持 **480×360 / JPEG q82**，不提高尺寸。
若要增强「版式可辨度」，把预算花在**样本内容**（§4 建议 2），而不是像素。
可选微调：1px 细线、letter-spacing 这类细节在 q82 下容易被压糊，**把 quality 提到 88–90** 比放大尺寸更划算。

## 4. 修复建议（按性价比排序；本文档不改代码与图片）

1. **【必须】补 `layout` 归一化。** 在 `load_theme()` 与 `convert_markdown_to_wechat_html()` 读到 JSON 后加一步：
   若存在 `locked_layout` 且无 `layout`，则 `theme["layout"] = theme["locked_layout"]`。
   这一处修完，15 套的版式装饰会一次性出现在缩略图上——**收益最大、改动最小**。
   （需同时确认 PWA/Pyodide 侧走的是同一入口，避免只在本地生效。）
2. **【强烈建议】扩充 SAMPLE，覆盖各套识别符号。** 在现有 h1/h2/列表/引用之外补：
   一段 `**重点结论**`、一段含 `30%` 的句子、一行以 `图：` 开头的图注、一个 `### 小标题`。
   ⚠️ 加完必须重跑并**逐张复查是否被裁**（360px 高度是硬约束，加内容可能把引用挤出画面）。
3. **【必须确认】前端接上 `kit-thumbs/`。** `drawerCard()` 需按 `t.kind === 'kit'`
   把目录前缀切到 `kit-thumbs/`，否则这 15 张图永远不会被渲染（当前落到 fallback 色块）。
4. **【锦上添花】给生成脚本加「版式已生效」自检。** 现有 `_guard()`（`magazine_layouts.py:262`）
   只保证「不丢字」，不保证「有装饰」，所以静默失效能一直藏着。建议生成后断言该套的特征串存在
   （如 guardian 的 `观点` 眉题、vogue 的 `font-size:52px`、natgeo 的 `52px` 短黄线），
   缺失就报错而不是安静地出一张平图。
