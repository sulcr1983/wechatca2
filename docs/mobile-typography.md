# 移动端排版规范（375px 微信阅读）

> 本文是 `core/format_engine.py` 里「移动端归一」那几段代码的说明书。
> 判据都能用 `python scripts/audit_mobile_typography.py` 复跑验证，改代码前后各跑一次。

## 0. 一句话结论

公众号文章 90% 在手机上读，可视宽度 375px、正文区约 343px，且微信里**页面不能横向滚动**。
所以排版的第一原则不是「好看」，而是**在 343px 里不崩**：
标题不折成锯齿、长链接不撑破版面、图注看得清、表格不被裁。

## 2. 为什么是这几条（依据）

- **长标题不能居中**：居中只适合 1–2 行的短标题；一旦折行，每行起点都要重新找，
  两侧参差会让阅读变累。《写给大家看的设计书》里对居中的评价是「正式但乏味」。
  通行做法是「标题超过两行就左对齐」（站酷/UI 设计排版经验文、135 编辑器排版规范均同结论）。
- **正文参数本项目已在规范内**：业内推荐正文 15–16px、行高 1.75–2.0、段距 20px、
  字距 1–1.5px、两侧留白 10–16px。实测 164 套：正文 15px（100%）、行高 1.65–2.0、
  段距 16–24px、wrapper 16px —— **不需要改**，所以本轮只动「会崩」的项。
- **不要首行缩进**：新媒体排版共识（135 编辑器/微信服务市场），手机屏一行放不下几个字，
  缩进纯属浪费。本项目本来就没有缩进，保持。
- **两端对齐（justify）在中文里可接受**：124 套用 justify，中文等宽字不会出现英文那种「河」，
  只要不断词就没问题。**不改**。
- **图注是正文的配角，但不能低于可读阈值**：13px `#999` 在白底上只有 2.85:1 对比度，
  低于 WCAG AA（正文 4.5:1），户外几乎读不清。改为 `#6B7280`（约 5.0:1）；暗底用 `#A1A7AE`。

## 3. 怎么覆盖（主题作者）

- `public/themes/*.json` 顶层加 `"heading_align": "design"` → 该主题**完全不做** R1/R2/R3，
  保留设计师写的原样（R4–R7 仍生效，它们只是防崩，不改观感）。
- 想给某套主题单独留居中色块标题：同上，用 `heading_align: "design"` 即可，不需要改引擎。

## 4. 怎么验证

```bash
python scripts/audit_mobile_typography.py            # 静态层，秒级，可当门禁（有 FAIL 返回 1）
python scripts/audit_mobile_typography.py --browser   # 加 Chrome 实测：页宽 / 折行 / 表格宽度
python scripts/theme_stress_audit.py --only render   # 164 套渲染审计（已内置 M6/M8 断言）
```

报告落在 `output/mobile-audit/report.json`（每套主题逐项 issue）。

## 5. 已知取舍

- **刊头类（vogue / 社论报 / 信笺 / 素页…）保留居中**：这是设计语言，短标题居中才有「刊头」感。
  只有放不下时才自动左对齐；中间态（两行但估算说放得下）用 `text-wrap:balance` 兜。
- R3 是**估算**：984 个样本里 981 个判断正确（3 个「居中但仍折行」出现在卡片类主题）。
  实现取舍是「宁可提前左对齐，也不让长标题居中折行」，因为前者只是风格变化，后者是阅读障碍。
- 表格 5 列以上时，即使内边距压到 16px 仍可能拥挤；这是微信正文宽度的物理限制，
  建议内容侧把表格压到 4 列以内（或拆成两张表）。
