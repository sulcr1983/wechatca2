## 二、修复计划（按「值不值得现在做」排序）

### P0-1 锁死依赖版本，并把 `requirements.txt` 的定位写清

**问题本质**：不是「文件该不该留」，是「构建产物的 Python 依赖没有版本契约」。`markdown.zip` 是构建产物，它的行为由 `.venv` 里那个版本决定，而 `>=3.5` 允许 3.11/3.12/4.0 随便进。

**改什么**
1. `requirements.txt`：`>=` → `==`，按当前**已验证可用**的版本钉死（markdown 3.11.2 / pillow 13.0.0 / playwright 1.64.1 / requests 2.34.2 / platformdirs 4.13.5 / python-dotenv 1.2.4；flask 3.1.3 单独一段标「本地弃用版仅参考」）。
2. 文件头加一段注释：**「本文件服务于本地脚本 + PWA 构建（markdown 打进 dist/py/markdown.zip）；Flask 已弃用但仍需可装」**，杜绝下一个人再提「移进 legacy」。
3. 把 `build.mjs:284` 与 `engine.worker.js:123` 注释里的「markdown 3.10」改成实际版本，避免注释与事实不符。

**验收**：`pip install -r requirements.txt` 幂等无变化 → `node pwa/scripts/build.mjs` 通过 → `python scripts/run_gates.py` 10/10。
**成本**：15 分钟。**风险**：低（只改声明，不改代码逻辑）。

---

### P0-2 把「密钥自查」变成永久门禁断言

报告这条本身是「看一眼就行」，但看一眼的价值只有一次。真正值钱的是让它**以后不用再看**。

**改什么**：`pwa/scripts/build.mjs` 的 `assertDist()` 里加一条——遍历 dist 文本文件，命中 `sk-[A-Za-z0-9]{16,}` / `Bearer [A-Za-z0-9._-]{20,}` / `api_key: '<20+>'` 就让构建失败（允许白名单：`ai.js` 的 placeholder 文案）。
**验收**：故意塞一个假 key 进 `src/`，构建必须红；删掉后必须绿。
**成本**：20 分钟。**风险**：低（假阳性可在白名单里加）。

---

### P1-1 复制前兼容性预检（把「事后告知」改成「事前拦截」）

**现状**：用户点「复制到公众号」→ 复制成功 → toast 说「还有 3 张外链图不会显示」。用户已经粘进后台了才发现。
**改什么**：`app.js:748 copyRich()` 开头先跑 `scanExternalImages(lastHtml)` + `data:image` 检测，有问题则**先弹确认**（「正文有 3 张外链图 / 2 张内嵌图，公众号里不会显示。仍要复制？」→ 继续 / 先本地化 / 取消），确认后才写剪贴板。`toastAfterCopy()` 保留作兜底。
**验收**：构造 3 种正文（纯文本 / 带外链图 / 带 data URI）走一遍复制，提示与实际一致；有头套件不回归。
**成本**：40 分钟。**风险**：低（纯前端分支）。

---

### P1-2 本地多稿库（补「素材暂存」的真缺口）

**现状**：单槽 `supersu.pwa.draft`，写第二篇就把第一篇覆盖掉，`restoreDraft()` 只能恢复最后一篇。
**改什么**：`LS.draft` 从单键升级为 `supersu.pwa.docs`（列表 + 当前 id），UI 加一个「稿件」抽屉（新建 / 切换 / 重命名 / 删除 / 最近更新时间）。数据仍全在本机，不联网、不上传。
**边界**：本期**不做**跨设备同步、不做云端；老数据做一次性迁移（旧 `draft` → 首篇）。
**验收**：新建 3 篇 → 来回切换内容不串 → 刷新后仍在 → 迁移后老草稿不丢。
**成本**：2–3 小时。**风险**：中（动草稿主路径，必须有迁移兜底 + 有头回归）。

---

### P1-3 封面与排版主题联动

**现状**：封面 10 套模板色板写死在 `catalog.js`；排版 164 套主题各有一套主色。做完一篇拿到封面，颜色对不上是常态。
**改什么**：封面页加一个「跟随当前排版主题」开关（默认关，避免打乱现有习惯）。开启后从 `supersu.pwa.theme` 取当前主题的 `primary/accent/background`，覆盖模板色板；只覆盖颜色，不动版式与字体。
**验收**：切 3 套对比度差异大的主题（浅底深字 / 深底浅字 / 高饱和），封面渲染色与主题一致且文字可读（不能白底白字）。
**成本**：2 小时。**风险**：中（深色主题 + 深色模板要保证对比度；需加一层亮度兜底）。

### P2（可选，先量化再决定）

**P2-1 引擎运行时预热**：现在 `boot()` 挂在 `requestIdleCallback(timeout 2500)`（`app.js:118-122`），首访 12MB 要等空闲才开始下。可选做法：SW `install` 完成 shell 后**再**空闲预取 `/runtime/*`，让二次访问「打开即有」。但会与首屏抢带宽，**建议先埋点量出真实首访耗时分布，再决定做不做**——不做也不影响现状（CacheFirst 已保证二次访问秒开）。

**P2-2 图片粘贴 → 本地素材 → 导出可用**：textarea 改成「粘贴即插占位 + 素材库」，渲染时替换为 data URI。**价值只在长图/HTML 导出**，公众号直贴仍然不生效（平台限制，改代码绕不过）。建议排在 P1 之后，或直接不做。
