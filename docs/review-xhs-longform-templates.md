# 对抗性审计：小红书长图文模板策略

> **审计对象**：`docs/requirements-xhs-longform.md`、`docs/plan-xhs-longform-next.md`、
> `docs/prototypes/xhs-longform-plan.html`（本轮交付的三件套）
> **审计人立场**：产品经理，按第一性原理追问「用户要的到底是什么」，不替自己的方案辩护。
> **审计日期**：2026-11-03。所有数据来自当前源码实测。

---

## 1. 结论先行

用户原话：「**模板都是千篇一律，只是改了个颜色，没有啥意义**」。

**这个判断成立。** 而且真相比表述更严重 —— 问题不是「模板不够多」，
而是**产品把仓库里最贵的资产（19 套真杂志版式）闲置着，另造了一套只有装饰差异的模板**。

三句话概括审计结果：

1. **12 套长文模板的差异都在「皮肤」上，没有一处是「骨相」**：零分栏、零首行下沉、
   零图文混排。换模板等于换页眉文字 + 换页脚格式 + 换纸色。
2. **我上一轮交的方案把力气用错了方向**：主目标是「一屏看全 12 套」，
   这等于**让用户更高效地浏览雷同的东西**。陈列问题解决了，价值问题没碰。
3. **正面资产就在自己仓库里**：`core/magazine_layouts.py` 有 19 套
   （Time / Guardian / Economist / NatGeo / Vogue / Forbes / MUJI / 森 / 浮世绘 / 宜家 / 星巴克 / adidas / 野兽派 / 深读 / 科技 / 理性 / 瑞士 / 轻），
   1457 行，有真分栏、序号系统、引文块、装饰线体系。**长图文模块完全没用它。**

## 2. 证据：12 套模板到底差在哪

### 2.1 量化

| 指标 | 实测值 |
|---|---|
| 12 套模板的专属 CSS 规则总数 | **81 条**（另 `.card.swiss` 14 条）= 95 条 |
| 这些规则的总字符数 | **4532** 字符 |
| 每套平均规则数 | **6.8 条** |
| 最少 / 最多 | 极简留白 **2 条** / 大厂文档 **12 条** |

### 2.2 这些规则改的是什么

按属性出现次数排序（81 条规则内）：

| 属性 | 次数 | 性质 |
|---|---|---|
| `right` / `top` / `bottom` / `z-index` | 20 / 12 / 12 / 13 = **57** | **装饰元素的定位** |
| `letter-spacing` | 8 | 字距（刊头文字） |
| `font-weight` | 7 | 字重 |
| `justify-content` | 5 | 页眉页脚排布 |
| `line-height` / `height` / `color` / `font-size` | 4 / 4 / 4 / 2 | 细部 |
| **`column` / `columns`** | **0** | — |
| **`float` / `::first-letter`** | **0** | — |
| **`display:grid` 用于正文分栏** | **0** | — |

**结论**：57/95 的规则在摆装饰元素的位置。**没有一条规则改变文字的编排结构。**

### 2.3 代码结构：所有模板共用同一个排版器

```js
// cards.js: cardInner({ role, blocks, tpl, pal, index, total })
// 内部按 role 分支（cover/opening/points/quote/dense/closing），
// tpl 只用于两件事：tpl.cls（CSS 命名空间）、tpl.head() / tpl.foot()（页眉页脚 HTML）
```

也就是说：**一篇文章怎么分段、每页放几句话、标题多大、正文多宽 —— 12 套完全一样**。
模板只能在「页眉写什么」和「页脚怎么排」上做文章。

### 2.4 精准区分：这些是「拟物道具风」，不是「杂志版式」

| 模板 | 实际做了什么 | 属于 |
|---|---|---|
| 苹果备忘录 | 模仿 iOS 备忘录界面（圆角白卡 + 横线纸 + 「完成」按钮） | 拟物道具 |
| 大厂文档 | 模仿 macOS 窗口（三个圆点 + CONFIDENTIAL） | 拟物道具 |
| 电影胶片 | 模仿胶片遮幅（齿孔 + KODAK 编号 + DIR. 横线） | 拟物道具 |
| 拍立得 | 模仿宝丽来相纸（胶带 + 白边） | 拟物道具 |
| 效率笔记 | 模仿 Notion 面包屑 | 拟物道具 |
| 杂志编辑 / 瑞士网格 | 有真正的刊头与网格线，但正文仍是单栏同宽 | **半版式** |

**拟物道具风解决的是「看起来像某个熟悉的软件」，不解决「一篇文章怎么排得好看」。**
小红书用户要的是后者 —— 他要的是「像我认真设计过的一页」，不是「像我截图了备忘录」。

## 3. 对抗性审计：我上一轮的方案错在哪

按严重程度排序。**这些是我自己方案的问题，不是用户的。**

### S-1（严重）主目标选错了：把「陈列」当「价值」

`plan-xhs-longform-next.md` §0 把「12 套模板看不全」列为 ① 号问题，
B1 批次（真实缩略图 + 一屏全见）是最大的投入项。

**问题**：一屏看到 12 套雷同模板，比滚动看 12 套雷同模板**唯一的区别是更快地失望**。
陈列优化只有在「容器里装的是真有差异的东西」时才产生价值。**顺序反了。**

正确的顺序是：先让模板有差异 → 再让差异可被高效浏览。
我把第二步做完了，第一步没做。

### S-2（严重）在错误的问题上做优化

需求文档 §6 C-4 花了一整条讨论「12 套要不要分 3 组（纸感/暗夜/强背景）」。
按 §2 的数据：分组维度是**装饰属性**。给雷同的东西分组，只是把雷同分门别类。

### S-3（中）原型在放大错误

`xhs-longform-plan.html` 做得越精致（12 套真渲染缩略图、一屏全见、撤销、出片托盘），
**用户越容易误以为「模板问题已经解决」**。原型是工业设计的漂亮外壳，里面是同一台发动机。

### S-4（中）需求台账漏了最上游的一条需求

`requirements-xhs-longform.md` §2 收录了 8 条用户原话，**但没有一条关于「版式要有真差异」**。
因为历史原话里确实没有 —— 这是这次才明确提出的。台账缺了这类需求，说明它只是「历史需求的汇总」，
没有接住「用户现在才说出口的那句」。

### S-5（中）把「拟物风」当成了版式资产

台账 §5.3 只写「12 套模板整套生效」，没有区分这 12 套里 5 套是拟物道具、只有 2 套算半版式。
数量 12 给人的错觉是有 12 种设计。

### S-6（轻）LF-TPL-7「模板搜索/分组」是典型的伪需求

12 个条目不需要搜索。把搜索当成需求，是在为「数量不够、差异不足」打补丁。

### S-7（轻）对「12 套是否够」没有判断标准

台账和计划都只有「12 套」这个数字，没有「多少套算够」的判据。
原因是**没有定义「一套模板」的差异维度** —— 没有维度就只能数个数。

## 4. 被闲置的资产：19 套真杂志版式

`core/magazine_layouts.py`（1457 行）的 `MAGAZINE_LAYOUTS` 注册表：

```
time / guardian / economist / natgeo / vogue / forbes / muji / mori / ukiyoe /
note / ikea / starbucks / adidas / brutal / deepread / tech / rational / swiss / light
```

**它具备长图文模板缺的东西**：

| 能力 | 实现位置 | 长图文有吗 |
|---|---|---|
| 真双栏正文（table 模拟，微信兼容） | `format_engine.py:3102 _layout_magazine` | ❌ |
| 小节序号系统（红色「01」「02」徽章） | `layout_economist` | ❌（长文只有页码） |
| 重点句结构级放大（22px + 左红线） | `layout_economist` | ❌ |
| 装饰线体系（细线 / 双线 / 条纹） | `thin_rule` / `double_rule` / `stripes` | ❌ |
| 小标题独立成块（骨架级） | `wrap_block` | ❌ |
| eyebrow 小标签 | `eyebrow()` | ❌ |
| 大字引文块 | `big_quote()` | 部分（quote 角色） |
| 首字下沉 | — | ❌（**两边都没有**） |

> ⚠️ 注意：**两边都没有首字下沉**。这是中文排版的常见手法，但也是一个可以立刻加、
> 视觉收益极高的东西（`::first-letter` + 中文需特殊处理）。

**这是本次审计最重要的发现**：产品不缺「做杂志版式」的能力，缺的是**把这个能力接到长图文上**。

## 6. 硬约束：手机上不能照搬杂志双栏

这是实施前必须钉死的技术事实，否则会做出「印刷好看、手机上没法看」的东西。

现产品卡片是 **1080 × 1440**，正文 **52px**（门禁断言 ≥28px，实测 dense 页 171 字）。

- 单栏：可用宽约 900px → 52px 中文 **17 字/行**，171 字 ≈ 10 行，合理。
- **双栏**：每栏约 440px → 52px 中文 **8 字/行**。一个 20 字的句子要折 3 行，
  段落节奏完全碎掉，**不可读**。

**所以正确的做法不是「把 Economist 的双栏搬过来」，而是提取杂志的「编排语法」，适配单栏竖屏**：

| 杂志手法 | 能否直接搬 | 竖屏适配做法 |
|---|---|---|
| 双栏正文 | ❌ 不可读 | **不做正文双栏**；只在「清单/对照」这类短句场景做两列 |
| 首字下沉 | ✅ 直接可用 | `::first-letter` 放大 3 行高，中文需单独调字号 |
| 引文块 | ✅ 可用 | 已有 quote 角色，可加大字号与留白 |
| 小节序号 | ✅ 可用 | 红色/描边数字徽章，比现在的页码强 |
| 装饰线体系 | ✅ 可用 | 细线/双线/条纹，成本极低、观感提升大 |
| 图文绕排 | ❌ 复杂 | 改为「图占整宽 + 文字在下方」的块级关系 |
| 网格与留白节奏 | ✅ 可用 | 真正能让「像设计过」的，是这个 |

## 7. 重构：定义「一套模板」的差异维度

问题根源是**没有定义维度**，所以只能数数量。建议用下面这个矩阵定义版式身份：

### 维度 A · 图文关系（5 种）
无图（纯排印）/ 上图下文 / 图满幅压字 / 图右侧窄栏 / 图片作为分节符（每 3 页插一张）

### 维度 B · 排印骨架（6 种）
单栏正体 / 首字下沉 / 首行缩进+两端对齐 / 段落悬挂缩进（清单感）/ 双栏（仅短句场景）/ 网格错位

### 维度 C · 视觉语法（影响「像不像设计过」）
- 序号系统：无 / 页码 / 数字徽章 / 大号描边数字
- 标题层级：单级 / 眉标+主标 / 章节号+主标+副标
- 引文处理：无 / 左侧竖线 / 大字号居中 / 反白块
- 装饰：无 / 细线 / 双线 / 角标 / 出血色块
- 留白节奏：密（每页 170 字）/ 中（120 字）/ 疏（80 字，配大留白）

### 维度 D · 纸色与质感
现有 8 套色板 + 纸纹。**这是最弱的一个维度，也是现在唯一的维度。**

**用法**：一套模板 = 从 A/B/C/D 各选一项的组合。
12 套雷同 = 只在 D 上变化。至少有 **5 × 6 × 数种 × 8** 的组合空间，
**不需要造 240 套，而是选 8–12 套差异最大的组合**（差异最大的标准：A 或 B 至少有一项不同）。

## 8. 输入形态：你提的「弹窗」是对的，而且仓库里已经有

你提到「输入文章是弹窗的，比现在的小窗口更好看」。**`docs/prototypes/xhs-canvas-ux.html` 里已经有现成实现**：

- 常驻**文章条**：标题 + 「309 字 · 自动分 5 页」+ 「编辑全文」
- 点「编辑全文」→ **88vh 全屏层** + 遮罩，`.art-full` 大字号 textarea，底部「取消 / 完成」
- 位置：`xhs-canvas-ux.html:1810 openArticleEditor()`

**设计文档给了实测理由**（`design-xhs-canvas-ux.md` §2.4）：

> 实测 300 字占 284px，画布只剩 473px。改成文章条后画布回到 554px（+17%）。
> 整篇文章要看的时候点「编辑全文」升一个 88vh 的全屏层 —— **读改和看图是两件事，不该抢同一块空间**。

⚠️ **一处必须澄清的历史**：同一份文档第 15 行记录你当时的原话是
「**又极简过头了，啥都弹窗了**」。
这句否决的是「**所有东西都弹窗**」（版式、配色、字体都藏进弹层），
**不是否决「长文编辑器用全屏层」**。§2.4 恰恰是那次否决之后改出来的方案 —— 高频控件常驻、
只有「整篇文章」这个占地最大、频率最低的东西升级成全屏层。

你现在说弹窗更好看，与 §2.4 的结论**一致**，不矛盾。

## 9. 建议的路线（三选一，需你拍板）

### 路线 1：把 19 套杂志版式迁到长图文，重新定义 12 套（推荐）
- **做法**：以 `magazine_layouts.py` 的 19 套为「设计意图来源」，在 `cards.js` 里实现
  对应的**手写分页器**（长文要分页，不能直接套用连续流）。剔除纯装饰的拟物套，
  保留/强化有编排逻辑的（Economist / Vogue / NatGeo / MUJI / Time / 瑞士 / 深读 / 野兽派）。
- **成本**：中。每套要写分页器变体，但不是从零 —— 现有 `buildLong` 的装箱逻辑可复用。
- **风险**：低（无新依赖、无 license 问题）。
- **局限**：不做真双栏（见 §6）。

### 路线 2：引入 Paged.js 重做渲染管线
- **做法**：`@page` + `break-*` 交给 Paged.js 分页，版式用 CSS 写，
  每个 `.pagedjs_page` 截图出 PNG。
- **成本**：高（换掉 `buildLong` 和 `cardInner` 整套）。
- **风险**：中。Paged.js 设计目标是 PDF，PWA 里截图稳定性未验证（尤其 iOS Safari）。
- **收益**：可以写出「真正的流式排版」，未来加版式成本极低。

### 路线 3：保留现管线，只补「版式维度 A/B」
- **做法**：不动分页器，在 `cardInner` 里加「图文关系」和「排印骨架」两个维度（§7 的 A/B）。
- **成本**：低。
- **收益**：中等 —— 能立刻拉开差异，但受限于现管线只能做单栏。

**我的建议是路线 1**：它复用了自家已验证的资产，成本可控，且直接命中「杂志设计感」这个诉求。
路线 2 是正确方向但风险与成本都更高，适合作为中期演进。
