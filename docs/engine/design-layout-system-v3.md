## 1. 实证结论：差在哪（72 套 vs 我们 164 套）

| 维度 | 句方便 72 套 | 我们 164 套 | 结论 |
|---|---|---|---|
| 标题内嵌装饰子元素 | **20 套（28%）** | **0 套** | ★ 最大差距 |
| `h1` 字号跨度 | 20 – **56px**（Jony Ive 56、Hische 52、苹果极简 48） | 22px 全仓统一 | 我们没有"大字报" |
| 正文行高 | 1.58 – **2.5**（原研哉·空 2.5、黑金 2.0、故宫红墙 2.0） | 1.75–1.9 | 我们不敢留白 |
| 正文对齐 | 左对齐 38 / 两端对齐 33 | 两端对齐 123 / 左 40 | 人家更爱左对齐 |
| `h1` 用 `border-left` | **13/72** | h2 有 69/164 用左竖条 | 我们把"左竖条"用滥了 |
| `h2` 底块+圆角 | 8 套 | 56 套有 h2 色块 | 数量够，缺的是别的 |
| 硬投影（`box-shadow` 无模糊） | 新粗野 / 孟菲斯 | 只有钢印族的软阴影 | ★ |

**一句话**：我们的差距不在"有没有色块/边框"，而在
① **标题里能不能塞一个装饰块**，② **敢不敢把字号和行高拉开**。

## 3. 方案：**不动现有版面，只加能力**

> 你的要求原话：「你不要改动我现在的公众号版面设计吧，但是要增加更多的版式」

所以本方案的硬约束是：

> **现有 164 套主题的渲染产物逐字节不变。** 新能力全部是"主题没声明就完全不生效"的可选钩子。

### 3.1 三层能力（在 V2 基础上修正钩子清单）

```
第 1 层 · 皮肤 Skin     现有 164 套 JSON      ← 一个字不改
第 2 层 · 装饰 Hooks    kicker / titleMark / h2Badge / quoteDeco   ← 新增，默认空
第 3 层 · 版式 Layout   现有 8 个 + 新增 4 个 → 共 11 个（§4）
```

**第 2 层是本次的核心**（上一轮我低估了它）。它解决的是"同样一个色块标题，为什么人家好看"：

| 钩子 | 主题 JSON 里怎么写 | 渲染器怎么用 | 不写时 |
|---|---|---|---|
| `kicker` | `"title_kicker": "FT · ANALYSIS"` | 塞在 `<h1>` 第一个子元素 | 空 → 不产出 |
| `titleMark` | `"title_mark": "bar"\|"dots"\|"gradient"` | `<h1>` 末尾插装饰 span | 空 → 不产出 |
| `h2Badge` | `"h2_badge": "solid"\|"bracket"\|"plain"\|"big"` | `<h2>` 开头插编号 | 空 → 不产出 |
| `quoteDeco` | `"quote_deco": true` | 引用首尾加引号字形 | 空 → 不产出 |

**为什么用枚举字符串而不是让主题写任意 HTML**：
主题 JSON 是数据，塞任意 HTML 进去等于把 XSS 面开到主题文件里。
枚举 → 渲染器查表产出固定安全的 HTML。想加新样式就加枚举值，一个函数一处。

### 3.2 同时放开被锁死的两个数值

| 现在 | 改为 | 依据 |
|---|---|---|
| `h1` 字号 22px | 允许主题声明 20–56px | 句方便 Jony Ive 56 / Hische 52 / 苹果极简 48 都是靠这个 |
| 正文行高 1.75–1.9 | 允许 1.6–2.5 | 原研哉·空 2.5 / 黑金 2.0 / 故宫红墙 2.0 |

⚠️ **但默认值不动** —— 只有主题显式声明才改。这是"不改现有版面"的具体含义。

## 6. 长图文方案（补齐）

### 6.1 现状（实测）

| 事实 | 值 |
|---|---|
| 模板数 | 12 套（`cards.js` 的 `LONG_TPLS`） |
| **页面角色** | **只有 5 种**：`opening` / `dense` / `points` / `quote` / `closing` |
| 12 套的差异 | 页眉页脚 + 纸纹；**正文区 12 套共用 `@@S@@:where(.card .body p)`** |
| 内页能放图吗 | **不能**（`image` 只在 `role==='cover'` 传入） |

所以翻一套长图文，**读到的是同一份排版，只是纸变了**。

### 6.2 方案：角色 5 → 10

| 新增角色 | 结构 | 自动触发条件 |
|---|---|---|
| **目录页** `toc` | 章节导航 + 页码 | 小节 ≥ 3 且预计页数 ≥ 6 |
| **双栏论证页** `split` | 标题 + 两栏对照 | 该段有两组并列短段落 |
| **编号塔** `ledger` | 大编号 + 短条目逐行 | 该段是 ≥ 3 条的清单 |
| **数据页** `stat` | 超大数字 + 一行说明 + 进度线 | 段首出现「87%」「3 倍」这类数字断言 |
| **引语页** `pullquote` | 整页只有一句大字 + 署名 | 引用段落 ≥ 1 且字数 ≤ 40 |

> **不做「图文页」**：内页放图要先解决图片来源与公众号图床，属另一个功能（§10）。

### 6.3 长图文的装饰钩子

与公众号共用 §3 的 `kicker` / `h2Badge`，长图文额外需要：

| 钩子 | 作用 |
|---|---|
| `pageNo` 样式（已有） | 页码（`01 / 06`、`P. 01`、`SCENE 01`） |
| `sectionKicker` | 每页顶部的小标签（`CHAPTER 01` / `FIELD NOTES`） |

### 6.4 关键前置修复（必须排在新增角色之前）

`pwa/src/cover/cards.js` 的 `palOf(k)` **读全局 `state.pal`**，不读传入的 `o.pal`。
这是本项目**已犯 6 次**的同一个 bug（`HANDOFF.md` §7.4）。不先修，新角色必然全同色 —— 会是第七次。

## 9. 必须补的两条产物级断言

1. **版式真的不一样**：同一夹具 × 同一皮肤，跑两个版式，HTML **结构指纹必须不同**。
   反向验证：版式函数换成 identity → 必须失败。
2. **钩子真的生效且不污染**：
   - 主题声明 `h2Badge` → `<h2>` 内出现编号 `<span>` 且原文标题文字不丢
   - 主题**不声明** → 产物与今天的 dump **逐字节一致**

第 2 条的后半句比前半句重要：它保证「不改现有版面」这句话是有证据的。

## 10. 明确不做

| 不做 | 原因 |
|---|---|
| 改动现有 164 套的渲染结果 | 你明确要求「不要改动现在的版面设计」。默认值全部不动 |
| 删除任何原有版式 | 只做合并（两套引擎实现都保留） |
| 自动配图 / AI 识图 | 你判定「没啥意义」；且公众号不认外链图 |
| 长图文内页放图 | 需先解决图片来源与微信图床，另一个功能 |
| 主题里写任意 HTML | 枚举查表，避免把 XSS 面开进主题数据 |
| 照搬句方便的 CSS 数值 | 只借鉴**手法**；色值/文案/命名自拟（与我们既有的版权路线一致） |
