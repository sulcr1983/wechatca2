## 1. 必须先纠正：项目里那条「data URI 会被拒」的结论

### 1.1 原文说的是什么

`pwa/src/images.js:5-8`：

> ⚠️ 平台事实（2026-10 查证）：微信公众号编辑器粘贴富文本时**只认公众号图床 URL，
> 拒绝 data: URI**。所以内嵌图对「导出 HTML / 长图 PNG / 离线留档」有效，
> 对「直接粘贴到公众号」无效——那条链路必须由用户在素材库手动上传。

`pwa/src/app.js:350` 同样：
> 事实：公众号编辑器粘贴富文本只认公众号图床，**拒绝 data: URI**。

### 1.2 实测反证

我在句方便（seneasy.cloud）的工作台**劫持了 `navigator.clipboard.write`**，
点「复制到公众号」，拿到它实际写入剪贴板的内容：

```json
{
  "types": ["text/html", "text/plain"],
  "text/html__size": 755383,          // 755 KB
  "imgTags": 19,                      // 正文里 19 个 <img>
  "dataUriImgs": 19,                  // 其中 19 个是 src="data:image/..."
  "httpImgs": 0                       // 0 个外链
}
```

同时它 UI 上出现：
- 「**已复制，可粘贴到公众号编辑器。**」
- 「正在处理 4/4 张图片…」（逐张转 base64 的进度）

**结论：`data:` URI 图片是可以随富文本粘进公众号的。** 我们那条注释是错的。

### 1.3 我们原来错在哪

| 我们的写法 | 事实 |
|---|---|
| 「只认公众号图床 URL，**拒绝 data: URI**」 | ❌ data URI **可以** |
| 「对『直接粘贴到公众号』无效」 | ❌ 有效 |
| 「必须由用户在素材库手动上传」 | ❌ 不是必须 |

**真实差异不在「能不能」，而在「我们没做」**：我们的 `copyRich()`（`app.js:845`）只写 `text/html` + `text/plain`，**复制前没有把外链图转成 data URI**。而 `ensureLocalizedForExport()` 只在**导出**时被调用（`app.js:1615/1623/1632`），复制链路从不调用它。

> ⚠️ **这是本轮最重要的发现**：不是平台限制，是我们漏了一步。
> 原来的注释把「我们没做」写成了「平台不让」，导致这个能力被永久放弃。

### 1.4 需要保留的边界（别从一个极端跳到另一个）

data URI 有真实代价，方案里必须处理：

| 约束 | 数值 | 来源 |
|---|---|---|
| 单图上限 | 8 MB | `images.js:17` |
| 单次上限 | 40 张 | `images.js:18` |
| 单次总量 | 60 MB | AGENTS §4「批量导出图片」 |
| 剪贴板实测体量 | 755 KB（19 张图） | 句方便实测 |

**19 张图 = 755 KB，说明它做了压缩**。我们若直接塞原图 base64，可能几 MB 甚至几十 MB，
粘贴时会卡。**必须压缩**，见 §3。

## 3. 方案 A：复制时自动内嵌图片（把「我们没做」补上）

### 3.1 改法

```
copyRich() 现在：
  wrapped = lastHtml
  → 写剪贴板

copyRich() 改成：
  1. 扫描 lastHtml 里的外链图
  2. 有 → 逐张抓取 + 压缩 + 转 data URI（带进度提示）
  3. 全部转完 → 写剪贴板
  4. 提示「已复制，含 N 张图；粘贴到公众号会自动上传」
```

**关键：不能照抄 `localizeImages()`**。它现在是「原图直转」，不压缩（`images.js:118`）。
755 KB / 19 张 ≈ 40 KB/张，说明对方压过。

### 3.2 压缩规格（建议）

| 参数 | 值 | 理由 |
|---|---|---|
| 最大宽度 | 1080px | 公众号正文显示宽度上限 |
| 格式 | JPEG q=0.82 | 照片类；PNG 只留带透明的 |
| 单张目标 | ≤ 150 KB | 19 张 ≈ 2.8 MB，可接受 |
| 单次总量 | ≤ 8 MB | 超过就提示「图太多，建议用长图导出」 |

用 Canvas 压缩，不需要新依赖（`export.js` 已在用 Canvas）。

### 3.3 ✅ 已验证通过（2026-11-01 晚，用户实测）

> **结论：公众号接受 data URI 内嵌图。**

验证方式（可复现）：

| 步骤 | 内容 |
|---|---|
| 1 | 生成测试页 `output/paste-test.html`：真实照片压到 **105KB**（宽 720 / q=75）→ `data:image/jpeg;base64`，外面包 `<section style="line-height:0">` |
| 2 | 用户在浏览器全选该段富文本 → `Ctrl+C` |
| 3 | 粘贴到公众号后台「新建图文」正文区 → `Ctrl+V` |
| 4 | **结果：图片正常显示，文字样式（字号/行距/颜色/引用底块）一并带过去** |

**用户回复：「成功」。**

这条同时排除了两个备选解释：
- ❌ 「句方便可能有服务端转存图床」——我们完全没有服务端，纯前端 data URI 也成功了
- ❌ 「公众号会拒绝 data URI」——旧的注释结论确实错了

> ⚠️ **需要修正的三处旧注释**（都写着「公众号拒绝 data URI」）：
> `pwa/src/images.js:5-8`、`pwa/src/app.js:350`、`pwa/src/app.js:986`。

**这个验证方法可复用**：以后任何「公众号到底认不认某种富文本写法」的疑问，
都用同一招——生成一个自包含的 `output/paste-test.html`（真图转 data URI + 内联样式），
用户全选复制、粘到公众号后台，一眼看结果。
比读文档、猜平台规则可靠得多（这次就证明了：项目里那条「data URI 被拒」的结论是错的）。

### 3.4 风险

| 风险 | 处理 |
|---|---|
| 图多时转 base64 卡住 | 并发 3 + 进度提示 + 超时 12s（沿用 `images.js` 现值） |
| 剪贴板体积过大导致粘贴失败 | 压缩到 ≤8MB + 超限提示 |
| 公众号更新后不再支持 data URI | 保留原 `text/plain` 兜底 + 失败时如实提示 |

## 4. 方案 B（已降级为可选）：补中文标点禁则

> ⚠️ **2026-11-01 晚实测推翻本节前提**：句方便**也没做**标点禁则
> （`line-break` 0 处、`text-indent` 0 处，`word-break` 同为 `break-word`）。
> 所以这不是「追赶项」，而是「可选优化」——做不做都不影响和别人打平。
> 保留本节是因为它对中文排版确实有价值，只是**优先级最低**。

### 4.1 现在的问题

`word-break:break-word` 的副作用：英文单词会被从中间劈开。
中文标点会出现在行首（`，` `。` `？` 跑到行首），这是中文排版大忌。

### 4.2 改法（纯 CSS，微信支持）

微信支持**部分** `line-break` / `word-break` 规则。可行组合：

```css
/* 中文标点禁则：不把标点放在行首 */
word-break: normal;           /* 不用 break-word（会劈开英文单词）*/
overflow-wrap: anywhere;      /* 只在放不下时才断，且优先在词边界 */
line-break: strict;           /* 行首禁则（iOS/Android 微信多数支持）*/
```

⚠️ **必须先实测**：`line-break: strict` 在微信 WebView 的支持度不明确。
方案里标注为「需真机验证」。

### 4.3 若 CSS 不可行，退到「零宽不换行符」方案

在标点前插入 `\u2060`（word joiner）或用 `&#8288;` 包裹标点对：

```
「文本，」→「文本<span style="white-space:nowrap">，</span>」
```

代价：HTML 体积变大，且微信是否会剥离 `&#8288;` 需验证。

**建议**：先用 CSS 方案（零成本），实测不行再考虑标记方案。

## 7. 复现（我做的实测）

```js
// 在 seneasy.cloud/dashboard 控制台执行，点「复制到公众号」后读结果
const orig = navigator.clipboard.write;
const captured = [];
navigator.clipboard.write = async function(items){
  for (const it of items){
    const rec = { types: [...it.types] };
    for (const t of rec.types){
      const b = await it.getType(t);
      rec[t + '__size'] = b.size;
      if (t === 'text/html'){
        const txt = await b.text();
        rec.imgTags     = (txt.match(/<img[^>]*>/g) || []).length;
        rec.dataUriImgs = (txt.match(/src="data:image/g) || []).length;
        rec.httpImgs    = (txt.match(/src="https?:/g) || []).length;
      }
    }
    captured.push(rec);
  }
  return Promise.resolve();
};
```

实测输出：`imgTags: 19, dataUriImgs: 19, httpImgs: 0, size: 755383`。
