## 一、命名原则（这次变了）

上一版错在**用技法描述起名**（朱线=红色线条、编号=数字序号），读起来像说明书。

这次改为：**从古籍版本学里找「本来就是这个意思」的术语**。每个名字必须满足三条：

1. **真词**：汉典能查到，有出处
2. **本义对得上**：它的原始定义就是描述「线条/留白/标记」这类版面元素
3. **字面能懂**：不认识古籍的人，看字面也知道是个什么东西

## 二、逐条核实结果与对应

### 1. `time` → **朱丝栏**（用户定稿）

**汉典原文**（词语解释）：
> 织有或画有**红色格线**的绢帛或纸笺。
> —— 唐·李肇《唐国史补》：「宋亳间，有织成界道绢素，谓之乌丝栏、朱丝栏。」

**为什么给它**：`time` 的配方核心是「**红色只做细框线、标题线、序号**，重点结论外面加一圈细红框」。
「朱丝栏」的字面就是**红色格线** —— 与「红细框线」字字对应，而且「朱」字一眼就是红。

> 落选：**黑口**（汉典：「线装书书口的一种版式，版心上下两端刻有粗细不同的黑色线条」）。
> 它与「线条有粗有细」更贴，但用户选了「朱丝栏」——理由是红色更醒目、字面更雅。

### 2. `guardian` → **天头**

**汉典原文**（词语解释）：
> 书页上端的空白处。

**为什么给它**：`guardian` 的配方核心是「**大标题上方压一行 14px 红字**（眉题）」。
「天头」就是**书页上方那块空白**——眉题恰好长在天的位置。

> 这是 7 个里对应最准的一个：古籍的「天头」本来就常用来写批注、题眉。

### 3. `economist` → **鱼尾**

**汉典原文**（国语辞典）：
> 一种古书版刻标识。在书叶中缝有鱼尾形的**丙字标记**，作为间隔文字或题记书名之用。

**为什么给它**：`economist` 的配方核心是「**红色「01」「02」序号 + 浅灰细线**」。
鱼尾是古籍里**用来分隔、标记条目的符号**——和「红色序号分隔小标题」是同一个功能。

> 额外好处：「鱼尾」是 7 个里唯一带**图形感**的词，比其他 6 个更有记忆点。

### 4. `natgeo` → **乌丝栏**（用户定稿）

**汉典原文**：
> **乌丝栏**：古代绢素或笺纸上用**墨线织成的界格**。—— 唐·李肇《唐国史补》

**为什么给它**：`natgeo` 的配方核心是「**左 4px 粗线 + 右 1px 细线**」的双竖线。
「丝栏」在古籍里就是**纸上的界格线** —— 一道一道竖着的线，与它的双线结构完全一致。

**为什么不是朱丝栏**：`natgeo` 的主色是**黄**，用「朱」（红）会错位；「乌丝」（墨线）更准。

### 5. `vogue` → **版心**

**汉典原文**（国语辞典）：
> 版框的中央部位留有一条不刻正文的空白处，因为宋元时代通行蝴蝶装，文字向里对折，故此部位称为「版心」。

**为什么给它**：`vogue` 的配方核心是「**整篇只有黑白，没有彩色**；大标题 34px 宋体，重点不上色只垫细线」。
「版心」的定义是「**一块留白**」——整篇黑白、靠留白撑气场，语义吻合。

> 已定：**版心**。落选「白口」（古籍里与黑口相对，指版心上下不刻线条的空白）——
> 「白口」更直白，但「版心」有典故、更有书卷气。

### 6. `forbes` → **算经**（用户定稿）

**维基百科《算经十书》**：
> 《算经十书》是指中国**汉、唐时期流传下来的十部重要数学书籍的总称**。
> 包括《周髀算经》《九章算术》《海岛算经》《孙子算经》《张邱建算经》
> 《五曹算经》《五经算术》《缉古算经》等。
> 唐代李淳风等人注释十部算经，唐高宗显庆元年（656 年）完成，作为国子监算学馆的教材。

**为什么给它**：`forbes` 的配方核心是「**数字本身就是主视觉**，放大到 28–32px」。
「算经」是中国古代**数学典籍**的统称 —— 以「算」为名的典籍，与「数字当主角」语义相通。

> 落选：**数目**（常用词，不是专名）。「算经」虽然严格说是**书名**不是版式元素，
> 但它是**真词、有出处、能查到**，比生造的「数目」更站得住。

### 7. `adidas` → **三道**

**「三道」**：非古籍专名，但「三」在古籍里是高频数（三才、三纲、三省）。
更贴近的实词是「**三条**」——佛教法器「三宝」纹样常称，但不够准。

**为什么保留它**：`adidas` 的配方核心是「**三条纹**，三根短线，不要拉太长，像固定识别符号」。
这是纯视觉符号，古籍里没有对应物（古籍不会用三条斜纹做装饰）。

**诚实的处理**：这个版式是最「现代」的一个，硬套古籍词会失真。
建议**保留「三道」**（不装古籍），或直接叫**「三条」**。

## 四、入口方案：确定做方案三

### 4.1 你说「反正下面都是空的」—— 我量了，确实

在 1100px 高的视口下实测（`docs/prototypes/wechat-v3.html`）：

| 项 | 数值 |
|---|---|
| 预览区总高 | **956px** |
| 文档实际高度 | **543px** |
| **文档下方空白** | **397px** |
| 文档占预览区 | 57% |

**方案三要花的 32px，完全在这 397px 的空白里。** 所以它不是「用预览空间换版式可见性」，是**用空白换**。

### 4.2 定稿设计

```
┌─ 预览 ──────────────────────────────── [手机] [复制到公众号] ┐
│                                                              │
│   ┌────────────────────────────┐                             │
│   │  周末去了趟海边            │                             │
│   │  第一天：什么也没做        │   ← 文档区（543px）         │
│   │  两天里我没看手机…         │                             │
│   └────────────────────────────┘                             │
│                                                              │
│   ← 这下面 397px 全是空白，方案三只吃掉其中 32px            │
├──────────────────────────────────────────────────────────────┤
│ 版式  默认  ▸                          公文·湖蓝 · 179 套    │ ← 32px
├──────────────────────────────────────────────────────────────┤
│ ● 公文·湖蓝  ● 公文·朱砂  ● 信笺·竹青 …      [全部 179 套 ›] │ ← 52px
└──────────────────────────────────────────────────────────────┘
```

点「▸」向上弹出：

```
├──────────────────────────────────────────────────────────────┤
│ 通用   默认 图文节奏 卡片流 目录导航 杂志分栏 首屏 卡片组 时间线│
│ 报刊   朱丝栏 天头 鱼尾 乌丝栏 版心 算经 三道                  │
└──────────────────────────────────────────────────────────────┘
```

**三个细节**：

1. **默认收起**，只占 32px —— 首屏可见「版式」这个词，但不喧宾夺主
2. **点开向上弹**，覆盖的是文档下方的空白区，**不推挤预览**
3. 手机上（375px）—— **本轮不做**，见第五节

### 4.3 为什么不再做方案一、二

- 方案一（色卡条渐隐 + 实底按钮）：**仍然要做**，但它只是修缺陷，和方案三不冲突
- 方案二（空态预览墙）：**暂缓**。理由：方案三让版式上了首屏，但主题的「看不见」问题还在。
  不过如果要一次做完两件事，空态墙会吃掉那 397px 空白——**和方案三抢地盘**。
  建议**先做方案三，看效果再决定要不要空态墙**。

## 五、移动端：本轮不做（同意你的判断）

### 5.1 为什么同意

现在移动端是「桌面三栏塞进 375px」，靠 `@media (max-width: 900px)` 把左栏右栏变成浮层。
这导致：

- 版式条 + 色卡条 + 底部页签在 375px 下**垂直堆了 3 层**，占掉近 150px
- 方案三的 32px 版式行在手机上会变成第 4 层

**在 375px 里塞第 4 层，是在错误的架构上叠加。** 移动端需要的是**重新设计**（比如把版式和主题合并成一个底部抽屉），不是继续加行。

### 5.2 本轮的处理方式

- 桌面版按方案三做完整实现
- 移动端**保持现状不动**（不加版式行），避免越改越挤
- 在代码里留一个注释说明「移动端版式入口待重新设计」，并在 `docs/open-tasks-*.md` 记一条

### 5.3 留给下一轮的移动端议题

| # | 议题 |
|---|---|
| M-1 | 375px 下是否把「版式 + 主题」合成一个底部抽屉（现在分三处） |
| M-2 | 底部 3 层（页签 / 色卡 / 版式）能否合并成 1 层 |
| M-3 | 手机上「内容 / 预览」页签切换 vs 单栏滚动的取舍 |
