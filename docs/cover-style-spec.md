# 封面风格规范（Cover Style Spec）

> 把 `references/` 里的设计散文，落成项目可执行的硬约束。
> 校验器：`python scripts/cover_style_check.py`（`--strict` 接门禁）
> 上游依据：`references/style-system.md` · `theme-presets.md` · `image-overlay.md`

---

## 0. 一句话

**数量靠正交，质量靠规范。**

模板越多越好，这一点不用讨论。要讨论的是「怎么让第 80 套和第 1 套一样好看」——
答案是：**把区分度放在色板和版式上，不要放在字重字距上。**

---

## 1. 三层模型

| 层 | 内容 | 数量策略 | 改动难度 |
|---|---|---|---|
| **视觉体系** | Editorial 杂志 / Swiss 瑞士 | 固定 2 个 | 极难（见 §7） |
| **色板** | paper / paper2 / ink / muted / line / accent / accentSoft | **可无限扩** | 按 §5 规则造，分钟级 |
| **版式** | 封面 / 内页 / 清单 / 对比 / 金句 … | **可无限扩** | 按 §4 骨架写，小时级 |

三层的关系是：视觉体系决定「气质基调」，色板决定「情绪」，版式决定「结构」。
**新模板 = 选一个体系 + 一套色板 + 一个版式**，三层自由组合，不需要重新设计。

---

## 2. 可变 / 不可变（最重要的一节）

### 可以变 —— 这是「更多」的来源

- 色板 7 个槽位的具体色值
- 版式骨架的结构与信息槽位
- 背景氛围类型（纸纹 / 墨洗 / 等高线 / 照片）
- 装饰元素（细线、页码、issue 标签、边注栏）

### 不能变 —— 这是「漂亮」的底线

- **字重与字距的区间**（§3）
- **字体家族类型**：Editorial 必须衬线，Swiss 必须无衬线
- **对比度下限**（§5）
- **安全区**：上下 80px / 左右 60px / 底部 120px 禁放重要信息
- **底图的选图与遮罩规则**（§6）

### 为什么这条要写死

改字重字距，得到的是「同一套东西换个颜色」——8 套全是粗黑大字，一眼看去是一个模板。
改色板 + 版式，才得到真正不同的风格。

反过来说：**一旦允许「这次字重粗一点」，第 20 套、第 50 套一定会滑向粗黑**，
因为粗字在小图里更显眼、更容易「看起来有效果」。这是滑坡，不是审美选择。
`references/style-system.md:34` 已经把这条路标成反面教材了。

## 3. 字号与字重阶梯

### 3.1 Editorial（杂志 × 电子墨水）

| 角色 | 字号（1080×1440） | 字重 | 字距 | 字体 |
|---|---|---|---|---|
| 封面主标题 | **84–128** | **500** | **+.030 ~ +.040em** | 衬线（Noto Serif SC / Songti SC / Playfair） |
| 页标题 | 52–82 | 500 | +.02em | 衬线 |
| 正文 | **26–32** | 400 | 0 | **衬线（zh）** |
| 标注 / 元信息 | 18–24 | 500 | +.20 ~ +.22em | 等宽 |

- 标题 / 正文字号比：**2.6–4.4**
- 「大字要细」不是风格偏好，是 identity test 的第 1 条

### 3.2 Swiss（国际主义）

| 角色 | 字号（1080×1440） | 字重 | 字距 | 字体 |
|---|---|---|---|---|
| 封面主标题 | **84–128** | **200–400**（越大越细） | −.010 ~ +.010em | 无衬线（Inter / Helvetica Neue / Noto Sans SC） |
| 页标题 | 52–82 | 300–500 | 0 | 无衬线 |
| 正文 | **28–42** | 400–500 | 0 | 无衬线 |
| 标注 / 元信息 | 20–28 | **500–650**（小字反而更粗） | +.15em | 无衬线 |

- Swiss 只允许**一个** accent，一整套图不换色
- 禁止渐变、卡片阴影、玻璃拟态、圆角卡片
- 大字号必须 lighter：≥96px 时字重不得超过 300

### 3.3 中文标题的特殊处理

中文信息密度高，一行塞不下就**先缩文案，再降字号**，不允许把正文压到 26px 以下来腾地方。
断行按语义（标点 > 双字连接词 > 均分），**禁止按字符数硬切**——英文会被劈成 `Ju/mps`。

## 4. 版式骨架（可扩）

每个版式必须只声明**信息槽位**，不绑定色值，不绑定字重：

```
slots: title / lead / body[] / meta / page-number
```

现有 6 种（`docs/prototypes/cover-lab.html`）：

| 版式 | 槽位组合 | 适合 |
|---|---|---|
| 大字报 poster | eyebrow + title + lead + byline | 观点、金句、强冲击 |
| 堆叠 stack | eyebrow + title + lead + byline | 通用封面 |
| 清单 list | title + body[]（编号） | 干货、推荐、工具合集 |
| 对比 compare | title + 两列 body[] | before/after |
| 高密度 dense | title + body[]（可拆页） | 教程、长文内页 |
| 金句 quote | title + lead + byline | 观点、引用 |

归藏 28 版式（`references/layout-recipes.md`）里的 M01–M16 / S01–S12 是同一套思路的更细版本，
可以按槽位映射进来，**不需要重画**。

**扩充版式时唯一的硬要求**：新骨架必须能在 §3 的字号阶梯下落位，
且通过 `cover_style_check.py` 的字号区间检查。

## 5. 色板构造规则

不给白名单，给**生成规则**——这样任何人都能造出新色板且自动达标。

### 5.1 七个槽位

```
paper       主背景（纸底）
paper2      内层卡片 / 次级纸面
ink         标题与正文主色
muted       正文次级色（摘要、说明、页脚）
line        分隔线（ink 的低透明度版本）
accent      强调色（色块、细线、大字，不用于小字正文）
accentSoft  强调色的浅调
```

### 5.2 亮色板构造

| 槽位 | 规则 | 示例（Ink Classic） |
|---|---|---|
| paper | 明度 92–96%，饱和度 < 10%，轻微偏暖或偏冷 | `#f3f0e8` |
| paper2 | 比 paper 低 4–6% 明度 | `#ebe6da` |
| ink | 明度 5–15% | `#0a0a0b` |
| muted | 在 ink 基础上提亮，**但必须保证 vs paper ≥ 4.5:1** | `#68625a` |
| line | ink @ 20–24% alpha | `rgba(10,10,11,.22)` |
| accent | **必须 vs paper ≥ 3.0:1** | `#111111` |
| accentSoft | paper 与 accent 的中间调 | `#d8d2c6` |

### 5.3 暗色板（仅一套，Midnight Ink）

暗色板不是「把亮色板反相」——muted 在暗底上要**提亮**而不是压暗，且纸纹层必须换混合模式（`screen` 而非 `multiply`）。

**只有 Midnight Ink 一套暗色。不要造第二套**，除非内容源图本身就是暗的（游戏、夜景、影视）。

### 5.4 一条必须记住的教训

**「跳眼的强调色」和「能当正文的强调色」是两个不同要求，不能兼得。**

实测案例：柠檬黄 `#c9a800` 对纸底 `#fafaf8` 只有 **2.21:1**——
当色块、当细线、当 128px 大字都很好，当 24px 的 eyebrow 小字就完全糊了。

所以规范规定：**accent 只用于色块 / 细线 / ≥64px 的大字，禁止用于小字正文**。
小字一律用 ink 或 muted。

## 6. 底图规则（联网图片）

> 这一节是「封面好看」的最大权重项，也是项目对外的核心差异化。
> Editorial identity test 第 1 条就要求：**纯色纸底不算 Editorial**。

### 6.1 通道（已实现，不是待建）

| 优先级 | 来源 | 前置条件 | 许可 |
|---|---|---|---|
| 1 | Pexels | 用户自配 key | Pexels License |
| 2 | Pixabay | 用户自配 key | Pixabay License |
| 3 | Wikimedia Commons | **免 key**，CORS 友好 | CC 系列，需署名 |

实现：`pwa/src/cover/search.js`（中文标题 → 英文场景词映射 → 搜图 → data URL，24h 缓存）。
失败返回空数组，UI 回退纯色或用户上传，**不静默**。

### 6.2 选图双测试（人 / 多模态判断，机器查不了）

**quiet-zone test**：至少一条 ≥30% 画布的band 是低细节 / 低对比 / 均匀的
（虚化背景、深阴影、雾、平静水面、纯色天空）。标题要落在这个带里。

**light test**：氛围光克制——阴天、晨雾、黄金时刻、林下、胶片柔光、黄昏剪影。
**拒绝**：高饱和正午硬光、机顶闪光、游客自拍、通用素材库的假笑。

任一不过 → **换图，不要用遮罩硬修**。

### 6.3 遮罩三级（顺序不能跳）

| 级别 | 做法 | 何时用 |
|---|---|---|
| Step 1 | **选图**（换一张合格的） | 永远先做这步 |
| Step 2 | **不加遮罩**，文字落进 quiet zone | 默认答案。能读就发 |
| Step 3 | **局部、取自图片色调的 tint** | 仅当 Step 2 缩略图不可读 |

Step 3 三条硬约束：

1. **局部**：只覆盖标题区域（`radial-gradient` 或单侧渐变，超出标题区完全透明）
2. **取图片固有色调**：森林 → 深苔绿 `#1a2818`，黄昏 → 茶玫瑰 `#4a2638`，雪 → 冷灰蓝 `#2a3438`。**禁止纯黑 `#000`**
3. **软**：标题区峰值 alpha **0.15–0.30**。需要 >0.40 才能读 → 图选错了，回 Step 1

### 6.4 违禁清单

- ❌ 全画布均匀垂直渐变（`inset:0` + `linear-gradient(180deg, rgba(0,0,0,.55) → .10)`）
- ❌ 纯黑遮罩
- ❌ 文字后面垫一个纯黑/纯白矩形色块（像截图标注）
- ❌ `mix-blend-mode: difference`（毁肤色）
- ❌ `img { opacity: .6 }`（毁照片纵深，全幅图的意义就没了）
- ❌ 全幅底图加 `backdrop-filter: blur()`（糊掉照片细节，和降透明度同类）
- ❌ 跳过 Step 1 直接上遮罩

### 6.5 主体避让

- 先写 **subject map**（人脸 / 手 / 产品 / 轮廓在哪），记成 HTML 注释
- 安全区优先级：**上下 > 单侧 > 对角**
- **标题绝不能横穿人脸**（哪怕加了遮罩）
- 标题占画布 **≤ 40%**，留白是设计的一部分
- `object-position` 按主体位置查表（上三分之一 → `center 25%`，中间 → `center center`，下三分之一 → `center 70%`）

图装不下字 → 换构图（挪进相框 / 双联 / 文字移出图外），**不要加大遮罩**。

### 6.6 缩略图终检（每次必做）

导出后缩到 **360px 宽**看：
- 标题笔画不放大就能读 → 过
- 标题在和照片「打架」 → 换图或挪位，**不是加强遮罩**
- 照片在均匀暗色下变成死灰 → 遮罩太重，回 Step 1

## 7. 新增一套「视觉体系」的门槛

色板可以随便加，**视觉体系不能随便加**。新增一套体系必须同时满足三条，缺一条就只是「换了个色板」：

1. **新的字体家族类型**（现有：衬线 / 无衬线；要新增得是真的第三种，比如等宽正文或手写体，且有可商用的中文字体）
2. **新的栅格逻辑**（现有：Editorial 单栏 + 边注 / Swiss 12–16 栅格左对齐；新体系要有不同的空间组织方式）
3. **新的遮罩或图底策略**（现有：选图优先 + 局部 tint；新体系要给出不同的图文关系）

三条都成立，才在 `references/style-system.md` 里加 Mode C 并写 identity test。

否则：**加色板就好**。

## 8. 机器查 vs 人必查

| 检查项 | 谁查 | 备注 |
|---|---|---|
| 字重 / 字距 / 字号区间 | 🤖 脚本 | §3 |
| 字体家族类型（衬线/无衬线） | 🤖 脚本 | 注意 `sans-serif` 里含 `serif`，别误判 |
| 对比度（标题 / 正文 / accent） | 🤖 脚本 | §5.2 |
| 标题 / 正文比例 | 🤖 脚本 | §3.1 |
| **选图质感（quiet-zone + light）** | 👤 人 / 多模态 | §6.2 |
| **主体避让（不跨脸）** | 👤 人 / 多模态 | §6.5 |
| **缩略图可读性** | 👤 人 | §6.6 |
| 遮罩 alpha 是否 ≤0.30 | 🤖 脚本（可正则查）+ 👤 复核 | §6.3 |

脚本只做 AUTO 类。**不要假装机器能判断「这张图好不好看」**——
它只能判断「这个色值够不够对比」「这个字重越没越界」。

## 9. 当前资产自检（2026-10-25 快照）

`python scripts/cover_style_check.py` 实测：**共 78 项 · 通过 54 · 失败 24**

### 9.1 参数层：合规 ✓

| 对象 | 结果 |
|---|---|
| `PWA/editorial` | 9/9 通过（对比度 17.38 / 5.29 / 16.58；字重 500；字距 +.040em；衬线） |
| `PWA/swiss` | 9/9 通过（对比度 18.94 / **4.54** / 10.23；字重 300；字距 −.010em；无衬线） |

> `swiss` 正文 4.54:1 只比下限高 0.04。**改 `muted` 时务必重跑**，很容易掉下去。

### 9.2 原型：14 项不合规

- 色板 3 项对比度失败：`dune` 正文 3.91 · `terminal` 正文 4.12 · `lemon` 强调色 **2.21**
- 版式 11 项排版越界：字重 700–800（应 500）、字距 −.012 ~ −.025em（应 +.030~+.040em）

### 9.3 模板层：10 套全部命中违禁遮罩 ✗ ← 这条最要紧

`public/cover-templates/*/index.html`（10 套，无一例外）都在用：

```css
.img-overlay { position:absolute; inset:0;
  background: linear-gradient(180deg, rgba(0,0,0,.35) 0%, rgba(0,0,0,.55) 50%, rgba(0,0,0,.70) 100%);
  backdrop-filter: blur(2px); }
```

这是 `references/image-overlay.md` 里 **Banned 第一条**点名的写法
（"game-key-art treatment, not editorial"），且峰值 **0.70 是规范上限 0.30 的 2.3 倍**，
再叠一层 `blur(2px)`。

**结论：项目内部的规范文档和实际资产互相矛盾 —— 规范说禁止，10 套模板都在用。**

这不是新设的门槛，是要先统一的内部矛盾。所以 B 阶段（立规范）的真正产出是：
**先承认这 10 套的遮罩写法不合格**，再决定是「改模板」还是「改规范」。
按 `image-overlay.md` 的立场（归藏原项目自己的文档），应该**改模板**。

## 10. 扩容流程（照这个走就不会翻车）

新增一套模板：

1. 选视觉体系（Editorial / Swiss）
2. 按 §5.2 造 7 槽色板 → 跑 `cover_style_check.py` 直到全绿
3. 选一个版式骨架（§4），套用 §3 的字号阶梯
4. 配底图（§6）：搜图 → 双测试 → **不加遮罩先试** → 不行才局部 tint（峰值 ≤0.30、取自图片色调）
5. 缩略图 360px 终检
6. 再跑一次校验器（`--strict`）

**第 2 步全绿之前，不要开始第 3 步。** 色板不达标，后面怎么排都救不回来。

改造已有模板（比如那 10 套）时，顺序反过来：**先删 `.img-overlay`，看裸图能不能读**
（§6.3 Step 2）。多数情况下删掉之后反而更像杂志 —— 那层 70% 黑遮罩本来就在替选图背锅。
