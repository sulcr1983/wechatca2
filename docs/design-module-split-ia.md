# 三模块信息架构：公众号排版 / 标题图 / 长图长文（模块拆分方案）

> 状态：**方案定稿，待落地**（本文档只做设计，不改代码）。
> 关系：**推翻并取代** `docs/design-xhs-studio-redesign.md` §3 的「双路径 + 页内二级行」决定，
> 决策人与时间见 §1 的 R 表。落地时需同步修订的既有文档见 §10。

## 0. 结论（一屏说清）

把现在「封面页内部的标题图/长文图文二级切换」拆成**三个平级顶级模块**：

```
顶栏：  [ 排版 ]  [ 标题图 ]  [ 长图文 ]      ← 三个常驻 tab，当前页高亮
            │           │            │
         公众号排版    一句话→配图   搜图(封面底图) → 贴长文 → 生图整套
         （现状不动）   →出封面       （用户原话的流程，一字不差）
```

- **拆的是「产品面」，不是「代码」**：引擎层（模板目录 / 渲染管线 / 搜图 / 可读性分析 / cards.js 分页 / story.js 成套生成）一份代码，两个模块各自的 UI 与状态。
- 标题图是大众需求，打开即用、看不见任何长文概念；长图长文是独立工具，有自己的完整工作流。
- 判决标准（本方案的立论）：**一个页面必须能用一句话说清**。现状的封面页需要两句
  （「写一句话或贴整篇，出一张图或一套图」）——说明它本来就是两个产品。

## 3. 目标信息架构

### 3.1 顶栏（全局导航）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ logo SuperSu [公众号排版][小红书标题图][小红书长图文]  …右侧现状不动        │
└──────────────────────────────────────────────────────────────────────────┘
```

- 三个 tab 常驻，当前页高亮（沿用 `.cover-btn[aria-pressed]` 的视觉）。
- **文案全称不可省略**（R6）：「公众号排版」「小红书标题图」「小红书长图文」。
- **#btn-cover 行为重定义**：从「两态文字切换按钮」变为「小红书标题图」tab。文案固定，
  不再变成「公众号排版」——回排版 = 点「公众号排版」tab。
- 新增 `#btn-longform`（「小红书长图文」）与 `#btn-editor`（「公众号排版」，排版页此前
  没有自己的入口按钮，补上它三 tab 才成立）。
- **375 策略（R6 派生）**：不缩 tab 文案，缩周围——`brand` 文字（logo 保留）、
  `brand-tail`、`brand-sub`、引擎徽标隐藏；「导出 ▾」按钮隐藏、导出四项并入
  「更多」菜单顶部（窄屏可达性不丢，桌面不变）；三 tab 字号 11px、padding 收窄。
  落地后必须过 `scripts/audit_mobile_typography.py`（375 无横向溢出）。

### 3.2 页面承载

- `#cover-root` 拆为 `#title-root`（标题图）与 `#longform-root`（长图长文），
  与 `#stage`（排版页）平级，三者互斥显示（同一套 `hidden` 互斥机制）。
- URL 无路由变化（仍单页，hash 不引入——与现状一致）。

## 4. 模块一：标题图（`#title-root`）

首屏结构与 design §3 的 wireframe 一致，**唯一变化是去掉 pathbar、署名回抽屉**：

| 区 | 内容 | 与现状的差异 |
|:--|:--|:--|
| 左栏 | ① 一句话输入（首屏主角）→ ② 配图三按钮（搜图置顶带特色角标）→ 搜图面板 → [保存大图] → ⚙ 调整抽屉 | **署名移回抽屉**（撤掉共字段 hack）；pathbar 删除 |
| 中栏 | 实时预览 → 结果区（只有单张封面）→ 示例墙 | 结果区不再出现「内页 N」卡片 |
| 右栏 | 风格卡（版式 × 色板） | 不变 |
| 抽屉内 | 字体 / 文字玩法 / 尺寸 / **署名** / 文字位置 / 磨砂 | 署名回归（§3 原设计） |
| 九宫格 | 预览条入口保留 | 长图长文模块不放（见 §6） |

空态文案只谈标题图；示例墙只放单张示例。

## 5. 模块二：长图长文（`#longform-root`）

首屏流程按 **R5 定稿顺序**编排：**粘贴文字 → 选图 → 选版式 → 导出**。

```
┌ 左栏 ────────────────┐ ┌ 中栏 ─────────────┐ ┌ 右栏 ────────────┐
│ ① 整篇文章 textarea   │ │ ③ 整套实时预览     │ │ ④ 长文模板 12 选 1 │
│    第一行 = 封面标题   │ │    横滑一页一卡     │ │ ⑤ 色板 8 选 1     │
│    [用正文] 导入      │ │    导出一整套 [N张] │ │ ⑥ 版式选项         │
│ ② 封面配图（三按钮）   │ │    打包整套 ZIP    │ │   · 显示页码       │
│    搜图（特色）        │ │ ⑤ 产物自检（静默）  │ │   · 签名           │
│    传一张 / 不要图    │ │                   │ │   · 内页背景图     │
└──────────────────────┘ └───────────────────┘ └──────────────────┘
```

- **① 整篇文章在左栏最顶上**（R5）：主输入是文章，第一步就是它；配图是第二步的
  可选动作，不与主输入抢位。
- ②的「配图」= **封面底图**（复用标题图的配图组件逻辑，state 独立）；内页背景图
  是另一个维度，留在右栏版式选项（§12.2 定位：高级项）。
- 「用正文」保留：从公众号排版页导入正文——这是模块间**唯一**的显式交互，松耦合合理。
- 签名/页码/背景图的控件从「标题图 pane」语义里彻底独立，全部状态归本模块。
- 空态：贴文章前的引导文案（自动分页说明 + `---` 用法一句话）。

## 6. 边界：拆产品面，不拆代码

**继续共用（一份代码）**：
`catalog.js`（模板目录）/ `render.js`（标题图渲染管线）/ `cards.js` + `story.js`
（长文分页与成套生成）/ `search.js`（Pexels 搜图）/ `analyze.js`（底图可读性）/
`layouts.js` / `templates.js` / `textmode.js` / `nine.js` / lightbox 组件。

**各自独立（UI 与状态分家）**：

| 项 | 标题图 | 长图长文 |
|:--|:--|:--|
| 输入 | `#cv-text`（≤500 字，首行标题） | `#cv-long-text`（整篇，首行=封面标题） |
| 署名 | 抽屉内 `#cv-author`（`supersu.cover.prefs.v1.author`） | 右栏 `#cv-long-sign`（longform prefs.longSign） |
| 结果 | 自己的画廊（单张） | 自己的结果区 + ZIP（整套） |
| 九宫格 | 有 | 无（整套 PNG 不切九宫格；后议） |
| 预览 | 单 iframe（fitty 管线） | deck 横滑（cards.js DOM + fitOverflowCards） |

九宫格只留标题图的理由：它切的是「一张图」，与标题图的产物形态同族；长文产出是
一套页，切九宫格没有用户故事。

## 7. 存储拆分

| 键 | 归属 | 字段 |
|:--|:--|:--|
| `supersu.cover.prefs.v1`（沿用） | 标题图 | style / size / mode / font / textMode / layoutPick / textPos / frosted / author。**path / longTpl / palKey 三字段停止写入**（load 忽略即可，不做破坏性清理） |
| `supersu.longform.prefs.v1`（新增） | 长图长文 | longTpl / palKey / **longPn / longSign / longBg（补上 S6 漏掉的持久化）** |
| 迁移 | 一次性 | longform 键为空且旧键存在 → 搬 longTpl/palKey（其余本就没存过）；之后旧键长文字段不再读 |

- ⚠️ 两个键都带 `supersu.` 前缀：`clearAll()` 已按前缀统一清除（`clearSupersuStorage()`），
  **无新增清理负担**——这是选前缀键而非新命名空间的原因。
- 长文正文（textarea 内容）**仍不持久化**，与现状一致；「用正文」导入是唯一来源。
  要不要草稿另立议题，本方案不做（极简至上）。
