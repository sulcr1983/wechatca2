## 1. 审计目标与原则

### 1.1 目标（对齐产品愿景，而不是对齐文档）

对三件事分别回答：**用户能不能顺畅完成、产物对不对、模板是不是真的多且有用**。

| 愿景 | 必须回答的问题 |
|---|---|
| 方便好用的公众号自动排版 | 从打开到「粘进公众号后台样式不丢」，中间有几处会卡住/需要用户理解内部概念？ |
| 方便好用的标题图生成 | 从一句话到底图到下载，非设计背景的用户能否在 2 分钟内得到一张可发布图？ |
| 方便好用的长图文生成 | 长文能否稳定分页、不丢句、不溢出、成套导出，且模板不是同一套骨架反复换色？ |
| 模板多多 | 模板数量是否真实可应用、彼此可区分、缩略图不重复、配色/对比度达标？ |

### 1.2 原则

1. **第一性原理**：从「用户要拿到什么产物」倒推，不从「代码里有什么函数」正推。
2. **对抗性**：每个「已完成」都先假设它不成立，去找反例；找不到反例才降级为「未证伪」。
3. **产物优先**：按钮可点、toast 出现、测试变绿都**不算**证据；剪贴板内容、下载文件字节、PNG 像素、逐句落版才算。
4. **可证伪**：每条结论必须给出「什么情况下这条结论会被推翻」，并实际尝试推翻一次。
5. **单一真源**：同一事实只认一个来源（见 §3）；跨来源冲突时**记录冲突**，不私自选边。
6. **不改产品**：本轮只产出认知与清单；任何修复都进入下一轮并单独评审。

### 1.3 明确不做

- 不修 bug、不重构、不调样式、不补门禁、不改文档结论（只登记）。
- 不评价原型视觉、不重开已被否的方案（`HANDOFF.md` §6.2 / 交接稿 §3.4）。
- 不做性能优化与成本优化（只记录可观测的性能事实）。
- 不对 AGPL/商标做法律结论（只核对「声明是否一致」）。
- 不采信「另一个 agent 说已经修了」——一律自己复跑。

## 3. 资料来源与真源优先级

审计期间**只认这一套优先级**；低优先级来源与高优先级冲突时，记为「文档失真」而不是「事实争议」。

| 级别 | 来源 | 可信度 | 失效条件 |
|---|---|---|---|
| **T1** | 线上实际资源（哈希/字节/渲染结果/下载文件） | 最高 | 网络被代理/缓存污染（必须 `--noproxy` + 禁缓存） |
| **T2** | 本地 `pwa/dist` 产物 | 高 | 未重建、构建被中断、`dist` 被手工改过 |
| **T3** | 当前源码 + 可复现命令（git/grep/diff） | 高 | 工作区有未提交改动、读的是缓存 |
| **T4** | 门禁/套件日志（含失败输出） | 中 | 套件本身断言不到产物、环境漂移、退出码被吞 |
| **T5** | 生成物（`STATE.md` / `changelog.json` / `themes/index.json`） | 中 | 生成脚本有 bug（本轮已发现一例） |
| **T6** | 活文档（AGENTS/INDEX/HANDOFF/交接稿） | 低 | 未随代码更新、转述二手结论 |
| **T7** | 原型 / 历史归档 / 提交信息 | 仅作线索 | 从未落地、口径已过期 |

**取证纪律**

- 每条事实至少两个独立来源交叉（例：源码 grep + 浏览器产物）。
- 命令必须可复现：记录完整命令、工作目录、commit、时间、是否联网。
- 线上请求统一 `curl --noproxy '*' -A "Mozilla/5.0"`（无 UA 会被 Cloudflare 403；本机 Clash 会拦 localhost）。
- 浏览器侧禁用缓存/注销 SW 后再量样式；等 `#boot.gone` 再判引擎就绪。
- 不把「文档里写的行号」直接当证据；行号只用于定位，结论必须来自当前内容。

## 6. 状态分级与判定标准

### 6.1 六级状态（互斥）

| 状态 | 定义 | 判定门槛 | 本项目示例（待最终确认） |
|---|---|---|---|
| **S1 已实现且可用** | 用户能完成目标并拿到正确产物 | 至少 1 条 E3 + 1 次独立复现；无 P0/P1 缺陷 | 主题切换 + 复制（需补多主题证据） |
| **S2 已实现但有缺陷** | 主路径可用，但违反承诺或边界失败 | 有可复现反例 | kit 背景锁定失效；hero/timeline 丢 h2 |
| **S3 临时方案 / 硬编码** | 能用但靠特例维持，改动易碎 | 代码证据 + 影响面说明 | 品牌锁死版式、固定色板常量、构建号=提交数 |
| **S4 伪实现 / 死代码** | 有 UI 或分支，但**对用户无效**或永不可达 | 调用链证据（入口不调用 / 分支无产出） | 外链转脚注开关（PWA 不调用）、`role:'steps'` |
| **S5 尚未开发** | 文档/需求已定，代码不存在 | 全仓 grep + 运行时确认 | 标题图 UX V2 骨架 |
| **S6 无法验证** | 依赖人工判断/外部账号/环境，证据不足 | 明确写出缺什么证据、谁能给 | 搜图结果「贴题度」、真实公众号后台粘贴效果 |
| **S0 已核查并排除** | 曾被怀疑，实测不成立 | 反例证据 | X-1「9 个文件未提交」 |

> 同一功能可以在不同链路环节处于不同状态（例：A 的「主题选择」S1，「kit 锁定」S2）。
> **禁止用模块级一个总状态掩盖局部缺陷。**

### 6.2 证据等级

| 等级 | 内容 | 能否支撑「可用」 |
|---|---|---|
| **E0** | 文档/交接稿声称 | ❌ |
| **E1** | 静态代码存在（grep/read） | ❌（只能支撑「有实现」） |
| **E2** | 进程内单测/夹具通过 | ❌（可能测的是另一套口径） |
| **E3** | 浏览器端到端 + **产物断言**（剪贴板/下载字节/像素/逐句） | ✅ 本地可用 |
| **E4** | 线上真实环境 + 独立复现 + **反向验证**（故意破坏应变红） | ✅ 线上可用 |

**反向验证是硬要求**：对每道关键门禁做一次「故障注入」，若仍绿，则该门禁不算证据（参考 `kit_alignment_canred.py` 的做法）。

### 6.3 「完成」的判定

一个功能标记为 S1，必须同时满足：

1. 用户链路端到端跑通（E3）；
2. 至少一个边界场景（空/超长/断网/无 Key/失败）有明确行为；
3. 有对应门禁或产物断言，且该断言经过反向验证；
4. 文档描述与实际行为一致（或已登记差异）。

### 8.2 A 模块专项

- 164 套主题 × 3 类夹具（短/标准/复杂）：丢字率、标签配平、无 `None`/空 style、对比度。
- kit 19 套：版式是否真锁、背景是否真禁、退出后是否恢复、换主题是否残留品牌色。
- 15 个版式：产物结构差异、`<h2>` 语义、换主题配色跟随、移动端断行。
- 复制：3 主题 × 3 版式 × 有无图；读剪贴板 HTML，检查 data URI、内联样式、禁用标签。
- 预处理四模式：同一输入在四模式下的差异是否符合承诺；`auto` 判定反馈是否与实际一致。
- 段落样式三开关：只影响目标块；与版式/主题组合不冲突。
- 字号/背景/自定义配色：产物真变化；kit 态锁定；plain 时零变化。
- AI：未配置不显形；失败降级原因；撤销恢复原文；Key 不落盘到导出/备份。
- 清除数据：18 个键全清；清后功能可重新初始化。

### 8.3 B 模块专项

- 25 style × 3 尺寸全量出图；PNG 尺寸、非空白、文字不裁切。
- 实时预览 vs 下载图：同文案同风格，像素/布局一致（防「预览好看、导出错位」）。
- 长标题（50 字）、单字、全英文、emoji、混排：不溢出、不孤字。
- 底图：纯白/纯黑/高对比/低对比；文字保护是否真的达标（读像素算对比度）。
- 搜图：无 Key、错 Key、429、超时、中文词无结果、翻页；缓存换 Key 不串源。
- 九宫格：逐格墨迹覆盖率、顺序、间距、空白格预警（当前缺失）。
- 字体：10 款逐个加载；慢网/失败回退；字体不参与首屏阻塞。

### 8.4 C 模块专项

- 分页完整性：原文每句都出现在某页（去空白/标点归一后比对）。
- 溢出：每页 `scrollHeight ≤ 可用高`；图片/长英文/URL/表格不撑破。
- 页数上限：`STORY_MAX_PAGES` 触发时的截断提示是否明确、可恢复。
- 手动分页符：连续两个只分一次；开头/结尾分页符不产生空页。
- 12 套模板 × 8 色板：组合抽样全覆盖；锁定规则与提示一致。
- 导出：ZIP 解包逐张校验尺寸/顺序/空白率/重复页。
- 步骤块：`type:'step'` 是否走到专用样式（当前走不到，`role:'steps'` 死代码）。
- 封面：与内页风格一致；封面文案不被裁切。

### 8.5 模板真实可用性（「模板多多」的对抗性验证）

| 指标 | 方法 | 判定 |
|---|---|---|
| 数量真实性 | 源 JSON / index / 缩略图 / 可应用数四者对齐 | 任一不一致即为虚数 |
| 结构多样性 | 去掉颜色值后的 `styles` 签名去重 | 签名数 / 总数 = 结构多样性；当前 62/164 |
| 视觉区分度 | 缩略图感知哈希去重率 | 去重率过高说明「看起来一样」 |
| 可应用性 | 逐套应用 + 渲染 + 产物断言 | 任何一套报错/丢字即不可用 |
| 配色合规 | 标题 ≥3.0、正文 ≥4.5、移动端断行 | 不达标即不可发布 |
| 锁死版式 | 品牌色版式不得进自由入口 | 进了即污染其他配色 |
| **整篇设计（kit）** | 19 套**逐套**检查 + **逐套目视**（不抽样） | 锁版式/锁背景/无品牌色残留；产物与 kit 描述一致 |
| 命名可发现性 | 按颜色/场景/用途搜索命中 | 搜不到 = 实际不可用 |

> 这个口径需要产品确认（见 §15）。

### 8.6 重复实现与单一真源

逐一确认是否存在第二套真相：

- 主题色板：`public/themes/*.json` vs `cards.js PALETTES` vs `catalog.js LAYOUT_STYLES` vs 原型内联色值。
- 渲染管线：`format_engine` vs `light.js`（近似预览）vs `cards.js`（长图文）vs `public/cover-templates`（独立 HTML）。
- 导出：`export.js` vs 各模块自建下载。
- 字号/版式常量：`app.js LAYOUT_OPTIONS` vs `LAYOUT_LABEL_ONLY` vs 引擎注册表。
- 存储键：18 个键散落 5 模块，无注册表。
- 统计数字：文档、STATE、测试描述、代码注释各写一套。

判定：**同一语义出现两处可独立变更的实现 = 结构性风险**，无论当前是否一致。

建「口径词典」，至少覆盖：主题总数 / 非 kit / kit / `su-*` / 早期经典 / 版式入口数 / 引擎版式数 / 段落样式 / 封面 style 数 / 封面版式卡数 / 长文模板数 / 长文色板数 / 门禁套件数（分层）/ 断言数。

| 层 | 检查 |
|---|---|

### 8.9 门禁误判（本轮已发现三类，需系统化）

1. **断言层级过低**：只查控件/toast。→ 逐套件标注「断言落在哪一层」。
2. **覆盖盲区**：线上层无长图文；九宫格无空白判定；复制只测默认主题。→ 建「模块 × 层级」覆盖矩阵，空格即风险。
3. **判据本身失效**：`preflight` 漏 `magazine_layouts.py`；`gen_state` 正则漏多行套件；`STATE` 缺有头层。→ 对关键门禁做**故障注入**，必须变红。
4. **环境假红/假绿**：引擎就绪慢、残留浏览器、端口 TIME_WAIT、代理、缓存。→ 记录每次运行的环境与耗时，区分「真失败」与「环境失败」。
5. **计数漂移**：套件描述写死断言数。→ 只认日志，不认描述。
